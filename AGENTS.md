# Neural Knowledge by TANK · refreshed 2026-10-17 · fee5860e47dd

This repository is the source of truth for every API contract in the TANK platform. Hand-written `.proto` files under `proto/` are compiled to Go, TypeScript and Python bindings committed under `gen/`, so every consumer imports a versioned snapshot rather than running codegen at build time. Wire names are deliberately neutral (`Channel`, not `Tread`; product vocabulary lives in the clients).

## Commands

```
npx --yes @bufbuild/buf lint                              # lint all protos (= make lint)
npx --yes @bufbuild/buf generate                         # regenerate gen/ (= make gen)
npx --yes @bufbuild/buf breaking --against '.git#branch=main'  # breaking check (= make breaking)
go build ./...                                           # compile generated Go
# make is often absent in agent sandboxes — run the npx commands above instead
```

## Areas

- `.` — repo root: Makefile, buf.yaml, buf.gen.yaml, go.mod, gen/ts package. Read `.neural/neurons/root.md`.

## Rules

From `CLAUDE.md` (hard prohibitions, verbatim):
- "Renumbering or reusing field numbers; removing a field before every client has shipped without it; editing `gen/` by hand; changing plugin versions without regenerating everything in the same PR."

From `CLAUDE.md` (decided, do not re-litigate):
- "Wire names stay neutral (`Channel`, not `Tread`); product vocabulary lives in the clients. One proto package per domain, version suffix `v1`. Generated code committed, not fetched at build time."

From `buf.yaml`:
- `lint.use: [STANDARD]` minus `PACKAGE_VERSION_SUFFIX`; `breaking.use: [FILE]` — moving a message between files is a breaking change even when the wire is unchanged.

## Before changing anything

1. Edit only files under `proto/`. Never edit `gen/` by hand.
2. Run `npx --yes @bufbuild/buf lint` — must pass before any PR.
3. Run `npx --yes @bufbuild/buf breaking --against '.git#branch=main'` — a wire break here is a production incident; only additive changes are safe to ship.
4. Run `npx --yes @bufbuild/buf generate` and commit the regenerated `gen/` in the same PR as the proto change. CI's staleness gate (`git diff --exit-code --stat gen/`) will fail if they diverge.
5. If you change plugin versions in `buf.gen.yaml`, also update the matching Go module pins in `go.mod` and regenerate everything.
