- This repo is input + output: hand-written `.proto` under `proto/`, generated Go, TypeScript and Python committed under `gen/`. `.gitignore` ignores only `node_modules/`, `gen/ts/dist/`, `gen/ts/*.tgz`, `__pycache__/` — generated *sources* are tracked on purpose, so every PR that touches a proto also carries the regenerated files.
- `Makefile` is the one documented entry point (`make check` = `lint gen build` + the stale-`gen/` gate), but `make` itself is not installed in this agent sandbox (no `/usr/bin/make`). Run the underlying buf commands directly: `npx --yes @bufbuild/buf lint|build|generate`, and `npx --yes @bufbuild/buf breaking --against '.git#branch=main'` for `make breaking`. `Makefile:1` (`BUF ?= npx --yes @bufbuild/buf`) confirms these are exactly what the targets shell out to.
- 27 domains now under `proto/tank/`, five added since the 2026-10-03 refresh: `board` (Neuralboards), `books` (Neuralbooks), `canvas` (Neuralcanvas), `remediation` and `security` (the two halves of Neuralsecurity). See `.neural/neurons/proto.md` for what each does.
- `buf.yaml` is v2, single module at `proto`, `lint.use: [STANDARD]` minus `PACKAGE_VERSION_SUFFIX`, `breaking.use: [FILE]` — FILE-level, so moving a message between files is breaking even when the wire is unchanged.
- `buf.gen.yaml` managed mode supplies `go_package` from a prefix, which is why most protos carry no `option go_package` — but the convention has split: the four newest domains (`books`, `canvas`, `remediation`, `security`) all hand-write `option go_package` instead of relying on managed mode, while `board` (also new) does not. A new domain should pick one path on purpose, not copy whichever neighbour happens to be open.
- Plugin pins in `buf.gen.yaml` mirror the runtime pins in `go.mod`: protoc-gen-go v1.36.4 ↔ `google.golang.org/protobuf v1.36.4`, connect-go v1.18.1 ↔ `connectrpc.com/connect v1.18.1`. `CLAUDE.md` forbids changing a plugin version without regenerating everything in the same PR.
- `gen/ts/src/index.ts` is a hand-maintained namespaced barrel and still has not picked up any of the five new domains — deep imports (`./tank/board/v1/board_pb.js`) are the only way to reach them from `gen/ts` today, same as the eight domains already missing from it in the last refresh.
- `go test ./...` appears in `.neural/map.yaml` but there is not a single `_test.go` file in the repo; `go build ./...` is the real check, and no Go toolchain is installed here either — CI's `go build ./...` step is the only place it is proven.
- `README.md` names the consumers each language serves and states the change discipline: "Changes are additive-first: add fields, ship every client, wait for the mobile build to land, then remove." It also now has a `## Security` section (every push/PR scanned by Neuralsecurity for secrets and fixable critical/high dependency vulnerabilities, verdict is the `neuralsecurity` check) — and three stray lines "x / y / z" sit at the very end of the file after that section; they read as leftover scratch content, not documentation, don't treat them as meaningful.
- `CLAUDE.md` hard prohibitions, verbatim: "Renumbering or reusing field numbers; removing a field before every client has shipped without it; editing `gen/` by hand; changing plugin versions without regenerating everything in the same PR."
- The Neural Knowledge refresh runner itself takes its lint/check commands from `.neural/map.yaml`'s `commands:` block, not from the Makefile. A stale map pointing at `make` will fail every refresh with `spawn make ENOENT` before anything is pushed — this is the actual cause of the string of failed refresh runs before this one; the map here is kept pointed at the `npx buf` commands for that reason.
