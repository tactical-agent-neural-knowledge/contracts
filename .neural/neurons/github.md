# Neurons · .github

refreshed 2026-10-10 · e52a377a71d9

- Two workflows now, not one: `ci.yml` (lint/breaking/gen/build/tsc, then `publish-ts`) and `security.yml` (a secret scan), both reproduced in full below since the second is new.
- `ci.yml`: two jobs, `check` (PRs, main, `v*` tags) and `publish-ts` (pushes only, `needs: check`). CI calls `buf` directly from `bufbuild/buf-setup-action@v1`, never `make` — a `Makefile`-only change is not exercised by CI, the two must be kept in step by hand.
- The breaking check is the point of `ci.yml`: `.github/workflows/ci.yml:31` says a wire break here "would be a production incident in web/mobile/agent-runner, so it is caught at the source." It runs only `if: github.event_name == 'pull_request'`.
- Trap: `actions/checkout` leaves a PR on a detached merge commit with no local `main`, so the step must `git fetch --no-tags origin main:main` before `buf breaking --against ".git#branch=main"` can read it. The same applies locally on a fresh clone. `fetch-depth: 0` exists purely for this.
- The staleness gate is `buf generate` then `git diff --exit-code --stat gen/`, failing with `::error::gen/ is stale. Run 'make gen' and commit the result.` A different buf/plugin version than `buf.gen.yaml`'s pins will trip it.
- Go version is never written in the workflow: `actions/setup-go@v5` takes `go-version-file: go.mod`. TypeScript check is `npm install --no-audit --no-fund && npm run build` in `gen/ts` on node 24 — a tsc compile only, no tests.
- `publish-ts` versions without committing (`npm version --no-git-tag-version`): a `v*` tag publishes `${GITHUB_REF_NAME#v}` under dist-tag `latest`; a push to main publishes `0.0.0-canary.${GITHUB_SHA::12}` under `canary`, to GitHub Packages (`npm.pkg.github.com`, scope `@tactical-agent-neural-knowledge`) authenticated with the ambient `github.token` — no external npm credential needed. `concurrency: group: ci-${{ github.ref }}` with `cancel-in-progress: true` can kill a half-finished publish on a second push.
- `security.yml` is a gitleaks secret scan, **inlined rather than called as a reusable workflow**, and the file's own header comment explains why at length: this repo is public, the org's shared `workflows` repo is private, and GitHub refuses a reusable workflow from a private repo to a public caller before any job is even scheduled — the run was a nought-second failure with no job and no log, and it had been failing silently on every push since adoption. The duplication here is the price of being public; if `workflows/.github/workflows/secret-scan.yml` changes its rules, this file has to be updated by hand to match.
- `security.yml` triggers: `pull_request`, `push` to main, a weekly `schedule` (Monday 06:17 UTC) that scans full git history (`fetch-depth: 0`) because "a credential committed and reverted is still a credential that leaked" in a public repo, and `workflow_dispatch`. Non-scheduled runs scan only the working tree (`fetch-depth: 1`).
- gitleaks is fetched as a pinned release binary (`VERSION: "8.30.1"`), not the Action, because the Action asks organisations for a licence key. The scan step always `--exit-code 0`; a separate `report` step (`if: always()`) decides pass/fail by reading `gitleaks.sarif` — this means a gitleaks crash can't silently read as a clean scan, but it also means the report step is the only thing actually gating the job.
- `report` step fails hard, deliberately, if `gitleaks.sarif` is missing at all ("an unknown result is a failure, never a pass") and again if the SARIF has findings. Findings are redacted in the log/summary because the log is world-readable on a public repo. A false positive is silenced only with a dated entry in `.gitleaksignore`, never by dropping the check.
- Both workflows declare `permissions: contents: read` at the top; only `ci.yml`'s `publish-ts` adds `packages: write`.
