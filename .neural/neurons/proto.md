# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage. Five domains were added since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers, invoices, payments, expenses and a cash summary. Amounts are integer cents (`int64 *_cents`, never float). `Invoice.share_url`/`pay_url` are the two credential-shaped fields: `GetInvoiceRequest.rotate` mints a new share link and kills the old one, because the token is stored only as a hash and cannot be read back — a lost link has no recovery but rotation.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that remember what they were written from (`Canvas.sources`, each with `seen_at`/`changed`/`changed_note`) and go stale (`Canvas.staleness`) when those move. `Block` is edited one at a time via `UpdateBlockRequest.base_rev`, not the whole page, so two people editing different paragraphs never collide. `BLOCK_KIND_DECISION` feeds `ListDecisions`, the cross-page decision ledger — a decision records what it supersedes (`supersedes_block_id`) rather than being edited in place.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board of `BoardObject`s inside `Board`. `AppFrame` (board.proto:52) is the product's actual differentiator — a frame can hold the *running application* (`preview_url`, `drawn_from_sha`, `moved_on`), not a picture of it, and `RequestChangeRequest` turns a click on a running element into a thread the agent works in. `BoardObject.rev` and `PutObjectsRequest.base_revs` give the same per-object optimistic-concurrency pattern as canvas blocks. `BoardObject.meta` is deliberately one opaque string (editor relationships: component instance, layout, pinning) rather than a field per idea, so a renderer that understands none of it still draws the board correctly.
- `proto/tank/remediation/v1/remediation.proto` is the boundary between "what is wrong" and "who fixes it": the security control registry (messaging core) submits a `Finding` across this file to the remediation engine (agent control plane), and neither side has an RPC into the other's job — `RemediationService` has no method that changes a control, retires a probe, or marks a finding resolved. Default `Disposition` is `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with a mandatory `test_requirement`, `reversible`+`undo`, and `lockout_risk` classes can never be auto-apply regardless of what else they declare.
- `proto/tank/security/v1/security.proto` is Neuralsecurity Phase 0: "controls are the primitive, frameworks are views over them" (security.proto:11) — one `Control` per fact, `FrameworkClause` only maps existing controls onto SOC2/etc, never adds a second set of facts. `ControlState` is deliberately pessimistic: `NOT_YET` beats an unevidenced "probably true", and a check that hasn't run recently reports `UNKNOWN` rather than repeating its last answer (`Evidence.stale`). Read-only service apart from `Evaluate`, which only re-runs checks.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode, and `StartRunRequest.mode = "neural"` skips planning and works in `repo` whatever the Tread is bound to. Now imports `board`, `books` and `canvas` to expose those services through `RunnerService` (`BooksSummary`, `WriteUpThread`, `ReadBoard`, `DrawOnBoard`, `ArrangeBoard`, etc.) so a run acts as the workspace's own agent with the same checks a person gets from the page.
- `PolicySummary.tools_gate_destructive` (agentctl.proto:63) closes a real gap: until 2026-10-07 a workspace's `destructive_tool` gate patterns were evaluated by the control plane but never told to the sandbox, so the gate the policy promised could not open and the command just ran — a deny list the runner cannot see denies nothing. `ControlService` gained write RPCs (`BindChannelRepo`, `SetChannelRepoAccess`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`, …) because the messaging core has only `USAGE`+`SELECT` on schema `agent`, owned by the control plane; these are narrow single-purpose calls, deliberately not a generic "write this table" RPC.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws` — now joined by `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}` (block/object-level diffs, e.g. `CanvasBlockChanged`, `BoardObjectsChanged`) plus ephemeral `typ.{ws}.canvas.{canvas}` / `typ.{ws}.board.{board}` presence (`CanvasEditing`, `BoardPointer` — the agent's own cursor is `BoardPointer.kind = "agent"`).
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Subscribe`/`Unsubscribe` now carry `canvas_ids`/`board_ids` alongside `channel_ids`/`thread_root_ids` — a client that never subscribes to a page or board never receives another editor's change. `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `agentctl` and `events` now import `board`/`books`/`canvas`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (or the raw `npx @bufbuild/buf generate` in this sandbox): managed mode supplies `go_package` unless the file sets `option go_package` itself (all five new domains do, matching the pattern `github.com/.../contracts/gen/go/tank/<domain>/v1;<domain>v1`), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
