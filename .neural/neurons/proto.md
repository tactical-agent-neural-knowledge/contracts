# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five are new this refresh: `board`, `books`, `canvas`, `remediation`, `security` — none of the five is in the hand-written TS barrel `gen/ts/src/index.ts` yet (see root neuron).
- `board` (Neuralboards), `books` (Neuralbooks) and `canvas` (Neuralcanvas) are the three product surfaces the agent shares with people in a workspace — an infinite board, double-entry bookkeeping, a written-page wiki — each with its own CRUD service (`BoardService`, `BooksService`, `CanvasService`) and its own realtime fan-out wired into `events.proto`/`realtime.proto` (see below). `agentctl.proto` gives the in-sandbox runner a parallel, simplified RPC set for each (`BooksSummary`/`BooksCreateInvoice`/..., `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`) rather than the full admin surface.
- `board.proto`'s `AppFrame` is the point of the whole domain: a frame can hold the *running application* at a commit, not a screenshot of one, and `Element`/`RequestChangeRequest` let a click inside that running frame turn into a change request — "the design and the code stop being two places."
- `canvas.proto`'s `Source` is what makes a page different from a wiki doc: it cites the threads/decisions/repositories it was written from, and is expected to say when those have moved rather than silently going stale. `Live` blocks are filled in server-side on read so a canvas is never stale about its own numbers. Blocks are edited one at a time (`UpdateBlockRequest`) so two people writing different paragraphs both succeed — same one-object-at-a-time model as `board.PutObjectsRequest`.
- `books.proto`: amounts are integer cents in the workspace currency, ids are Snowflake decimal strings like everywhere else, double-entry underneath but the surface is just `Customer`/`Invoice`/`Payment`/`Expense`/`CashSummary`. `RecordPaymentRequest` with no amount means "what is still due."
- `remediation.proto` and `security.proto` are a deliberately split pair (Neuralsecurity phases 0 and §2.3): `security.proto`'s `Control`/`ControlState` is the registry of what's true about TANK's own system (`CONTROL_STATE_UNKNOWN` on a stale check, never its last answer — "a registry that flatters the system is worse than no registry"); `remediation.proto` is the engine that turns a `Finding` into a pull request. The file comment is explicit that the registry (messaging core) and the engine (agent control plane) must stay two different programs — "a system that can mark its own homework is not a security system" — so the registry submits findings across the boundary but cannot run anything, and the engine cannot touch a control. Neither file is imported by any other proto yet.
- `remediation.proto`'s `Disposition` defaults to `DISPOSITION_PROPOSE` (a PR a human merges); `DISPOSITION_AUTO_APPLY` is reversible-only, behind a policy gate, with a one-click undo, and restricted to a short declared class list — never a connection the model decides on its own. `DISPOSITION_REFUSED` is a first-class outcome, distinct from a failed attempt.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `topo.DecideBenchmarkRequest.supersedes_id`. Dropping `optional` to tidy a field silently changes meaning.
- `agentctl.proto` grew from 673 to 1045 lines this refresh (board/books/canvas RPCs above, plus platform-ops). `PolicySummary.tools_gate_destructive` (new) is the fix for a real gap documented in the field's own comment: the destructive-tool deny patterns existed in every workspace's policy and the control plane evaluated them, but nothing inside the sandbox was ever told the patterns — "a deny list the runner cannot see denies nothing." Don't assume a `PolicySummary` without this field is safe to trust for gating.
- `agentctl.ControlService.RefreshNeuralKnowledge` and `OpenThread` are new: refreshing a repo's Neural Knowledge is itself a modeled RPC — the control plane finds a Tread with access to the repo, keeps one standing thread per repo for refreshes, and the call is idempotent while one is already running (`started = false`). `RunContext.skip_neural_knowledge` / `StartRunRequest.skip_neural_knowledge` exist to run the same task with and without the layer, for measuring it.
- `agent.TreadSettings.pull_requests` (new) is `"review"` (default: posts the PR, mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges) — the setting is already on the wire even if a given client UI doesn't expose it yet. `agent.TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment`/`SetUpRepoPreviews` are new premium-workspace hosting RPCs: TANK can generate a Tread's repo from a template or, for a workspace's own repo, open a PR adding the workflow file that reports builds — "a pull request and never a push: a workflow file in somebody else's repository is their decision."
- `events.proto` and `realtime.proto` both grew the same three ways this refresh, once per new live surface: a `*Changed` event (board/canvas content), ephemeral pointer/editing presence (`BoardPointer`, `CanvasEditing` — ", never stored"), and matching `Subscribe`/`ClientFrame`/`ServerFrame` fields/oneof cases carrying `board_ids`/`canvas_ids`. Subscribing is what makes another person's edit arrive; a client that never asks is unaffected.
- `topo.GetBriefingResponse` gained `hours` (24-hour ring for Home) and `setup` (`BriefingSetup`, first-week onboarding checklist); `workspace.HomeLayout.setup_hidden` is the matching "person dismissed it" flag.
- `admin.proto` gained `EndMemberSessions`: end every session a member holds without touching their membership or tokens — the only way to sign someone out before this was remove-then-re-add.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest file and `GetBootstrap` is still its point: one call on app open, everything else lazy.
- `proto/tank/agentctl/v1/agentctl.proto` remains the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids are Snowflake decimal strings.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}` / `.thread.{root}` / `.user.{uid}` / `.ws`, plus now `evt.{ws}.board.{board}` / `evt.{ws}.canvas.{canvas}` and their `typ.` ephemeral counterparts.
- Cross-package imports make FILE-level breaking bite across domains: `events.proto` now also imports `board` and `canvas`; `agentctl.proto` now imports `board`, `books` and `canvas`. A field removed from any of those fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `buf breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
