# Neurons · proto

refreshed 2026-10-07 · 77435ec229ee

- 25 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Three domains are new since the last refresh and are the biggest files in the repo: `board.proto` (549 lines, Neuralboards — the infinite board whose frames can hold a running application, not a picture of one), `books.proto` (333 lines, Neuralbooks — double-entry bookkeeping surfaced as customers/invoices/payments/expenses), `canvas.proto` (302 lines, Neuralcanvas — pages that cite the threads/decisions/repos they were written from and say when those have moved).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Staleness is a repeated idea, not just a canvas thing: `Board.staleness` / `staleness_note` (board.proto), `AppFrame.moved_on` / `moved_note` (what a frame was drawn from has moved on), and `BoardObject.derived` (`Derivation`, board.proto) all carry the same shape — 0 is current, something moved, say so in a sentence. `ReportPreview` / `ReportBoardSource` / `DeriveDiagram` are how a frame or diagram gets redrawn from what is actually true instead of from memory.
- `AppFrame` and `BoardSource` are deliberately the same shape for the same reason (board.proto:453): TANK never holds a customer's deploy or DB credentials. A workspace's own CI calls `ReportPreview`/`ReportBoardSource` with a token scoped to `board:preview` to say where its build is or what its schema is; TANK never polls or reaches in.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file outside board/books/canvas (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/agentctl/v1/agentctl.proto` (380 lines) is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode. Since the last refresh it also carries `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport` and `WriteUpThread`/`ReadCanvas`/`AskCanvas` and the whole board tool surface (`ListBoards`…`RecordFinding`) — every tank tool call listed in the umbrella CLAUDE.md goes through this one proto.
- `proto/tank/agent/v1/agent.proto` grew from the auth-only Run/Agent pair to also own `TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` (agent.proto:324-347, TANK generating and waking a Tread's own repo) and `TreadSettings.read_neural_knowledge` / `pull_requests` / `pr_reviewer_ids` — the per-Tread knobs `agentctl.RunContext.skip_neural_knowledge` and `task_class` read at run start.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`. `AuditLogged` is internal — the gateway never fans it out to clients. It now imports `board`, `canvas` and `workspace` as well, so a field removed from any of those breaks FILE-level breaking here even if events.proto itself is untouched.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `agentctl` imports `agent`, `blocks`, `board`, `books` and `canvas` in one file. A field removed from `message.proto` or `board.proto` fails the breaking check in every file that merely references it.
- `BoardService` (board.proto:528) has 19 RPCs; `ExportBoard.format` is `"svg"|"png"|"jpg"|"pdf"` (empty = svg), and `scale`/`quality` only apply to raster formats — a vector export has nothing to scale or compress. `BoardEmbedResponse.page_url` doubles as the credential: `rotate` mints a new link and silently breaks the old one, `revoke` turns `embedded` false for good.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — `board`, `books` and `canvas` are not in it today.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
