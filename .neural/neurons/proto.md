# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new files: Neuralboards is `board.v1`, Neuralbooks is `books.v1`, Neuralcanvas is `canvas.v1`.
- `board.proto` (Neuralboards): an infinite board whose `AppFrame` can hold the *running application*, not a screenshot (`board.proto:50-51`) — a person clicks into it and `RequestChangeRequest` asks for a change to the element they clicked, sourced via `Element.origin` that the preview build stamps on. `ReportPreviewRequest`/`ReportBoardSourceRequest` are deliberately the same shape: a workspace's own CI tells TANK where a build or a schema already is, so TANK never holds a credential into somebody else's network (`board.proto:450-459`).
- `books.proto` (Neuralbooks): double-entry bookkeeping surfaced as customers/invoices/payments/expenses/`CashSummary`, integer cents, Snowflake-string ids. `BankTransaction` reconciliation always records *why* a line matched (`MatchBankTransactionRequest`), and `Invoice.share_url` is a rotatable credential, same pattern as `board.proto`'s `BoardEmbedRequest`.
- `canvas.proto` (Neuralcanvas): a page that cites what it was written from (threads, decisions, repos) and says when that's gone stale — "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true" (`canvas.proto:13-14`). `Block.live` fields are filled in by the server on read, not stored, so a canvas is never stale about its own data. Blocks write independently (`UpdateBlockRequest`) so two people editing different blocks both succeed.
- `security.proto` + `remediation.proto` are one system split by design, enforced as a hard boundary: the registry (`security.v1`, in the messaging core) decides what is true and is read-only except `Evaluate`; the engine (`remediation.v1`, in the agent control plane) is the only thing that can write code and has no RPC to change a control or mark a finding resolved. `remediation.proto:17-19`: "A system that can mark its own homework is not a security system." `SubmitFinding` is idempotent on `(finding_id, control_version)` so an hourly evaluation doesn't open duplicate pull requests.
- `security.proto`'s rule: "Controls are the primitive, frameworks are views over them" (`security.proto:11-16`) — SOC 2 etc. are `FrameworkClause` mappings onto one set of `Control` facts, never a second set. A `ClauseCoverage` state is always derived as the worst of its mapped controls, never stored directly. `ControlState.UNKNOWN` beats a stale cached pass — "a check that has not run recently reports UNKNOWN rather than its last answer" (`security.proto:19-21`).
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` only applies to a short, declared `Class` list with a written reverse per class (`remediation.proto:129-132`) — this is the list meant to be shown to a buyer's security team.
- `agentctl.proto` grew the runner↔control-plane contract: `StartRunRequest.mode = "neural"` (with `repo`) runs a Neural Knowledge refresh instead of a normal task; `RunContext.skip_neural_knowledge` / `task_class` ("single_area" | "multi_area" | "") and `PolicySummary.tools_gate_destructive` (the destructive_tool gate patterns, absent until 2026-10-07 — see the comment at `agentctl.proto:61-69` on why a deny list the runner can't see denies nothing) all steer one run. `RefreshNeuralKnowledge` and `RegisterDeployment`/`GetDeployment` are new top-level RPCs for the knowledge refresh and TANK-hosted deployments respectively.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "server said zero" vs "older server said nothing" in `ChannelReadState.unread_count`. Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` imports `agent`, `blocks`, `board`, `books`, `canvas`; `events` imports nine other packages including the three new ones. A field removed from any imported file fails the breaking check everywhere it's referenced, not just in its own file.
- `realtime.proto`'s `ClientFrame`/`ServerFrame` oneofs grew `CanvasEditingFrame`/`BoardPointerFrame` (board/canvas presence, rate-limited like typing, never stored) alongside `Subscribe.canvas_ids`/`board_ids` — a client must subscribe to a page or board before another person's edit on it arrives.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — it covers 14 of 27 packages (unchanged this cycle; board/books/canvas/remediation/security are not yet in it).
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
