# Neurons · proto

refreshed 2026-10-15 · 6e371811ddb2

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` — Neuralboards, Neuralbooks, Neuralcanvas, and the two-sided security system (registry + fixer).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel."
- `tank.agent.v1.TreadSettings` (agent.proto:260) is the Tread switchboard: `pull_requests` is `"review"` (default, mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges); `merge_allowed` is the separate on/off gate for whether TANK may merge at all — both must line up, `pull_requests` alone does not grant merge rights. `neural_knowledge_enabled` (field 7) defaults on server-side and `RunContext.skip_neural_knowledge` (agentctl.proto) is how one run opts out.
- `proto/tank/security/v1/security.proto` and `proto/tank/remediation/v1/remediation.proto` are deliberately two services, not one: security.proto's rule is "Controls are the primitive; frameworks are views over them" (one `Control` per fact, `FrameworkClause` maps onto it, never a second set of facts) and a stale check reports `CONTROL_STATE_UNKNOWN`, never its last answer. remediation.proto's rule is the registry judges and submits a `Finding` across the boundary, the remediation engine is the only thing that writes code, and `Disposition.AUTO_APPLY` is narrow and declared per `Class` — propose-only is the default for everything else.
- `proto/tank/board/v1/board.proto`: a board's `Frame` can hold the running application itself (`AppFrame app`, frame-only), not a picture of one — that's the whole difference from any other canvas. `proto/tank/canvas/v1/canvas.proto` pages carry their own `staleness` / `staleness_note` so a page can say when it has drifted from what it cited, instead of silently going out of date.
- `proto/tank/books/v1/books.proto` is double-entry bookkeeping surfaced as customers/invoices/payments/expenses/`CashSummary`; amounts are integer cents, `Settings.enabled` gates the whole feature per workspace (premium).
- Realtime and events got matching additions for both new canvas/board editing: `realtime.proto`'s `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids`, `ClientFrame`/`ServerFrame` gained `canvas_editing`/`board_pointer` oneof members, and `events.proto` added `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` — the board one carries a `kind` ("user"|"agent") so an agent's own cursor draws distinctly.
- `optional` is used throughout as deliberate presence, not nullability: `ChannelReadState.unread_count` (channel.proto) is `optional` so a client can tell "server said zero" from "older server said nothing"; dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only, never the messaging core. `PolicySummary.tools_gate_destructive` (field 9) was added because the equivalent deny-list patterns existed in every workspace's policy but were never sent into the sandbox — "a deny list the runner cannot see denies nothing" (agentctl.proto:58-66). `RunContext.channel_goal_classification` distinguishes `"single_area"` (cheaper model, no plan stage) from `"multi_area"`.
- Cross-package imports make FILE-level breaking bite across domains: `events.proto` now imports `board` and `canvas`, `agentctl.proto` imports `board`, `books`, and `canvas`. A field removed from any of those fails the breaking check in every importer.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless the file sets one explicitly (board, books, canvas, remediation, security all do). The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain automatically.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
