# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five domains are new this refresh: `board`, `books`, `canvas`, `remediation`, `security` — each its own product, not an extension of an existing one.
- `board` (Neuralboards), `books` (Neuralbooks) and `canvas` (Neuralcanvas) are the three agent-facing surfaces that shipped together; each has its own top-level `*Service` (`BoardService`, `BooksService`, `CanvasService`) plus a matching set of `agentctl.proto` RPCs (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`, `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`, `ReadCanvas`/`AskCanvas`/`WriteUpThread`) so a run can use them without the full domain service.
- `proto/tank/board/v1/board.proto`'s whole point is `AppFrame`: a board frame can hold the running application at a commit, not a screenshot of it. `drawn_from_sha` + `drawn_at` vs. server-filled `moved_on`/`moved_note` is how a board learns its own frame has gone stale.
- `proto/tank/books/v1/books.proto`: amounts are always integer cents (`int64 ..._cents`), ids are Snowflake decimal strings like everywhere else. `Settings.stripe_secret_key` is write-only — set to store, send empty to leave alone, read back only as `stripe_key_hint` (last four chars). Invoices go through `tank.<domain>` style states (`INVOICE_STATUS_DRAFT|SENT|OVERDUE|PAID|VOID`); `VOID` is "never counted", not deleted.
- `proto/tank/canvas/v1/canvas.proto`'s stated reason to exist: "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true." `BLOCK_KIND_DECISION` and `BLOCK_KIND_LIVE` are the two block kinds that carry that promise — `Decision.needs_revisiting`/`revisit_note` for the first, and `Live` blocks being filled in by the server at read time (never stored stale) for the second.
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberately split pair, documented at length in `remediation.proto`'s header: the security registry (judge) and the remediation engine (fixer) "must not be the same program" — the registry can only submit a `Finding` across the boundary, never run anything; the engine can never alter a control or framework mapping. Read that header comment before touching either file.
- `security.proto`'s rule is "controls are the primitive, frameworks are views over them" — one `Control` per fact, `FrameworkClause` maps onto controls, never a second set of facts. `ControlState.UNKNOWN` is mandatory for a check that hasn't run recently; it must never report its last answer stale, and `NOT_APPLICABLE`/`PARTLY` both require a non-empty `reason` so a control can't quietly disappear.
- `remediation.proto`'s four house rules, stated verbatim in the file: propose-only by default (a PR a human merges; `AUTO_APPLY` is narrow and declared), every remediation carries its required regression test as an enforced requirement not a suggestion, a finding fans out class-wide across every repo/workspace it applies to (the fan-out is recorded), and every remediation names the run that drove it.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline holds for the new domains — e.g. `board`/`canvas` events talk about "pages" and "boards" in comments but the wire types stay `Canvas`/`Board`.
- Realtime got two new per-page/per-board frame types mirroring the existing typing pattern: `CanvasEditingFrame`/`BoardPointerFrame` on `ClientFrame`, `CanvasEditing`/`BoardPointer` events echoed on `ServerFrame` — both ephemeral (never stored), rate-limited like typing. `Subscribe`/`Unsubscribe` grew `canvas_ids`/`board_ids`: a client that never subscribes never sees another person's edit.
- `tank.agent.v1.TreadSettings` (agent.proto:260) is the Tread-level switchboard: `pull_requests` is `"review"` (default: posts the PR, mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges); `read_neural_knowledge` toggles whether runs in this Tread read/record this very layer, on by default.
- `RunContext.task_class` (agent.proto:124) is how the control plane classes an ask ("single_area", etc.) for routing/special modes, and `skip_neural_knowledge` (agent.proto:120, also on `StartRunRequest`) exists specifically to run the same task with and without this layer as a measurement — don't treat it as dead weight if you see it unset.
- `agentctl.proto` grew `RefreshNeuralKnowledge` and `OpenThread` RPCs (this refresh is itself driven through the former) plus a GitHub-preview cluster: `RegisterDeployment`/`GetDeployment`, `SetUpPreviewWorkflow`, `BindChannelRepo`/`UnbindChannelRepo`/`SetChannelRepoAccess`, `CreateGitHubConnectState`. `StartRunRequest.mode = "neural"` skips planning and works in `repo` regardless of what the Tread is bound to.
- `unread_count` trap is unchanged and still live: `Channel.last_seq` (channel.proto:44) says "unread = last_seq - last_read_seq", but `ChannelReadState.unread_count` (channel.proto:77-85) documents why that's wrong (thread replies and deletions also consume a `channel_seq`). Use `unread_count`.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second. FILE-level breaking means cross-package imports (e.g. `events.proto` now importing `tank.board.v1`/`tank.canvas.v1`) make a field removed from an imported file break the importer's check too.
