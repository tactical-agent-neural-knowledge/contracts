# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (22 at the last refresh), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New since last refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberate separation of powers: `security` (the control registry) judges what is wrong, `remediation` (the agent control plane) is the only thing that can write a fix. The engine has no RPC to change a control, retire a probe or mark a finding resolved — read the file header before adding one.
- `remediation.proto`: `SubmitFinding` is idempotent on `(finding_id, control_version)`; `Disposition` defaults to `PROPOSE` (a PR a human merges) and `AUTO_APPLY` is only legal for a `Class` that declares `reversible`, `undo` and `test_requirement` and does not set `lockout_risk`.
- `security.proto`: `ControlState` has no state for "probably fine" — `NOT_YET` is the honest default for anything unmeasured, and a check that hasn't run recently reports `UNKNOWN` rather than its last answer (`Evidence.stale`). `Posture.unknown` is pulled out separately because it says whether the rest of the posture can be trusted.
- `board.proto`'s `Frame` can hold the running application (`AppFrame`), not a picture of one; `drawn_from_sha` / `moved_on` is how a board learns the app has moved on since it was drawn. `PutObjectsRequest.base_revs` and `BoardObject.rev` give per-object optimistic concurrency, same pattern as canvas blocks.
- `canvas.proto` and `board.proto` both edit one unit at a time (`UpdateBlockRequest`, `PutObjectsRequest`) rather than the whole document, so two people editing different parts never collide — only the same block/object twice is a reported conflict, never a silent overwrite.
- `books.proto`: amounts are integer cents, `Settings.stripe_secret_key` is write-only (read back only as `stripe_key_hint`), and `GetInvoiceRequest.rotate` mints a new `share_url` and kills the old one in the same call — the share token is stored as a hash and is never readable back, rotate is the only recovery.
- `proto/tank/agentctl/v1/agentctl.proto` picked up three new surfaces this cycle: Neuralbooks (`BooksSummary`/`BooksCreateInvoice`/...), Neuralcanvas (`WriteUpThread`/`ReadCanvas`/`AskCanvas`), and Neuralboards (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`) — each a thin runner-facing wrapper that imports the domain's own types rather than redeclaring them.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) closes a real gap dated in the comment: before 2026-10-07 the destructive-tool gate patterns lived in policy and were evaluated by the control plane but never sent into the sandbox, so the gate the policy promised could not open and the command just ran.
- `optional` is still used throughout as deliberate presence, not nullability (see `channel.proto`, `topo.proto`, `workspace.proto`); dropping it to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` now also imports `board`, `books` and `canvas`; `events` imports `board` and `canvas` for `BoardObjectsChanged`/`CanvasBlockChanged`. A field removed from one of those fails the breaking check in every importer.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`; managed mode in `buf.gen.yaml` supplies `go_package`. Some newer files (`books`, `canvas`, `remediation`, `security`, `billing`, `catalog`, `monitor`, `platform`, `topo`) also declare an explicit `option go_package` — redundant under managed mode but harmless; most files have none.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
