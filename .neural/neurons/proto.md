# Neurons · proto

refreshed 2026-10-07 · 77435ec229ee

- 25 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `board`, `books` and `canvas` are the newest domains (added since the last refresh) and are not yet in the hand-written TS barrel `gen/ts/src/index.ts` — see the root neuron.
- `proto/tank/agentctl/v1/agentctl.proto` `RunnerService` is the entire tool surface an in-sandbox agent gets, one RPC per tool: `PostToThread`, `PostPlan`, `AskForApproval`, `AskQuestion`, `DrawOnBoard`, `ArrangeBoard`, `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`, `WriteUpThread`, `AskCanvas`, `OpenPullRequest`, `RequestCiWatch`, `RecordDecision`, `Remember`, `RecordFinding`, etc. — adding a tool to the product means adding an RPC here first.
- `ControlService.StartRunRequest.mode` is `""` for an ordinary run or `"neural"` for a Neural Knowledge refresh; `"neural"` skips planning and works in `repo` regardless of what the Tread is bound to, and `repo` becomes required. `skip_neural_knowledge` exists only to A/B the value of this layer (same task with/without it).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/board/v1/board.proto`: Neuralboards. `Frame.app` is what makes a board different from every other canvas tool — a frame can hold the running application, not just a picture of one. `BoardTemplate` save/list/delete, `ExportBoard`/`ListBoardSlices`/`BoardEmbed` (raster, named-region slice, or embed link) and `DeriveDiagram` are all new since the last refresh. `staleness`/`staleness_note` on previews is how a board learns what it shows no longer matches what is deployed.
- `proto/tank/books/v1/books.proto`: Neuralbooks, the money side kept by an agent in the workspace — double-entry underneath, customers/invoices/payments/expenses/cash-summary on the surface. Amounts are always integer cents. `Settings.stripe_secret_key` is write-only by convention (set to store, send empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — there is no RPC to read the real key back.
- `proto/tank/canvas/v1/canvas.proto`: Neuralcanvas, pages that cite the threads/decisions/repositories they were written from; `staleness`/`staleness_note` fire when a citation moves so the page says it might be wrong instead of going quietly stale. `WriteFromThread` and `Ask` are the two entry points (write a thread up, query the written pages).
- `proto/tank/agentctl/v1/agentctl.proto` `RunContext` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode (planning → `plan`, implementing → `acceptEdits`).
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `agentctl` imports `agent`, `blocks`, `board`, `books` and `canvas`. A field removed from any of those fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
