# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage. Newest five: `board`, `books`, `canvas`, `remediation`, `security` — each is the product surface for a Neural* feature (Neuralboards, Neuralbooks, Neuralcanvas) or the security/remediation control plane, and each is also exposed to agent runs through mirror RPCs on `agentctl.proto`'s `RunnerService` (BooksSummary/BooksCreateInvoice/BooksRecordExpense/BooksRecordPayment/BooksReport, WriteUpThread/ReadCanvas/AskCanvas, ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists. `HomeLayout.setup_hidden` (new) is whether the person dismissed the first-week setup cards that `topo.proto`'s `BriefingSetup` describes.
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, the largest file) is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode, and `StartRunRequest.mode = "neural"` skips planning and works in `repo` whatever the Tread is bound to.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9) closed a real gap, documented in the field's own comment: the destructive-tool deny patterns lived in every workspace's policy and the control plane evaluated them, but nothing inside a sandbox was ever told the patterns — "a deny list the runner cannot see denies nothing." Any new policy-driven gate must be mirrored onto `PolicySummary` or it is enforced nowhere the runner can see it.
- `agentctl.proto`'s block of `BindChannelRepo` / `UnbindChannelRepo` / `SetChannelRepoAccess` / `CreateGitHubConnectState` / `SetChannelAgentSettings` / `SetWorkspaceAgentPolicy` on `ControlService` exists because schema `agent` belongs to the control plane (messaging core has USAGE + SELECT only, never DML) — see the comment at `agentctl.proto:328-348`. These RPCs are deliberately narrow, one per write the messaging core needs; there is no generic "run this statement against my schema" RPC and there will not be one.
- `proto/tank/remediation/v1/remediation.proto` is the other half of that same separation-of-powers idea at the security layer: `tank.security.v1`'s control registry (judges) submits a `Finding` across `RemediationService.SubmitFinding`; the agent-control-plane-implemented engine (fixes) can only propose a pull request by default (`Disposition.PROPOSE`), and `DISPOSITION_AUTO_APPLY` is restricted to a short declared `Class` list that must state `reversible`/`undo` and can never be set when `Class.lockout_risk` is true. The engine has no RPC to mark a finding resolved or edit a control — see the file header comment.
- `proto/tank/security/v1/security.proto`'s one rule is in its own header: "Controls are the primitive; frameworks are views over them" — a `Control` is the single fact, a `FrameworkClause` (e.g. SOC 2 "CC6.1") only maps onto it, never adds a second set of facts. `ControlState` has no state meaning "we assume yes": `NOT_YET` is the honest home of anything unmeasured, and a stale `Evidence` always forces `UNKNOWN` rather than repeating the last answer.
- `proto/tank/board/v1/board.proto` (549 lines, new) is Neuralboards: an infinite board where `BoardObject.kind = OBJECT_KIND_FRAME` can hold `AppFrame` — the running application at a commit, not a screenshot (`Frame.app`, board.proto:50-69). `Board.staleness`/`AppFrame.moved_on` track drift between what was drawn and what shipped, the same pattern Neuralcanvas uses for its own pages. `PutObjectsRequest.base_revs` + `BoardObject.rev` is the optimistic-concurrency scheme: one shape at a time, so two people moving different objects never collide.
- `proto/tank/books/v1/books.proto` (343 lines, new) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/`CashSummary`. Amounts are integer cents. `Settings.stripe_secret_key` is write-only (set it, read back only `stripe_key_hint`'s last four chars). `GetInvoiceRequest.rotate` mints a new `share_url` and kills the old one — the share token is stored as a hash and is unrecoverable by design, so rotation is the only recovery path for a lost link (books.proto:155-164).
- `proto/tank/canvas/v1/canvas.proto` (302 lines, new) is Neuralcanvas: pages that cite what they were written from (`Canvas.sources`, each a `Source` with `changed`/`changed_note`) and go stale (`Canvas.staleness`) the same way a board does. `Decision` blocks form a workspace-wide ledger (`ListDecisionsRequest`/`DecisionRecord`) with `supersedes_block_id` chains. Edits are per-block (`UpdateBlockRequest.base_rev`), not per-page, so two people editing different paragraphs both succeed.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, plus the new `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}` (block/object-level `CanvasBlockChanged`/`BoardObjectsChanged`) and ephemeral `typ.{ws}.canvas.{canvas}` / `typ.{ws}.board.{board}` (`CanvasEditing`/`BoardPointer`, never stored). `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` mirrors those additions on the gateway frames: `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids`, and `ClientFrame`/`ServerFrame` gained `canvas_editing`/`board_pointer` oneof members, rate-limited like typing and never persisted. `Event.cursor` is still the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` still caps at 500 ids and *replaces* the set rather than adding to it.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- `proto/tank/admin/v1/admin.proto` gained `EndMemberSessions` (field comment at admin.proto:67-82): ends every session a member holds without touching their membership or bot/API tokens — the "a laptop went missing" action, as distinct from `RemoveMember` which only ends sessions as a side effect of taking the person's last membership.
- `proto/tank/agent/v1/agent.proto` gained hosting/preview RPCs: `CreateTreadRepo`/`SetTreadDeployment` (TANK-generated repo + cluster hosting, premium + admin-only, one per Tread) and `SetUpRepoPreviews`/`ListRepoPreviewSetups` (opens a PR adding a preview-reporting workflow to a repo the workspace already connected — a PR, never a push to someone else's default branch). `TreadSettings` gained `pull_requests` ("review" default vs "merge_when_green") + `pr_reviewer_ids`, and `read_neural_knowledge` (on by default, server always sets it).
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `events` now also imports `tank.board.v1` and `tank.canvas.v1`, `agentctl` imports `tank.board.v1`, `tank.books.v1` and `tank.canvas.v1`. A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` (though recent domains set it explicitly anyway), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
