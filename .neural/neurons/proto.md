# Neurons · proto

refreshed 2026-10-07 · d58208d52ddc

- 26 domains now (4 new since 2026-10-03: `board`, `books`, `canvas`, `security`), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `tank.board.v1` (board.proto, 549 lines) is Neuralboards: an infinite board whose `Frame` can hold a *running application* (`AppFrame`), not a screenshot. `BoardObject.rev` is bumped on every write so two people (or a person and an agent) editing different objects never collide; `PutObjectsRequest.base_revs` is how a client says what it last saw, and a mismatch comes back in `PutObjectsResponse.conflicts` rather than being silently overwritten.
- `tank.board.v1.AppFrame`/`Derivation` both carry a `drawn_from_sha` / `moved_on` / `moved_note` triple — the board's staleness model: a frame or a derived diagram remembers the commit it came from, and compares it against what shipped since to say "this has moved on" instead of quietly going stale (same idea as `Board.staleness` and Neuralcanvas's own staleness field).
- `tank.board.v1.BoardObject.meta` (field 18) is one opaque string for editor-only relationships (component instance, named style, layout, pin, visibility) — deliberately not one proto field per concept, so a renderer that only knows geometry/`Style` still draws the board correctly and ignores what it doesn't understand.
- `tank.books.v1` (books.proto) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses, integer cents throughout. `Settings.stripe_secret_key` is write-only by convention — set to store, empty to leave alone, read back only as `stripe_key_hint` (last four chars); nothing in the schema enforces that, so a server that echoes it back on read would leak it.
- `tank.security.v1` (security.proto) models **controls, not framework checklists**: `Control` is the one primitive (owner, `CheckKind`, `ControlState`, `Evidence`/`Attestation`), and `FrameworkClause`/`ClauseCoverage` are read-only views mapping existing controls onto SOC2-style clauses. A clause's state is "derived, never stored: the worst of its controls" (security.proto:186) — adding a framework must never add a new fact, only a new mapping.
- `tank.security.v1.ControlState.CONTROL_STATE_UNKNOWN` is not "state unspecified" — it's the forced answer when a check hasn't run recently enough (`Evidence.stale`), distinct from the honest "not yet implemented" (`NOT_YET`). Setting `MET` without a resolving `Evidence` defeats the whole model.
- `proto/tank/agent/v1/agent.proto` (new: `RunState` now has 19 values, through `RUN_STATE_APPROVAL_EXPIRED`) and `proto/tank/agentctl/v1/agentctl.proto` (240 new lines) grew the agent surface with Neuralboards/Neuralbooks/Neuralcanvas tool calls (`DrawOnBoardRequest`, `BooksCreateInvoiceRequest`, `WriteUpThreadRequest`, `AskCanvasRequest`, ...) — the sandboxed runner never talks to those services directly, only through `RunnerService` in agentctl, authenticated by `RUN_TOKEN`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, plus the new `.canvas.{canvas}` and `.board.{board}` subjects for `CanvasBlockChanged`/`BoardObjectsChanged` and friends. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it. `Subscribe`/`Unsubscribe` now also take `canvas_ids`/`board_ids` — a client that never subscribes to a page or board never receives another editor's live changes to it.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- `proto/tank/topo/v1/topo.proto` separates derived marks (always `MARK_STATUS_OPEN`, never stored, no `created_by_user_id`) from stored ones with a real lifecycle; only stored marks ever produce a `TopoMarkUpdated` event. `RecordEvent` is for first-party observers only and carries a `dedupe_key` because webhooks get redelivered. `GetBriefingResponse` now also returns `BriefingHour` (last 24h of message/run activity, for Home's day ring) and `BriefingSetup` (first-week checklist booleans, `done` = all true).
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, and now `agentctl` imports `board`, `books` and `canvas`, while `events` imports `board` and `canvas` too. A field removed from any imported file fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and currently misses 12 of the 26 domains (see `.neural/neurons/root.md`) — a new domain needs its own `export * as <name>` line added by hand.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
