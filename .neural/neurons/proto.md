# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now, up from 22 last refresh (new: `board`, `books`, `canvas`, `remediation`, `security`). Still always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`, managed mode supplying `go_package` unless the file opts out (see root neuron). Adding a domain needs only the new file plus `make gen` — lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml` — but the hand-written TS barrel at `gen/ts/src/index.ts` needs its own edit to pick it up.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same split for the new domains: `board.proto` is Neuralboards, `canvas.proto` is Neuralcanvas, `books.proto` is Neuralbooks — product names only in comments and READMEs, never in `package` or message names.
- `proto/tank/remediation/v1/remediation.proto` is the newest and most load-bearing addition: the seam between the security registry (messaging core, decides what's true/wrong) and the remediation engine (agent-control, the only thing that writes code). "A system that can mark its own homework is not a security system." Propose-only by default; every remediation must carry its own regression test as a requirement, not a suggestion; a finding fans out to every repository/workspace the same check applies to, recorded per-repo.
- `proto/tank/security/v1/security.proto`: "Controls are the primitive; frameworks are views over them" — one set of facts (`Control`, each with an owner/check/evidence query), frameworks (SOC 2 today) are `FrameworkClause` mappings onto controls, never a second set of facts. A control with no evidence is `NOT_YET` even when everyone is sure it holds, and a stale check reports `UNKNOWN` rather than its last answer — deliberately pessimistic by design.
- `proto/tank/board/v1/board.proto`: an infinite board shared by people and the agent; its one real difference from any other canvas tool is `Frame.app` — a frame can hold the *running* application, not a picture of one. `BoardObject` revisions are per-object (`base_revs` map in `DrawOnBoardRequest`/`ArrangeBoardRequest`) so a shape a person moved since the agent last read it is reported as a conflict rather than silently overwritten.
- `proto/tank/books/v1/books.proto` (Neuralbooks): `GetInvoiceRequest.rotate` mints a new share link and kills the old one atomically — the share token is stored as a hash, so an ordinary read returns an empty `share_url` and the link is *not* recoverable by anyone, TANK included, once issued. `rotate` (admin only) is the only way out for a business that lost its link; it is a deliberate, audited escape hatch, not a bug in "forgot it, can't get it back."
- `proto/tank/canvas/v1/canvas.proto`: "the written side of a team's work" — a page cites the threads/decisions/repositories it was written from and flags itself stale when those move, rather than quietly rotting like a wiki. Per-block revisions (not whole-page), a decision ledger, and `Answer.sources` on `AskCanvasResponse` so an answer always names what it came from.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings. `RunnerService` now covers board/canvas/books tool calls directly (`DrawOnBoard`, `AskCanvas`, `BooksCreateInvoice`, …) — the runner acts as the workspace's own agent principal through the same checks a human hits from the page.
- `PolicySummary.tools_gate_destructive` (agentctl.proto, added this cycle) is the fix for a real production gap: the field was absent until 2026-10-07, meaning the control plane evaluated `policy.tools.gate.destructive_tool` patterns but the sandbox was never told, so the gate the policy promised could never open and the command just ran. "A deny list the runner cannot see denies nothing" — any new policy knob must be mirrored into `PolicySummary` or it is decorative. Separately, `ControlService` writes into schema `agent` (owned by the control plane; the messaging core may read it but not write it) — `BindChannelRepo`/`SetChannelRepoAccess`/`SetChannelAgentSettings`/etc are RPCs *because* of that boundary.
- `proto/tank/agent/v1/agent.proto` grew `TreadDeployment` (TANK's own hosting: `<slug>.tank.chat`, `managed`/`workflow_present`/`image_tag`) plus `CreateTreadRepo`/`SetTreadDeployment` (premium, admin-only, generates+wakes a repo from TANK's template) and `SetUpRepoPreviews`/`ListRepoPreviewSetups` (opens a PR adding the preview-reporting workflow to a repo the workspace *already* connected — never a push to a default branch, one failing repo never blocks the others). `SetUpRepoPreviewsResponse.token` is shown exactly once; `rotate_token` is the only way to see it again.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects `evt.{ws}.ch.{channel}` / `.thread.{root}` / `.user.{uid}` / `.ws`, plus new `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}`. `CanvasBlockChanged`/`BoardObjectsChanged` carry just the changed block/objects (not the whole page/board) so concurrent editors converge without a full reload. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto`: `Subscribe`/`Unsubscribe` now take `canvas_ids`/`board_ids` alongside `channel_ids`/`thread_root_ids` — a client must subscribe to a canvas/board for its live edits to arrive at all. `CanvasEditingFrame`/`BoardPointerFrame` are rate-limited and ephemeral like `TypingFrame`, never persisted; `BoardPointer.kind` ("user"|"agent") is what lets a client draw the agent's own cursor distinctly.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST: "Markdown is never the storage format." `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE); a `BlockAction` travels client → server → owning agent as an event, not an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events.proto` now imports `tank.board.v1` and `tank.canvas.v1` on top of `tank.admin.v1`/`tank.agent.v1`/`tank.blocks.v1`/etc; `agentctl.proto` imports `tank.agent.v1`, `tank.blocks.v1`, `tank.board.v1`, `tank.books.v1`, `tank.canvas.v1`. A field removed from any of those breaks every importer's breaking check even when the importer's own file is untouched.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
