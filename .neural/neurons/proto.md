# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New this refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same split elsewhere: Neuralboards is `tank.board.v1`, Neuralbooks is `tank.books.v1`, Neuralcanvas is `tank.canvas.v1`.
- `proto/tank/security/v1/security.proto` and `proto/tank/remediation/v1/remediation.proto` are a deliberate two-program split, stated in remediation.proto's own header: the registry (security.v1, lives in the messaging core) decides what is wrong; the engine (remediation.v1, lives in the agent control plane) is the only thing that can write code. Security "cannot run anything" and remediation "cannot change a control" — a system that can mark its own homework is not a security system.
- `security.proto`'s `ControlState` has no state meaning "looks fine": a control with no recent check reports `UNKNOWN`, never its last answer, and `NOT_APPLICABLE`/`PARTLY` both require a mandatory `reason` — an N/A without one is how a control quietly disappears.
- `remediation.proto`'s `Disposition.AUTO_APPLY` is narrow by construction: only a declared `Class` with its reverse documented is eligible, every remediation carries the regression test it is held to, and a refusal (`DISPOSITION_REFUSED` / `REMEDIATION_STATE_REFUSED`) is a first-class recorded outcome, not a missing row.
- `proto/tank/board/v1/board.proto` is the one package with no `option go_package` among the new domains — the other four (books, canvas, remediation, security) all set one. Nine files total now declare it by hand (billing, books, canvas, catalog, monitor, platform, remediation, security, topo); any new hand-written one must match the managed `go_package_prefix` in `buf.gen.yaml` exactly.
- `board.proto`'s `AppFrame` is the product distinction: a frame can hold the *running application* (`preview_url`, `status: building|live|failed|asleep`) rather than a picture of one — see also `ReportPreview`/`BoardSource` for how a workspace's own CI tells TANK where its build landed.
- `proto/tank/agentctl/v1/agentctl.proto` grew three new imports this refresh (`board`, `books`, `canvas`) so the runner can act as the workspace's own agent against those services (`BooksSummary`, `DrawOnBoard`, `AskCanvas`, etc. on `RunnerService`) — it is still runner ↔ control-plane only, never to the messaging core directly, authenticated by the per-run `RUN_TOKEN`.
- `agentctl.proto`'s new `BindChannelRepoRequest` / `SetChannelRepoAccessRequest` / `SetWorkspaceAgentPolicyRequest` etc. exist because schema `agent` belongs to the control plane and the messaging core has only SELECT on it (see the file's own "the agent schema's own writes" comment) — these RPCs are a deliberately narrow boundary, not a wider grant; there is no generic table+statement RPC and the comment says there will not be one.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) was added because the field was simply *absent* before 2026-10-07: the control plane evaluated destructive-tool patterns but never told the sandbox about them, so a deny list nothing could see denied nothing. Worth checking for this shape of bug elsewhere: a control that exists server-side but was never wired into the message the runner reads.
- `events.proto` and `realtime.proto` both grew parallel pairs for the two new live surfaces: `CanvasBlockChanged`/`CanvasEditing` + `BoardObjectsChanged`/`BoardPointer` are the stored/broadcast events; `CanvasEditingFrame`/`BoardPointerFrame` are the ephemeral, never-stored, rate-limited-like-typing counterparts on the websocket `ClientFrame`/`ServerFrame`. `Subscribe`/`Unsubscribe` now carry `canvas_ids`/`board_ids` alongside `channel_ids`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), empty-vs-unconfigured in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1`/`tank.channel.v1`, and now `agentctl` imports `board`/`books`/`canvas`. A field removed from an imported file fails the breaking check in every file that references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
