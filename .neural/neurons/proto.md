# Neurons · proto

refreshed 2026-10-14 · 6e371811ddb2

- 27 domains now (5 new this cycle: board, books, canvas, remediation, security), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `remediation.proto` and `security.proto` are Neuralsecurity's two halves and are deliberately two services, never one: `security` (messaging core) is the control registry that judges what is true/wrong; `remediation` (agent control plane) is the engine that can write code and open PRs. `remediation.proto`'s header comment states the rule: "A system that can mark its own homework is not a security system" — the registry cannot run anything, the engine cannot change a control. `Disposition` defaults to PROPOSE (a PR a human merges); `AUTO_APPLY` requires a declared, reversible `Class` with no `lockout_risk` and a mandatory `test_requirement`.
- `security.proto`'s `ControlState` is deliberately pessimistic: `NOT_YET` is the honest home of "probably true but unevidenced", and a stale/never-run check reports `UNKNOWN` rather than its last answer — "a registry that flatters the system is worse than no registry."
- `board.proto`'s whole point is `AppFrame`/`Frame`: a board frame can hold the *running application*, not a screenshot (`BoardObject.app`). `Board.staleness`/`Derivation.moved_on` is the same "this might be out of date" pattern as `Canvas.staleness` — both at 0 (current) to 100 (nothing it rested on still holds).
- `books.proto`: amounts are integer cents, ids are Snowflake strings like everywhere else. `Settings.stripe_secret_key` is write-only (set to store, empty to leave alone, read back only as `stripe_key_hint`'s last 4 chars) — same share-link-as-credential pattern as `Invoice`'s rotate-only `share_url`/`GetInvoiceRequest.rotate`.
- `canvas.proto`: a page's `Source` records what it was written from and whether that has `changed` — the whole premise ("the failure of every wiki... is that nobody can tell what is still true"). `Block.live` is filled in server-side on read (never stale by construction); writes are per-block (`UpdateBlockRequest.base_rev`), same collision model as `board.PutObjectsRequest.base_revs`.
- Product vocabulary never reaches the wire: `proto/tank/channel/v1/channel.proto:7`, Channel "is presented as a 'Tread' in the product… The wire name stays Channel."
- `agent.proto`'s `TreadSettings` is where "can TANK merge its own PRs" lives: `pull_requests` ("review" default | "merge_when_green") plus `merge_allowed`, `pr_reviewer_ids`, `notify_reviewers` — added this cycle, next to `auto_accept_plans`.
- `agentctl.proto` (runner ↔ control-plane only, never messaging core directly) grew RPCs mirroring Neuralbooks/Neuralcanvas/Neuralboards for a run acting as the workspace's agent (`BooksSummary`, `WriteUpThread`, `DrawOnBoard`, etc.), plus `PolicySummary.tools_gate_destructive` — this field was *absent* until 2026-10-07, and its absence meant the destructive_tool gate the policy promised could never open inside the sandbox; "a deny list the runner cannot see denies nothing."
- `agentctl.proto`'s new agent-schema RPCs (`BindChannelRepo`, `SetChannelRepoAccess`, ...) exist because the messaging core was issuing INSERT/DELETE directly against schema `agent` (owned by the control plane, which only grants it SELECT) — green only in CI where the test fixture self-grants DML. Fixed as a narrow RPC boundary, not a wider grant, on purpose: "there is no RPC that takes a table and a statement, and there will not be one."
- `optional` is deliberate presence, not nullability, throughout (`UpdateChannelRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`). Dropping it to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `topo`/`search` import `tank.message.v1`, `admin` imports `tank.workspace.v1`/`tank.channel.v1`, and now `agentctl` imports `board`/`books`/`canvas`, `events` imports `board`/`canvas`. A field removed from an imported file fails the breaking check wherever it's referenced.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`; managed mode supplies `go_package` and the `PACKAGE_VERSION_SUFFIX` lint exemption already covers it. Remember `gen/ts/src/index.ts` is hand-written and won't pick it up.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
