# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- `tank.books.v1` (Neuralbooks) is double-entry bookkeeping run by an agent: `Settings.stripe_secret_key` is write-only (read back only as `stripe_key_hint`'s last four chars), `Invoice.share_url`/`pay_url` are credentials minted on send, and `GetInvoiceRequest.rotate` is admin-only because the share token is stored hashed and cannot otherwise be recovered — losing the link is otherwise permanent (books.proto:155-164).
- `tank.canvas.v1` (Neuralcanvas) and `tank.board.v1` (Neuralboards) share one shape: a `staleness` int (0 current, 100 nothing it rests on still holds) plus a `staleness_note` sentence, and both write one block/object at a time (`UpdateBlockRequest`/`PutObjectsRequest`) with a `base_rev`/`base_revs` optimistic-concurrency check so two editors never silently overwrite each other.
- `board.proto`'s whole point is `AppFrame`: a frame can hold the *running application* (`preview_url`, `drawn_from_sha`, `moved_on`) rather than a picture of one. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, layout, pinning) so a renderer that ignores it still draws the board correctly.
- `tank.security.v1` (Neuralsecurity) inverts the usual compliance model: `Control` is the one source of truth and `FrameworkClause`/`ClauseCoverage` are *views* over it — "controls are the primitive, frameworks are views over them" (security.proto:11). A stale check reports `CONTROL_STATE_UNKNOWN`, never its last answer; `NOT_APPLICABLE` and `PARTLY` both require a mandatory `reason`.
- `tank.remediation.v1` is the deliberate seam between judge and fixer: the control registry (messaging core) submits a `Finding` across this boundary and can only read back via `ListRemediations` — there is no RPC here to change a control or mark one resolved (remediation.proto:285-291). `SubmitFindingRequest` refuses when `judge_principal == fix_principal`.
- Remediation defaults to `DISPOSITION_PROPOSE` (a PR a human merges); `DISPOSITION_AUTO_APPLY` requires a declared `Class` with `reversible=true`, a non-empty `undo`, and `lockout_risk=false` — a class that risks locking an operator out can never be auto-apply regardless of what else it declares (remediation.proto:145-156).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new files: "Tread" and "Radar" never appear as wire names.
- `optional` is deliberate presence, not nullability, throughout: `ChannelReadState.unread_count` (channel.proto), `DecideBenchmarkRequest.supersedes_id` (topo.proto), `TopoPreferences.configured` (workspace.proto). Dropping it to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` grew from the runner↔control-plane contract into also carrying Neuralbooks/Neuralcanvas/Neuralboards calls *made from a thread* (`BooksCreateInvoice`, `WriteUpThread`, `DrawOnBoard`, …) plus a block of RPCs that exist only because the messaging core was issuing raw INSERT/DELETE against the `agent` schema it has no grant on — "the fix is a call, not a wider grant" (agentctl.proto ~line 330): `BindChannelRepo`, `SetChannelRepoAccess`, `SetWorkspaceAgentPolicy` etc. are the narrow, declared replacement, and there will deliberately never be an RPC that takes a table and a statement.
- `PolicySummary.tools_gate_destructive` (agentctl.proto:61-67) is new: until 2026-10-07 the destructive-tool deny list lived only in policy evaluated by the control plane and was never told to the sandboxed runner, so "the gate the policy promised could not open and the command simply ran." A policy field the runner can't see enforces nothing.
- Cross-package imports make FILE-level breaking bite across domains: `events.proto` now also imports `board` and `canvas` (for `BoardObjectsChanged`, `CanvasBlockChanged`, etc.), and `realtime.proto`'s `Subscribe`/`ClientFrame`/`ServerFrame` grew `canvas_ids`/`board_ids` and `CanvasEditingFrame`/`BoardPointerFrame` fields to carry the same two features over the gateway.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
- Adding a domain needs a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`. Convention is now split: `books`, `canvas`, `remediation`, `security` (and the older `billing`, `catalog`, `monitor`, `platform`, `topo`) declare `option go_package` explicitly; `board` — the newest of the five — does not and relies on managed mode's `go_package_prefix` like most packages. Picking which style to copy matters less than matching one of them exactly.
