# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 26 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New this refresh: `board` (Neuralboards), `books` (Neuralbooks), `canvas` (Neuralcanvas), `remediation`, `security` — the last two are Neuralsecurity's judge/fix split (see below). `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline holds in the new files: `board.proto`/`canvas.proto` call their things Board/Canvas on the wire, "Neuralboards"/"Neuralcanvas" only in comments.
- `proto/tank/agentctl/v1/agentctl.proto` roughly tripled and is now the biggest contract surface by RPC count: `RunnerService` (~30 rpcs) is every tool the sandboxed runner can call — thread/plan/card/approval/question/status, `BoardResearch`/`CommitFiles`/`SetBrand`/`SetLanding`/`RecordFinding` (gated by `RunContext.product_run`), the full Neuralbooks/Neuralboards/Neuralcanvas surfaces, git+CI (`OpenPullRequest`, `RequestCiWatch`, `GetCiFailure`), `RecordDecision`/`Remember`, and `SessionStore*`. `ControlService` is the separate operator surface (service-token, not `RUN_TOKEN`): `StartRun`/`RefreshNeuralKnowledge`/gates/`SessionStore`, plus product hosting (`CreateProductRepo`, `SetProductReplicas`, `RegisterDeployment`/`GetDeployment`, `SetUpPreviewWorkflow`) and the `BindChannelRepo` family that writes schema `agent` on the messaging core's behalf.
- `StartRunRequest.mode = "neural"` is this refresh's own trigger: it skips planning and works in `repo` regardless of what the Tread is bound to. `RunContext.task_class` ("single_area" | "multi_area" | "") lets the control plane route a simple ask to a cheaper model without a plan stage; `skip_neural_knowledge` turns this whole layer off for one run, for measuring it with/without.
- `proto/tank/board/v1/board.proto`: `AppFrame.drawn_from_sha`/`moved_on`/`moved_note` and `Board.staleness` are the same idea as a Neuralcanvas page — a board that can't say what it still matches is a board nobody trusts. `ReportBoardSource`/`DeriveDiagram` read a schema or an `infra/` tree from the workspace's own CI (a `board:preview`-scoped token) rather than TANK holding a database credential — same shape and same reasoning as `ReportPreview`.
- `proto/tank/books/v1/books.proto`: `Invoice.share_url` is write-once — the token is stored as a hash, so an ordinary `GetInvoice` returns it empty; `GetInvoiceRequest.rotate = true` mints a new link and kills the old one atomically (admin only), because a lost link is a billing problem but a readable-back token would be a credential leak. `Settings.stripe_secret_key` is the same write-only pattern (read back only as `stripe_key_hint`'s last four chars).
- `proto/tank/canvas/v1/canvas.proto`: `Source.changed`/`changed_note` on every citation is what makes a page's `staleness` meaningful — a page is only as current as the stalest thread/decision/repo/canvas it cites. `Canvas.parent_id`/`children` makes pages a tree, not a flat list.
- `proto/tank/remediation/v1/remediation.proto` is deliberately a different file from `security.proto`, not a different package in the same one: the comment block at the top states the registry (messaging core, judges) and the remediation engine (agent-control, the only thing that can write code) "must not be the same program." `Disposition` is `PROPOSE` (always, a human-merged PR) or `AUTO_APPLY` (narrow, reversible, never `lockout_risk`) or `REFUSED` (a first-class outcome, not an error). `Class.test_requirement` is mandatory for every class — "a fix without a regression test is a fix with a half-life."
- `proto/tank/security/v1/security.proto`: "Controls are the primitive; frameworks are views over them" — a `FrameworkClause` (SOC 2 today) maps onto existing `Control`s and is never allowed to assert a new fact. `ControlState` is deliberately pessimistic: a check that hasn't run recently reports `UNKNOWN`, never its last answer, and partial credit (`PARTIAL`) requires a mandatory `reason`.
- `events.proto`/`realtime.proto` gained a collab layer for the two new surfaces: `CanvasBlockChanged`/`BoardObjectsChanged` are persisted diffs (one block or a few objects, not a whole document); `CanvasEditing`/`BoardPointer` are ephemeral presence (never stored), rate-limited like typing. `Subscribe`/`Unsubscribe` grew `canvas_ids`/`board_ids` — a client that never subscribes never gets another person's edit.
- `topo.proto`'s `GetBriefingResponse` grew `BriefingHour` (an hourly activity ring for Home) and `BriefingSetup` (first-week checklist: goal set, GitHub connected, agent summoned, someone invited, avatar set); `workspace.proto`'s `HomeLayout.setup_hidden` is the one new field letting a person dismiss that checklist.
- Cross-package imports are real and make FILE-level breaking bite across domains: `agentctl` now imports `agent`, `blocks`, `board`, `books` and `canvas`; `events` imports `board` and `canvas` too. A field removed from any of those fails the breaking check everywhere it's referenced, not just in its own file.
- `optional` is still used throughout as deliberate presence, not nullability (unchanged-field semantics, "this replaces nothing", empty-vs-unconfigured) — dropping it to tidy a field silently changes meaning. Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`); `make breaking` catches the first, nothing but discipline catches the second.
