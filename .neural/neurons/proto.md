# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` (plus `topo`, already present but newly documented here).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." `tank.board.v1` and `tank.canvas.v1` follow the same rule: "Neuralboards"/"Neuralcanvas" are product names in comments only.
- `tank.board.v1` (board.proto, 549 lines) is Neuralboards: an infinite board of `BoardObject`s. Its one unusual idea is `AppFrame` (board.proto:52) — a frame can hold the *running application* at a commit, not a screenshot; `drawn_from_sha` + `moved_on` is how a frame learns it has gone stale, the same pattern Neuralcanvas uses for pages. `BoardObject.meta` (field 18, out of declaration order) is a single opaque string for editor-only relationships (component instance, named style, layout, pinning) so a renderer that doesn't understand it just leaves it alone. `BoardObject.rev` makes concurrent edits last-write-safe per object rather than per board.
- `tank.books.v1` (books.proto) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary. All money is integer cents. `Settings.stripe_secret_key` is write-only by convention (comment at books.proto:36-39): set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars — never round-tripped in full.
- `tank.canvas.v1` (canvas.proto) is Neuralcanvas: pages that cite what they were written from (`Source`), so a page can say when it has gone stale instead of quietly lying. `BlockKind.LIVE` blocks are filled in by the server at read time (`Live.value`/`detail`), never cached at write time — a canvas is never stale about its own data even when it is stale about everything else.
- `tank.remediation.v1` (remediation.proto) is the seam between the control registry (`tank.security.v1`, judges) and the agent control plane (fixes): remediation.proto:9-38 states the rule in prose — "A system that can mark its own homework is not a security system." `Disposition.PROPOSE` is the default for every code change; `AUTO_APPLY` is deliberately narrow. A `Finding` carries `control_version`; a finding against a changed control version is treated as a different finding, not an update.
- `tank.security.v1` (security.proto) is Neuralsecurity's control registry: `ControlState` has five honest values and no "probably fine" — `NOT_YET` is correct even when everyone believes a control holds but nobody can evidence it, and a check that hasn't run recently reports `UNKNOWN` rather than repeating its last answer (security.proto:38-41). `CheckKind.NONE` controls can never be `MET`.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only, now 931+ lines. `PolicySummary.tools_gate_destructive` (added this refresh, field 9) is the fix for a real gap: the destructive-tool gate pattern existed in every workspace's policy and was evaluated by the control plane, but was never sent into the sandbox, so the gate could not open and the command simply ran (agentctl.proto:60-68 explains it in place). `RunContext.skip_neural_knowledge` + `StartRunRequest.skip_neural_knowledge` exist to run the same task with/without the Neural Knowledge layer for measurement.
- `ControlService` in agentctl.proto now has a block of narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) that exist only because schema `agent` grants the application role USAGE+SELECT and nothing else; the messaging core was issuing INSERT/DELETE directly against `agent.*` tables, only green because the CI fixture self-grants DML (agentctl.proto:328-349). The fix is a call per intent, deliberately not a generic "run this statement" RPC — there will not be one.
- `RefreshNeuralKnowledgeRequest`/`OpenThreadRequest` (agentctl.proto) are how this very refresh gets triggered: the control plane keeps one standing thread per repository and starts a "neural" mode run there, idempotent while one is already active.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope; now imports `board` and `canvas` for `BoardObjectsChanged`/`CanvasBlockChanged` etc. `CanvasEditing`/`BoardPointer` are explicitly "Ephemeral… Never stored" — presence-shaped events riding the same bus as persisted ones.
- `proto/tank/realtime/v1/realtime.proto`: `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids` — a client that never subscribes never sees another person's edit arrive. `ClientFrame`/`ServerFrame` oneofs gained `canvas_editing`/`board_pointer`, rate-limited like typing and never persisted.
- `proto/tank/admin/v1/admin.proto`: `EndMemberSessions` (new) signs a member out of every session without touching membership or bot/API tokens — previously the only way to force sign-out was remove-then-re-add the member.
- `optional` is still used throughout as deliberate presence, not nullability (`ChannelReadState.unread_count`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`); dropping it to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books`, `canvas` on top of `agent`/`blocks`; `events` imports `board`/`canvas`. A field removed from `canvas.proto` can fail the breaking check in `agentctl.proto` and `events.proto` even though neither defines it.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second. `gen/ts/src/index.ts` is hand-written and still covers only 14 of 27 domains — `board`, `books`, `canvas`, `remediation`, `security` (this refresh's new domains) are absent from it along with the 8 noted previously, so consumers must deep-import those.
