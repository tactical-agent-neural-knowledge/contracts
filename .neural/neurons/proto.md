# Neurons · proto
refreshed 2026-10-09T15:24:11Z · e52a377a71d9

- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines) is the biggest and most central file: the runner<->control-plane contract, split into two services — `RunnerService` (per-run `RUN_TOKEN`, everything a sandboxed agent calls: PostToThread, PostPlan, AskForApproval, BoardResearch, Books*, ReadBoard/DrawOnBoard, OpenPullRequest, SessionStore*) and `ControlService` (operator/product surface: StartRun, DecideGate, CreateProductRepo, BindChannelRepo, SetWorkspaceAgentPolicy — service-token only, never RUN_TOKEN).
- All ids on the wire are Snowflake decimal strings (`string ... _id`), never an int type — this is stated once in agentctl.proto's top comment and assumed everywhere else.
- `optional` scalar fields mean "unset = leave unchanged" on an Update* request (see `UpdateChannelRequest`, `SetChannelPreferenceRequest`) or "server didn't compute this" on a response (`ChannelReadState.unread_count`) — never reach for a sentinel value (0, "") for "not set" when the field is optional.
- Every enum's zero value is `*_UNSPECIFIED = 0`; several carry an explicit fallback meaning in a trailing comment (e.g. `NOTIFY_PREF_UNSPECIFIED` = "follow the workspace preference") — read the comment before assuming unspecified means "none".
- `tank.events.v1.Envelope` wraps every durable bus event and every realtime frame payload in one `google.protobuf.Any payload`; adding a new event type means adding a message here *and* wiring it into whatever reads `Envelope.type`/unpacks the Any elsewhere (not visible from this repo).
- `channel.proto` is the canonical example of the "wire neutral, product-named is the exception" rule from CLAUDE.md: the message is `Channel`/`ChannelType`, but `TreadGoal`/`TreadPlan`/`DescribeTread`/`CreateTreadFromPlan` are intentionally product-named because they're Tread-specific concepts with no neutral equivalent — don't rename `Channel` to `Tread` and don't try to neutralize `TreadGoal` either.
- `board.proto`'s `Frame` (`OBJECT_KIND_FRAME`) can hold a *running application*, not just a picture — that's the one thing that makes Neuralboards different from a normal whiteboard proto and is easy to miss skimming the enum.
- `books.proto Settings.stripe_secret_key` is write-only by convention: set it to store, send empty to leave alone, read back only as `stripe_key_hint` (last four chars) — same shape as a password field, enforced by convention/comment only, not by any proto option.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9) was added 2026-10-07 after a real gap: the runner enforced policy locally but was never told which patterns must open a `destructive_tool` gate, so the gate silently never opened. If you add a new client-enforced policy field, mirror it here too or it has the same failure mode.
- `go_package_prefix` in `buf.gen.yaml` is the only required override; adding a new `tank/<domain>/v1` directory needs no new entry in `buf.gen.yaml` or `buf.yaml` — modules/plugins are repo-wide.
- Cross-domain imports are common and are checked by `buf breaking` at `FILE` granularity (`buf.yaml`): `agentctl.proto` alone imports `agent`, `blocks`, `board`, `books`, `canvas`; `events.proto` imports ten other domains. A breaking change in a widely-imported domain (`agent`, `channel`, `blocks`) risks failing CI in many unrelated-looking files.
