# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` — each is a whole product surface, not an extension of an existing one.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same pattern in the new files: `board.proto` is Neuralboards, `books.proto` is Neuralbooks, `canvas.proto` is Neuralcanvas — none of those words are the package name.
- `proto/tank/board/v1/board.proto`: an infinite board of `BoardObject`s inside a workspace. `AppFrame` is the point — a frame can hold the *running application* at a commit, not a screenshot (`drawn_from_sha` / `moved_on` track when the frame has gone stale against what's deployed).
- `proto/tank/books/v1/books.proto`: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary. Amounts are always integer cents. `Settings.stripe_secret_key` is write-only — set to store, send empty to leave alone, read back only as `stripe_key_hint` (last four chars). Money goes to the business's own Stripe, never TANK's.
- `proto/tank/canvas/v1/canvas.proto`: pages that cite what they were written from (threads, decisions, repositories) and say when that source has moved — "the failure of every wiki is... nobody can tell what is still true" (canvas.proto:14). `BLOCK_KIND_LIVE` embeds a real, current figure; `BLOCK_KIND_DECISION` is structure, not prose.
- `proto/tank/remediation/v1/remediation.proto` and `security.proto` are a deliberately split pair: `security` (the control registry — what's true and what's wrong) lives in the messaging core, `remediation` (the engine with the GitHub App and sandboxes that can write code) lives in the agent control plane. The file's own words: "A system that can mark its own homework is not a security system." Never collapse them into one service.
- `security.proto`'s `ControlState` is deliberately pessimistic: `NOT_YET` is the honest home of "probably true but unmeasured," a stale check reports `UNKNOWN` rather than its last answer, and `NOT_APPLICABLE` requires a `reason` so a control can't quietly vanish. Controls are the one set of facts; frameworks (SOC 2 etc.) are views over them, never a second set of facts.
- `remediation.proto`'s four rules, enforced by the shape of the messages, not just stated: propose-only by default (`AUTO_APPLY` is a narrow, declared exception), every remediation carries the regression test it's held to, a finding fans out to every repo/workspace the same check applies to, and every remediation names the run that drove it.
- `agentctl.proto` grew an `agent`-schema write boundary (`BindChannelRepo`, `SetChannelRepoAccess`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`, etc.) because the messaging core was issuing INSERT/DELETE directly against `agent.*` tables it only has SELECT on in production — green in CI only because the test fixture over-grants itself. The fix is narrow RPCs, not a wider grant, and per the file's own comment there will not be a generic "table + statement" RPC.
- `agentctl.proto` also carries the agent's own tool surface as of this refresh — `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` — each a thin pass-through to the matching domain service, invoked by the agent as the workspace's own agent with the same checks a person gets.
- Cross-package imports keep growing and still make FILE-level breaking bite across domains: `events.proto` now imports `board` and `canvas` for their realtime events (`BoardObjectsChanged`, `CanvasBlockChanged`, etc.), and `realtime.proto`'s `Subscribe`/`ClientFrame`/`ServerFrame` grew canvas/board variants alongside channel ones.
- `optional` is still deliberate presence, not nullability (see `ChannelReadState.unread_count`, `TopoPreferences.configured`); nothing in this refresh's additions changes that convention, and the new `EndMemberSessionsResponse.sessions_ended` (plain `int32`, not `optional`) is a counter, not a presence flag — don't confuse the two patterns.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
