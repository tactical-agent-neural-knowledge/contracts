# Neurons · proto

refreshed 2026-10-15 · 09478439316a

- 27 files now (was 22): this refresh added `board`, `books`, `canvas`, `remediation` and `security`, each the usual one-package-per-domain shape, `proto/tank/<domain>/v1/<domain>.proto`, package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `tank.board.v1` (`BoardService`, 19 RPCs) is Neuralboards: an infinite board of `BoardObject`s inside optional `Board` frames, where `AppFrame` can hold the *running application* at a commit rather than a screenshot — `ReportPreview`/`ListPreviews`/`ForgetPreview` are how a workspace's own CI tells TANK where a build landed. `RequestChange` asks for an edit to whatever is in a running frame; `GenerateTest` turns a journey through that app into a test; `ExportBoard`/`BoardEmbed`/`ListBoardSlices` cover raster/embed/slice export.
- `tank.books.v1` (`BooksService`, 19 RPCs) is Neuralbooks: double-entry bookkeeping surfaced as customers, invoices, payments, expenses and a `CashSummary`. Amounts are integer cents in the workspace currency, ids are Snowflake strings like everywhere else. `ReadReceipt` is model-read receipts; `ImportBankTransactions`/`MatchBankTransaction` is the bank-feed-to-invoice/expense matching path.
- `tank.canvas.v1` (`CanvasService`, 10 RPCs) is Neuralcanvas: pages that cite what they were written from (`Source`) and go stale when that source moves — "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true" (file header). `Live` blocks are filled in by the server at read time, so a canvas is never stale about its own embedded data. `WriteFromThread` and `Ask` are the two agent-facing entry points (write a thread up, query the pages).
- `tank.remediation.v1` (`RemediationService`, 5 RPCs) is the fix-it half of Neuralsecurity, deliberately a separate program from the half that judges (`tank.security.v1`) — file header: "a system that can mark its own homework is not a security system." Four fixed rules: propose-only by default (`AUTO_APPLY` is a short, declared exception list); every fix ships a regression test; a finding fans out class-wide across every repo/workspace it applies to, not just the one it arrived on; every action is recorded via the run's own event stream.
- `tank.security.v1` (`SecurityService`, 5 RPCs) is the posture side: "controls are the primitive, frameworks are views over them" — one `Control` per fact (owner, check, evidence query), frameworks (SOC2 etc.) only ever map onto existing controls, never add new facts. A control that errors or hasn't run recently reports `UNKNOWN` rather than reusing its last answer — the model is allowed to say "we don't know."
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `TreadSettings` (agent.proto:260) is where the merge/notify policy lives, and the three fields interact rather than stacking independently: `pull_requests` is `"review"` (default, posts + mentions `pr_reviewer_ids`) or `"merge_when_green"`; `merge_allowed` is the separate on/off switch for whether TANK may merge *at all*; `notify_reviewers` only fires when a PR is actually waiting on a person (`merge_allowed` off, or `pull_requests == "review"`), falling back to whoever requested the run when `pr_reviewer_ids` is empty.
- `TreadDeployment` (agent.proto:363) is TANK's own hosting for a Tread's app: `<slug>.tank.chat` + repo `agenture-<slug>`. `CreateTreadRepo` makes one (premium workspaces only, gated by `RepoConnection.premium`/`hosting_available`), `SetTreadDeployment` wakes/sleeps it, `ListWorkspaceDeployments` lists every app a workspace hosts for the Treads the caller is in.
- `PolicySummary.tools_gate_destructive` (agentctl.proto:61, new this refresh) exists because of a production gap: the destructive-tool deny patterns lived in workspace policy and the control plane evaluated them, but nothing inside the sandbox was ever told the patterns, so the gate never actually opened — "a deny list the runner cannot see denies nothing." Any runner-side gate logic must read this field, not assume it's enforced upstream.
- `RunContext.skip_neural_knowledge` (agentctl.proto) turns off reading/writing this very layer for a run — set when a Tread disabled it, or the run is the control half of a measurement; `task_class` ("single_area" vs "multi_area", empty on older runs) is how the control plane chose planning depth and model tier.
- Unread-count trap, unchanged: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that's wrong — thread replies and deletes also consume a `channel_seq`. Use `unread_count`.
- `optional` is deliberate presence throughout, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id`, empty-vs-unconfigured in `TopoPreferences.configured`. Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains, and this refresh added more of them: `agentctl` now imports `board`, `books` and `canvas`; `events` now imports `board` and `canvas`; `realtime` carries `CanvasEditingFrame`/`BoardPointerFrame` client frames and the matching `CanvasEditing`/`BoardPointer` server events. A field removed from any of these fails the breaking check in every importer.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus regenerating: managed mode supplies `go_package` unless you opt out like the nine domains that set it explicitly (see root neurons), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel (`gen/ts/src/index.ts`) is hand-written and will not pick it up — board/books/canvas/remediation/security all still need deep imports from TS.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `buf breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
