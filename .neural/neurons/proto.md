# Neurons · proto

refreshed 2026-10-07 · 572da952c512

- 26 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New since the last refresh: `board`, `books`, `canvas`, `security` (whole new files, not additions).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same pattern in the new files: `board.proto` and `canvas.proto` are internally "Neuralboards"/"Neuralcanvas" in comments only; `books.proto` is "Neuralbooks".
- `proto/tank/board/v1/board.proto` (549 lines, new): an infinite board whose `Frame` can hold a *running application*, not a picture of one (`AppFrame`). `PutObjectsRequest.base_revs` is optimistic concurrency per-object — a mismatch returns the real version in `PutObjectsResponse.conflicts` rather than overwriting it. `BoardTemplate.custom` gates deletability: only workspace-saved templates can be removed, not ones TANK ships.
- `proto/tank/books/v1/books.proto` (333 lines, new): double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary. Amounts are integer cents in the workspace's currency (comment is explicit: no floats). `BankTransaction` + `MatchBankTransactionRequest` is reconciliation, separate from `RecordPaymentRequest`.
- `proto/tank/canvas/v1/canvas.proto` (302 lines, new): block-structured pages (`BlockKind`, e.g. `BLOCK_KIND_LIVE`, `BLOCK_KIND_DECISION`) that cite their sources and go stale when those sources move — the file's own framing is "the failure of every wiki is nobody can tell what is still true." One of the few files with an explicit `option go_package`.
- `proto/tank/security/v1/security.proto` (262 lines, new): "Controls are the primitive; frameworks are views over them" — one `Control` registry, `FrameworkClause`s (SOC 2 today) map onto it, never a second set of facts. `ControlState.UNKNOWN` is mandatory for a stale check — "a stale check reports UNKNOWN, never its last answer" — and `CheckKind.NONE` controls can never be `MET`. `SecurityService` is read-only except `Evaluate`, which only re-runs existing checks; nothing can mark its own homework.
- `events.proto`, `realtime.proto`, `topo.proto`, `workspace.proto` and `agent.proto` grew additive fields/messages this cycle rather than new files: `events.proto` gained `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` (the last three are how an agent's cursor is drawn on a board alongside people's); `realtime.proto`'s `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids`; `topo.proto`'s `GetBriefingResponse` gained `hours`/`setup` for Home's day ring and first-week checklist; `agent.proto` gained `TreadDeployment`, `CreateTreadRepo`, `SetTreadDeployment` and `SetUpRepoPreviews`/`ListRepoPreviewSetups` (TANK can now generate and host a Tread's repo, or open a PR adding CI to one the workspace already owns).
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/agentctl/v1/agentctl.proto` (913 lines, the biggest file overall) is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids are Snowflake decimal strings. `RunnerService` now also carries `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`, `ReadCanvas`/`AskCanvas`, and `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` — the runner tool surface tracks the new books/canvas/board domains directly rather than going through events.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events.proto` now also imports `tank.board.v1` and `tank.canvas.v1` on top of `admin`, `agent`, `blocks`, `channel`, `files`, `huddle`, `message`, `monitor`, `presence`, `topo`, `workspace`. A field removed from any of those fails the breaking check in `events.proto` even though it never touches events directly.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — `board`, `books`, `canvas`, `security` all shipped without it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
