# Neurons · proto

refreshed 2026-10-08 · b57522e4f7aa

- 27 domains now (was 22): `board`, `books`, `canvas`, `remediation` and `security` are new this window. Still one package per domain, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `security.proto` + `remediation.proto` are a deliberate split, not one feature in two files: `security.proto` (messaging core) is the judge — a `Control` registry where **"controls are the primitive, frameworks are views over them"**, every `ControlState` is honest including `UNKNOWN` for a stale/never-run check, and the service is read-only except `Evaluate` (re-runs checks, cannot mark anything met by itself). `remediation.proto` (agent control plane) is the fixer, reached only via `SubmitFinding`. Neither can do the other's job: the registry can't run anything, the engine has no RPC to change a control. Read the file headers (`security.proto:9-22`, `remediation.proto:9-38`) before touching either.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with `reversible=true`, an `undo`, a `test_requirement`, and `lockout_risk=false` — a class that could lock an operator out can never be AUTO_APPLY regardless of what else it declares (`remediation.proto:145-155`). `SubmitFinding` is idempotent on `(finding_id, control_version)`.
- `board.proto`'s point is `AppFrame`: a frame on an infinite board can hold the *running application* at a commit, not a screenshot (`board.proto:50-52`). `PutObjectsRequest` is one-object-at-a-time by design — two people moving different shapes never conflict. `RequestChangeRequest` + `Element` is how a click inside a live frame becomes a change request, relying on the preview build stamping elements with their source origin.
- `books.proto` is straightforward double-entry bookkeeping surfaced as customers/invoices/payments/expenses/a cash summary; amounts are integer cents, ids are Snowflake-string like everywhere else. `BankTransaction` matching (`MatchBankTransactionRequest`) always records why a line was matched, not just that it was.
- `canvas.proto`'s rule is in its own header: "what separates a canvas from a document is that it remembers what it was written from" — every `Canvas` carries `Source`s (threads, decisions, repos) that can go stale. `UpdateBlockRequest` edits one `Block` at a time so two people writing in different parts of a page both succeed; `WriteFromThreadRequest` drafts a page from a thread's actual decisions.
- `proto/tank/agentctl/v1/agentctl.proto` grew RPCs for every new surface the runner can touch from inside a sandbox: `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread`, `ReadCanvas`, `AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard`, plus repo/deployment plumbing (`CreateTreadRepo`, `SetTreadDeployment`, `SetUpRepoPreviews`, `ListRepoPreviewSetups`) and policy/admin RPCs (`SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`, `SetChannelRepoAccess`). It now imports `board`, `books` and `canvas` directly — those three packages are reachable only through the control plane, never the messaging core's own gateway.
- `PolicySummary.tools_gate_destructive` (`agentctl.proto:61-69`) is the fix for a real incident, documented inline: the destructive-tool deny patterns existed in every workspace's policy and the control plane evaluated them, but the field to tell the sandboxed runner about them did not exist until 2026-10-07 — "a deny list the runner cannot see denies nothing." Any new policy gate needs its matching field on `PolicySummary` in the same change or it is silently unenforced in the sandbox.
- `RunContext.skip_neural_knowledge` and `RunContext.task_class` ("single_area" vs "multi_area", empty on older runs) are both new on `RunContext`; `StartRunRequest.mode = "neural"` (documented in the pre-existing neuron below) skips planning entirely, these two fields instead steer an ordinary run.
- `events.proto` gained four real + two ephemeral events for the two new live surfaces: `CanvasBlockChanged`/`CanvasChanged` on `evt.{ws}.canvas.{canvas}`, `CanvasEditing` (ephemeral) on `typ.{ws}.canvas.{canvas}`; `BoardObjectsChanged`/`BoardChanged` on `evt.{ws}.board.{board}`, `BoardPointer` (ephemeral, carries `kind: "user"|"agent"`) on `typ.{ws}.board.{board}`. Same pattern as before: the objects-changed/block-changed event carries only what moved, never the whole document.
- Unread-count trap, unchanged: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq" while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that's wrong (thread replies and deletes also consume a `channel_seq`). Use `unread_count`.
- `optional` is still deliberate presence, not nullability, across `UpdateChannelRequest`, `SetChannelPreferenceRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`. Dropping it to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest file and `GetBootstrap` is still its point. `HomeLayout.setup_hidden` is new — whether the first-run setup checklist is dismissed.
- `proto/tank/topo/v1/topo.proto` gained `BriefingHour` (hourly message/run counts) and `BriefingSetup` (`goal_set`, `github_connected`, `agent_summoned`, `someone_invited`, `avatar_set`, `done`) feeding a day's briefing — derived read-side data, not a new mark type; the derived-vs-stored mark split from before is unchanged.
- Cross-package imports keep growing: `agentctl` now also imports `board`, `books`, `canvas` on top of `agent`/`blocks`; `events` imports `board`/`canvas` on top of `admin`/`agent`/`blocks`/`channel`/`files`/`huddle`. FILE-level breaking (`buf.yaml`) means a field removed from any of these fails the breaking check everywhere they're referenced, not just in their own file.
- Adding a domain still needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` — but check whether it needs an explicit `option go_package` (see root neuron: the managed-mode exception list is no longer small or consistent) and know the TS barrel `gen/ts/src/index.ts` will not pick it up automatically.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
