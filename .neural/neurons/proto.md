# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five domains are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- `board.proto` (Neuralboards) and `canvas.proto` (Neuralcanvas) both model an infinite/structured surface that "remembers what it was written from": `Board.staleness`/`staleness_note` and `Canvas.staleness`/`staleness_note` are the same idea — 0 is current, 100 means nothing it rests on still holds. `AppFrame` is the board's one real trick: a frame can hold the *running application* (`preview_url`, `drawn_from_sha`, `moved_on`), not a screenshot of it.
- `books.proto` (Neuralbooks) is double-entry bookkeeping behind a customers/invoices/payments/expenses/cash-summary surface; all money is integer cents. `Invoice.share_url`/`Settings.stripe_secret_key` are both write-once-read-never: the share token and the Stripe key are stored as hashes/last-four, so `GetInvoiceRequest.rotate` is the only way back from a lost link — admin only, old link dies the instant the new one is issued.
- `remediation.proto` and `security.proto` are the two halves of Neuralsecurity and must stay separate programs: `security` (the control registry, messaging core) judges, `remediation` (the engine, agent control plane) fixes, and `Remediation.forbidden_paths` + `judge_principal`/`fix_principal` enforce in the schema that neither can be the other. `SecurityService` is read-only except `Evaluate`, which only re-runs checks — nothing in it can mark its own homework.
- `security.proto`'s `ControlState` is deliberately pessimistic: `NOT_YET` is the honest home of "probably true but unevidenced", and a stale check reports `UNKNOWN` rather than repeating its last answer — `Evidence.stale` forces this. `Control.id` is "dotted and never renumbered"; frameworks (`FrameworkClause`) are views over controls, never a second set of facts.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with `reversible`, `undo`, and `test_requirement`, and `lockout_risk = true` forbids `AUTO_APPLY` regardless of what else the class declares.
- `agentctl.proto` grew the runner-facing surface for all three new domains in one pass: `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` on `RunnerService` — the agent acts as the workspace's own user, through the same checks a person gets. `PolicySummary.tools_gate_destructive` (field 9) is new and is itself a fix: the destructive-tool gate patterns existed in every workspace's policy but were never sent into the sandbox, so "a deny list the runner cannot see denies nothing" until this field shipped.
- `agentctl.proto`'s `ControlService` grew a parallel, narrower set of RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) because the messaging core had been issuing raw INSERT/DELETE against schema `agent`, which it only has USAGE+SELECT on — fixed as named calls, not a wider grant, "there is no RPC that takes a table and a statement, and there will not be one."
- `agent.proto`'s `TreadSettings.pull_requests` ("review" default | "merge_when_green") and `pr_reviewer_ids` are the actual home of the auto-merge-after-CI setting; it already exists on the wire next to `auto_accept_plans` and is not a TANK GitHub App setting — the app only grants reach.
- `TreadDeployment` + `CreateTreadRepo`/`SetTreadDeployment` (agent.proto) is TANK-hosted premium hosting (`<slug>.tank.chat`, `agenture-<slug>` repo); `SetUpRepoPreviews`/`ListRepoPreviewSetups` (agent.proto) plus `SetUpPreviewWorkflow`/`RegisterDeployment`/`GetDeployment` (agentctl.proto `ControlService`) is the separate path for a workspace's *own* repo: TANK opens a PR adding the reporting workflow, never pushes to a default branch directly.
- Unread-count trap still live: `Channel.last_seq` (channel.proto:44) says "unread = last_seq - last_read_seq" while `ChannelReadState.unread_count` documents why that's wrong (thread replies and deletes also consume a `channel_seq`). Use `unread_count`.
- `optional` is still deliberate-presence, not nullability, everywhere it appears (`UpdateChannelRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`). Dropping it to tidy a field silently changes meaning.
- `events.proto` and `realtime.proto` both grew matching pairs for the two new live surfaces: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` as bus events, mirrored by `CanvasEditingFrame`/`BoardPointerFrame` on the realtime `ClientFrame`/`ServerFrame` union and `Subscribe.canvas_ids`/`board_ids`. `BoardPointer.kind` ("user"|"agent") is what lets a board draw the agent's own cursor among people's.
- Cross-package imports keep making FILE-level breaking bite across domains: `agentctl` now imports `board`, `books`, and `canvas`; `events` now imports `board` and `canvas` too. A field removed from any of those fails the breaking check anywhere it's referenced.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` — managed mode supplies `go_package` (the five new domains all set it explicitly anyway, unlike most), and the `PACKAGE_VERSION_SUFFIX` lint exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and still does not cover any of `admin, billing, board, books, canvas, catalog, command, huddle, monitor, platform, remediation, security, topo` (12 of 27 domains) — adding a domain's proto does not add it to the barrel.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
