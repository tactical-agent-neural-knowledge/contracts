# Neurons · proto

refreshed 2026-10-07 · d58208d52ddc

- 26 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Four domains were added since the last refresh: `board`, `books`, `canvas`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." The same discipline holds in the new files: `board.proto`'s comments say "Neuralboards" and "Tread", but the messages are `Board`/`BoardObject`, never `Tread*`.
- `proto/tank/board/v1/board.proto` (549 lines, newest and biggest addition): an infinite board whose `Frame` can hold the running application rather than a picture of one (`AppFrame.preview_url`/`status`/`drawn_from_sha`). `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pinning) deliberately kept out of typed fields so a renderer that doesn't understand it still draws the board correctly.
- `board.proto`'s `PutObjectsRequest` and `canvas.proto`'s `UpdateBlockRequest` share one conflict model: a per-object/per-block `rev`, a client-supplied `base_rev`/`base_revs`, and a response that returns the other editor's version (`conflicts`/`theirs`) instead of overwriting it. Collisions are reported, never silently resolved, in both files.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/`CashSummary`. All money is integer cents (`int64 ..._cents`); `Settings.stripe_secret_key` is write-only and reads back only as `stripe_key_hint` (last four chars) — never round-trips the real key.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite what they were written from (`Source.ref`/`changed`), with a `staleness` score (0 current, 100 "nothing it rests on still holds") — the same convention `board.proto`'s `Board.staleness` reuses verbatim. `Live` blocks are filled in by the server at read time so a page is never stale about its own numbers.
- `proto/tank/security/v1/security.proto` (Neuralsecurity Phase 0) states its own rule in the file header: "Controls are the primitive; frameworks are views over them" — one `Control` registry, `FrameworkClause` rows are a crosswalk onto it, never a second set of facts. `ControlState.UNKNOWN` is mandatory once a check goes stale (`Control.stale`/`max_age_seconds`); a stale check must not keep reporting its last answer.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` (913 lines, the biggest file) is the runner ↔ control-plane contract only, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings. This refresh added `skip_neural_knowledge` (also on `agent.proto`'s `TreadSettings.read_neural_knowledge`) and `RunContext.task_class`, plus `RegisterDeployment`/`GetDeployment` mirroring `agent.proto`'s new `TreadDeployment` status fields and `CreateTreadRepo` (generate a repo for a Tread from its template).
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`. `AuditLogged` is internal — the gateway never fans it out to clients.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` when the file doesn't set one itself, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — it's now missing 12 of the 26 domains, including all four added this refresh.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
