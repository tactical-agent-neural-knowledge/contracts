# Neurons · proto

- 26 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New this cycle: `board`, `books`, `canvas`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `proto/tank/security/v1/security.proto` (new) is Neuralsecurity Phase 0: **controls are the primitive, frameworks are views over them**. One `Control` (owner, `CheckKind`, `ControlState`, `Evidence`) per fact about the running system; a `FrameworkClause` maps a framework (e.g. SOC 2) onto controls and is never a second set of facts. `ControlState.UNKNOWN` is forced the moment `Evidence.stale` is true — a check that has not run recently must report UNKNOWN, never its last answer; this is the one invariant the service exists to protect. `SecurityService` is read-only except `Evaluate`, which only re-runs checks — nothing in the wire lets a control mark its own homework.
- `proto/tank/books/v1/books.proto` (new) is Neuralbooks: customers, invoices (`share_url`, `competes_with`/`payment_instructions` in settings), payments, expenses (receipts read by the model via `ReadReceipt`), bank import/matching, and `GetCashSummary`/`GetReport` as the answers agents actually ask for (profit, cash, receivable, by category/customer). `RunnerService` exposes a parallel `Books*` surface (`BooksSummary`, `BooksCreateInvoice`, `BooksRecordExpense`, `BooksRecordPayment`, `BooksReport`) in `agentctl.proto` so a run never needs `BooksService` directly.
- `proto/tank/canvas/v1/canvas.proto` (new) is Neuralcanvas: pages built of typed `Block`s (`BLOCK_KIND_DECISION`, `BLOCK_KIND_LIVE`, `BLOCK_KIND_MESSAGE`, `BLOCK_KIND_TABLE`, ...). Its stated reason for existing over a generic wiki: a page cites the threads/decisions/repos it was written from, so staleness is representable instead of silent. `WriteFromThread` and `Ask` are the two entry points a run uses (exposed on `RunnerService` as `WriteUpThread`/`ReadCanvas`/`AskCanvas`); `CanvasBlockChanged` (events.proto) is block-granular so two editors in different paragraphs don't collide.
- `proto/tank/board/v1/board.proto` (new, 549 lines) is Neuralboards: an infinite board where `Frame.app` (`AppFrame`) can hold the **running application** at a repo/ref/route, not a screenshot — that is the whole premise of the domain. Grew across this cycle to add save-able `Template`s, raster/slice/embed `ExportBoard`, `GenerateTest` (a recorded journey through a running frame becomes a test), and `ReportBoardSource`/`DeriveDiagram` (diagrams drawn from what is true in the running app, not hand-drawn). `BoardPointer` (events.proto) carries a `kind` of `"user" | "agent"` so the agent's cursor renders distinctly from a person's.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode. Grew by 240 lines this cycle: `RunContext.task_class` and `StartRunRequest.skip_neural_knowledge`/`OpenThreadRequest.skip_neural_knowledge` (a run can opt out of the refresh this very file documents), plus `RegisterDeployment`/`GetDeployment` and the whole Books/Canvas/Board RPC surface on `RunnerService` — it now imports `board`, `books`, and `canvas` alongside `agent` and `blocks`.
- `proto/tank/agent/v1/agent.proto` grew `CreateTreadRepo`/`SetTreadDeployment`/`TreadDeployment` (a Tread's own app lifecycle: building/live/failed/asleep on TANK's cluster) and `TreadSettings.pull_requests`/`pr_reviewer_ids` plus `read_neural_knowledge` — the per-Tread switches that `agentctl`'s `skip_neural_knowledge` and `task_class` read at run start.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, the empty-vs-unconfigured distinction in `TopoPreferences.configured`. Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}` etc. This cycle added the full `canvas.*`/`board.*` event trio each (`*Changed` for persisted writes, an ephemeral `*Editing`/`*Pointer` on a `typ.{ws}.*` subject that is never stored) — same shape as the existing message/channel events, now imports `board` and `canvas`.
- Cross-package imports are real and make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books`, and `canvas` on top of `agent`/`blocks`; `events` imports `board` and `canvas` on top of `admin`/`agent`/`blocks`/`channel`/etc. A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless you write one explicitly (8 domains now do: billing, books, canvas, catalog, monitor, platform, security, topo). Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and still does not cover `board`, `books`, or `canvas` — it has not been updated since they landed.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
