# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 proto files now, five new domains since the 2026-10-03 refresh: `board`, `books`, `canvas`, `remediation`, `security`. Same convention throughout: `proto/tank/<domain>/v1/<domain>.proto`, package `tank.<domain>.v1`, one package per domain (`CLAUDE.md`). Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board whose `Frame` can hold the **running application itself**, not a screenshot (`AppFrame`, board.proto:50) — the thing a person can click into and ask for a change (`RequestChangeRequest`). `BoardService` also covers templates (`SaveBoardTemplate`), export (`ExportBoard` — raster/slice/embed), turning a clicked-through flow into a test (`GenerateTest`), and two workspace-reports-in patterns mirrored from each other: `ReportPreview` (a workspace's own CI says where its build is) and `ReportBoardSource` (a workspace's own CI says what its schema/infra is) — both exist so TANK never holds a credential or connection string into somebody else's system.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping underneath, customers/invoices/payments/expenses/`CashSummary` on the surface. Amounts are integer cents in the workspace currency. `BankTransaction` reconciliation always records *why* a line was matched. `ReadReceipt` reads a receipt with the model; `Export` hands an accountant the period as a file.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite what they were written from (`Source`) and say so when that drifts — "the failure of every wiki is... nobody can tell what is still true" (canvas.proto:14). `Live` blocks hold the real number, filled in server-side on read, never a cached screenshot. `UpdateBlock` writes one block at a time so two people editing different parts of a page both succeed. `ListDecisions` is the cross-page decision ledger — "what did we decide about X" is a query, not a search.
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are deliberately two files and two services, not one — the seam is load-bearing. `security.proto`'s `SecurityService` (the control registry, in the messaging core) judges: `Control`/`Posture`/`FrameworkCoverage`, almost entirely read-only (`Evaluate` only re-runs checks). `remediation.proto`'s `RemediationService` (the agent control plane) fixes: `SubmitFinding` → `Remediation` → pull request. "A system that can mark its own homework is not a security system" (remediation.proto:19) — the registry cannot run anything and the engine cannot touch a control, a probe or a framework mapping; there is no RPC on either side that would blur that.
- `security.proto`'s own rule: **controls are the primitive, frameworks are views over them** — one `Control` per fact, a `FrameworkClause` (e.g. SOC 2) only ever maps onto existing controls, never adds a second set of facts. A control with no evidence is `NOT_YET` even when everyone's sure it holds; a stale check reports `UNKNOWN`, never its last answer — "a registry that flatters the system is worse than no registry" (security.proto:21).
- `remediation.proto`'s four rules, each enforced by the shape of a message, not a comment: propose-only by default (`Disposition.PROPOSE` is the zero-value neighbour; `AUTO_APPLY` needs a declared `Class`); every `Remediation` carries the regression test it is held to; a `Finding` fans out to every `Target` repository the pattern applies to, not just the one it was reported against; every remediation names the run that drove it (the flight recorder). `SubmitFinding` is idempotent on `(finding_id, control_version)` — an hourly re-evaluation must not open a second round of pull requests.
- Existing domains got additive changes only (checked against main — all clean under `buf breaking`): `admin.EndMemberSessions` (ends every session a member holds without touching membership — the admin tool for "laptop went missing" vs. the existing remove-member flow for "person left"); `agent.TreadSettings` gained `pull_requests` ("review" default vs. `merge_when_green`) and `pr_reviewer_ids` and `read_neural_knowledge`; `agent.RepoConnection`/`TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` for TANK-hosted repos on premium workspaces; `agent.SetUpRepoPreviews` opens a pull request (never a push) adding the preview-reporting workflow to repos a workspace already connected.
- `agentctl.proto` is the biggest mover: it now imports `board`, `books` and `canvas` and `RunnerService` grew matching RPCs so a run can act as the workspace's own agent — `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`, `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` (`DrawOnBoardRequest.base_revs` carries the revisions last read per object id, so a shape somebody else moved is reported as a conflict instead of silently overwritten).
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9) closed a real gap, documented in the field comment itself (agentctl.proto:201-209): the destructive-tool deny patterns existed in every workspace's policy and were evaluated by the control plane, but were never told to the sandbox — "a deny list the runner cannot see denies nothing." Worth rereading before trusting any older `PolicySummary` consumer to have honored this gate.
- `agentctl.ControlService` grew a block of narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) explained at agentctl.proto:510-530: schema `agent` belongs to the control plane, the messaging core only has `USAGE`/`SELECT` on it, and the messaging core had been issuing direct INSERT/DELETE against it anyway — only ever green in CI, where the test fixture grants itself DML the prod role doesn't have. The fix is these RPCs, deliberately narrow (no generic "table + statement" write exists or will).
- `events.proto` and `realtime.proto` grew the matching live-collaboration triples for the two new surfaces: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`, each with a `realtime.proto` client frame (`CanvasEditingFrame`, `BoardPointerFrame`) rate-limited like typing and never stored. `BoardPointer.kind` ("user" | "agent") is what lets an agent's own cursor render distinctly while it draws beside people.
- Unread-count trap, still live: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong. Use `unread_count`.
- `optional` is used throughout as deliberate presence, not nullability — unchanged-field semantics, "this replaces nothing" (`DecideBenchmarkRequest.supersedes_id`), empty-vs-unconfigured (`TopoPreferences.configured`). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains, and the new domains widen this: `agentctl` now imports `board`, `books` and `canvas`; `events` now imports `board` and `canvas` too. A field removed from `canvas.proto` or `board.proto` can now fail the breaking check in `agentctl.proto` or `events.proto`, not just within their own file.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
