# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Five wholly new domains since the last refresh: `board` (Neuralboards — an infinite canvas whose frames can hold a *running application*, not a screenshot), `books` (Neuralbooks — double-entry bookkeeping surfaced as customers/invoices/payments/expenses), `canvas` (Neuralcanvas — pages that cite the threads/decisions/repos they were written from and say when those move), `remediation` (the half of Neuralsecurity that fixes: findings in, pull requests out) and `security` (the half that judges: a Control registry, frameworks are views over it).
- `remediation.proto` and `security.proto` are a deliberate split: the registry (`security`, in the messaging core) decides what is wrong and cannot run anything; the engine (`remediation`, in the agent control plane) holds the sandboxes and GitHub App and cannot change a control or mark a finding resolved. `remediation.proto:17-19`: "A system that can mark its own homework is not a security system." `RemediationService` has no RPC that edits a control; `SecurityService` is read-only apart from `Evaluate`, which only re-runs checks.
- `remediation.Disposition` defaults to `PROPOSE` (a pull request a human merges); `AUTO_APPLY` is only legal for a declared `Class` with `reversible = true`, a mandatory `undo`, and never for one with `lockout_risk = true` — the one thing a security fix must not become is the outage.
- `security.ControlState` is deliberately pessimistic: `UNKNOWN` is forced whenever a check is stale or has never run, never the control's last answer — "a stale check reports UNKNOWN, never its last answer: the silent failure mode of every security scanner is a broken check that stays green" (security.proto:38-40). `NOT_APPLICABLE` and `PARTLY` both require a mandatory `reason`.
- `books.Settings.stripe_secret_key` is write-only: send it to store it, send empty to leave it alone, read back only `stripe_key_hint` (last four chars). Same pattern as `Invoice`'s `share_url`/rotate on `GetInvoiceRequest` — the token is stored as a hash and cannot be read back by anyone, including TANK; rotating is the only recovery from a lost link.
- `canvas.Block` and `board.BoardObject` both carry a per-object `rev`/`rev` bumped on every write, and `UpdateBlockRequest.base_rev` / `PutObjectsRequest.base_revs` let a client detect a collision on one block or one shape rather than overwriting the whole page/board — the same single-item-conflict pattern both new domains converge on independently.
- `board.AppFrame.drawn_from_sha` / `moved_on` and `canvas.Source.seen_at` / `changed` are the same idea twice: a board or page that was derived from a running app, a repo, or a thread records what it rested on, so staleness (`Board.staleness`, `Canvas.staleness`) is computed, not asserted.
- `agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids are Snowflake decimal strings. It grew ~370 lines this cycle: `PolicySummary.tools_gate_destructive` (the destructive-tool gate patterns the runner previously could not see — "a deny list the runner cannot see denies nothing"), `RunContext.skip_neural_knowledge` / `task_class`, `RefreshNeuralKnowledge` / `OpenThread` on `ControlService`, and in-sandbox RPCs so a run can act as the workspace's own agent: `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard`.
- `agentctl.proto`'s last section is itself a neuron: schema `agent` belongs to the control plane (app role has USAGE + SELECT only), but the messaging core had been issuing raw INSERT/DELETE against it — "only ever green in CI, where the test fixture grants itself DML". The fix is six narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`), not a wider grant — "there is no RPC that takes a table and a statement, and there will not be one."
- `agent.TreadSettings.pull_requests` ("review" default | "merge_when_green") plus `pr_reviewer_ids` is the setting a Tread uses to let TANK merge its own agent's green PRs without a human; `read_neural_knowledge` (default on) is the matching toggle for whether a run touches this layer at all.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `optional` is used throughout as deliberate presence, not nullability: `ChannelReadState.unread_count`, `DecideBenchmarkRequest.supersedes_id` (topo.proto), `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo`/`search` import `tank.message.v1`; `admin` imports `tank.workspace.v1`/`tank.channel.v1`; `events.proto` now also imports `tank.board.v1` and `tank.canvas.v1` for the new realtime fan-out events (`BoardObjectsChanged`, `BoardPointer`, `CanvasBlockChanged`, `CanvasEditing`). A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless the file sets `option go_package` itself (now 9 files do — check with `grep -rl "option go_package" proto/` before assuming managed mode covers a new domain). Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — it already misses all five new domains.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
