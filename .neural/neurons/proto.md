# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now (5 added since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `proto/tank/board/v1/board.proto`: Neuralboards, an infinite board whose `Frame` can hold the *running application* (`Frame.app`) rather than a picture of one — that's the whole reason the type exists. `ObjectKind` covers frame/rect/ellipse/line/arrow/text/sticky/image/connector/draw. `BoardService` is the human-facing CRUD; the agent's own board actions (`ReadBoard`, `DrawOnBoard`, `ArrangeBoard`, `ListBoards`, plus `BoardResearch`) are RPCs on `agentctl.v1.RunnerService`, not here.
- `proto/tank/books/v1/books.proto`: Neuralbooks, double-entry bookkeeping surfaced as customers/invoices/payments/expenses/a cash summary. Amounts are integer cents. `Settings.stripe_secret_key` is write-only by convention (field 10) — set it to store, send empty to leave alone, read back only as `stripe_key_hint`'s last four chars; never round-trips the real key.
- `proto/tank/canvas/v1/canvas.proto`: Neuralcanvas, pages built from `Block`s (`BlockKind` incl. `DECISION`, `LIVE`, `MESSAGE`, `TABLE`). The file's own comment states its one design rule: a page cites what it was written from (threads, decisions, repos) so staleness is visible rather than silent — unlike a wiki.
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberately split pair: `security` is the control registry (judges — `ControlState`: MET/PARTLY/NOT_YET/NOT_APPLICABLE/UNKNOWN, read-only `SecurityService` except `Evaluate`), `remediation` is the fix engine (`RemediationService`: `SubmitFinding`→PR, `AUTO_APPLY` only for a short declared class list with a mandatory `undo`). Neither service has an RPC to do the other's job — the file comments call this out explicitly as "a system that can mark its own homework is not a security system."
- `proto/tank/agentctl/v1/agentctl.proto` grew from ~645 to 1045 lines this cycle, almost entirely `RunnerService` additions wiring the runner to the three new domains: `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `ReadCanvas/AskCanvas/WriteUpThread`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard`, plus `RecordFinding` (the remediation seam) and `PollInbox` (long-poll for steer/approval/answer/cancel, returns on `seq > after_seq` or after `wait_ms`). `ControlService.StartRunRequest.mode = "neural"` skips planning and works in `repo` regardless of the Tread's binding — this refresh is itself one such run.
- `proto/tank/events/v1/events.proto` and `proto/tank/realtime/v1/realtime.proto` grew matching pairs for live collaboration on canvas and boards: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` as events, mirrored by `CanvasEditingFrame`/`BoardPointerFrame` as client frames and new `Subscribe`/`Unsubscribe` fields (`canvas_ids`, `board_ids`) — a client only gets another person's edits on a page/board it has explicitly subscribed to. `BoardPointer.kind` is `"user" | "agent"` so the agent's own cursor renders distinctly.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/topo/v1/topo.proto` added `GetBriefingResponse.hours` (24 hourly `BriefingHour` message/run counts, for Home's day ring) and `.setup` (`BriefingSetup`: goal_set/github_connected/agent_summoned/someone_invited/avatar_set/done, for Home's first-week cards). It separates derived marks (always `MARK_STATUS_OPEN`, never stored) from stored ones with a real lifecycle; only stored marks ever produce a `TopoMarkUpdated` event.
- `proto/tank/agent/v1/agent.proto` added `TreadDeployment` plus `CreateTreadRepo` (generates a repo for a Tread from its template) and `SetTreadDeployment` (wake/sleep the Tread's app on TANK's cluster) on `AgentService`; `Run.deployment` is present once TANK made that Tread's repository.
- Cross-package imports are real and make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent` and `blocks`; `events` now imports `board` and `canvas` too. A field removed from any of those fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless the file sets one by hand (now 9 files do — see `root.md`), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and does not pick up new domains (see `root.md`) — all 5 domains added this cycle are missing from it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
