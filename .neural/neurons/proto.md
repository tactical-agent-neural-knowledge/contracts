# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, the biggest file now) is the runner ↔ control-plane contract: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`. It now also carries the thread-facing RPCs for Neuralbooks, Neuralcanvas and Neuralboards (`BooksSummary`/`BooksCreateInvoice`/`BooksReport`, `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` on `RunnerService`) — the agent acts as the workspace's own user through these, same checks as a person.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) closed a real gap: before 2026-10-07 the control plane evaluated `tools.gate.destructive_tool` patterns but never told the sandbox what they were, so "a deny list the runner cannot see denies nothing" — the gate could never actually open. Don't assume a policy field not on `PolicySummary` is enforced in-sandbox; it has to be read there.
- `ControlService` writes into Postgres schema `agent`, which is owned by the control plane; the messaging core (api) only has `USAGE`/`SELECT` there. `BindChannelRepo`/`UnbindChannelRepo`/`SetChannelRepoAccess`/`CreateGitHubConnectState`/`SetChannelAgentSettings`/`SetWorkspaceAgentPolicy` exist because api was previously issuing INSERT/DELETE against `agent.*` tables directly — only ever green because the CI test fixture grants itself DML the prod role doesn't have. The fix is these narrow RPCs, not a wider grant, and per `agentctl.proto`'s comment there will never be a generic "table + statement" RPC.
- `proto/tank/remediation/v1/remediation.proto` is the deliberate seam between judge and fixer: the messaging core's control registry (what's true/wrong) submits a `Finding` via `SubmitFinding`; only the agent control plane (GitHub App, sandboxes, gate engine) can act on it, and `SubmitFindingRequest.judge_principal` is refused if it equals the engine's own fix principal — "a system that can mark its own homework is not a security system." `Disposition` is `PROPOSE` (PR a human merges, the default) / `AUTO_APPLY` (declared narrow classes only, reversible, never lockout-capable) / `REFUSED` (a first-class outcome, not an error).
- `proto/tank/security/v1/security.proto`, Neuralsecurity Phase 0: "controls are the primitive, frameworks are views over them" — one `Control` registry, and a framework (SOC 2 today) is only a `FrameworkClause` mapping onto existing controls, never a second set of facts. `ControlState` has no optimistic default: `UNKNOWN` means the check is stale or never ran and must not report its last answer ("the silent failure mode of every security scanner"), and `NOT_APPLICABLE`/`PARTLY` both require a mandatory `reason`.
- `proto/tank/books/v1/books.proto` (Neuralbooks): amounts are integer cents, ids are Snowflake strings. `Invoice.share_url` is a credential, not a readable field — the token is stored as a hash, so a plain `GetInvoice` returns it empty; `GetInvoiceRequest.rotate=true` (admin only) mints a new link and kills the old one atomically, because "a rotation that leaves both working is not a rotation" and this product doesn't email invoices, so a lost link is a billing problem, not just a security one.
- `books.proto`'s `Settings.stripe_secret_key` is write-only by the same pattern as other secrets here: set it to store, send empty to leave alone, read back only as `stripe_key_hint` (last four chars).
- `proto/tank/canvas/v1/canvas.proto` (Neuralcanvas): a page's difference from a wiki is that it remembers what it was written from — `Canvas.sources` cites threads/decisions/repos/canvases with `Source.changed` flipping when the cited thing moves, and `Canvas.staleness` (0 current, 100 nothing it rests on still holds) is the same idea `board.proto` reuses for boards. `UpdateBlock` takes `base_rev` for per-block optimistic concurrency — a collision reports `conflict`+`theirs` on just that block, never throws away the writer's typing or the page.
- `proto/tank/board/v1/board.proto` (Neuralboards, 549 lines): `BoardObject.app` (`AppFrame`) is the product's point — a frame can hold the *running application* at a commit, not a screenshot, with `drawn_from_sha`/`moved_on`/`moved_note` telling a viewer when the app has moved on since the frame was drawn. `RequestChangeRequest` turns a click inside that running frame plus a sentence into a thread where the agent works — "the design and the code stop being two places."
- `board.proto`'s `ReportPreview`/`ReportBoardSource` are deliberately the same shape: a workspace's own CI tells TANK where it put a build, or what its DB schema / `infra/` looks like, with a short-lived token scoped to `board:preview` — TANK never holds a customer's DB connection string or reaches into their network. `PutObjects`/`ArrangeBoard`/`DrawOnBoard` all take `base_revs` (object id → last-seen rev) for the same per-object optimistic concurrency as canvas's `base_rev`; a mismatch comes back as `conflict_ids`/`conflicts`, never a silent overwrite.
- `proto/tank/agent/v1/agent.proto` gained Tread-hosting: `CreateTreadRepo` (TANK generates+binds a repo from a template, premium/admin only) and `SetTreadDeployment` (wake/sleep on TANK's own cluster) sit beside `SetUpRepoPreviews` (TANK opens a PR adding a reporting workflow to a repo the workspace *already* connected) — hosting your own vs. previewing your own are two different RPCs with different trust boundaries. `RepoConnection.premium`/`hosting_available`/`deployment` gate which path a client offers.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new files: `board.proto`/`canvas.proto` say "Neuralboards"/"Neuralcanvas" only in comments, never in a field or message name.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl.proto` now imports `board`, `books` and `canvas`; `events.proto` now imports `board` and `canvas` too (for `BoardObjectsChanged`/`CanvasBlockChanged` and friends). A field removed from `canvas.proto` or `board.proto` can now fail the breaking check in `agentctl.proto` and `events.proto` as well as any future importer.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
