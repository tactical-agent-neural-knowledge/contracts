# Neurons · proto

refreshed 2026-10-14 · 3b1cc8caafe7

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five new since 2026-10-03: `board`, `books`, `canvas`, `remediation`, `security`.
- `board`, `books`, `canvas` are the three new product surfaces (Neuralboards, Neuralbooks, Neuralcanvas), each with its own `agentctl.proto` RPCs so a run can act as the workspace's agent — `BooksCreateInvoice`, `WriteUpThread`, `DrawOnBoard`, etc — the same service a person uses from the page, with the same checks.
- `remediation` and `security` are two halves of Neuralsecurity kept deliberately apart: `security.proto`'s `SecurityService` is the control registry (judges, platform-wide, read-only apart from `Evaluate`), `remediation.proto`'s `RemediationService` is the fix engine (agent control plane, opens pull requests). "A system that can mark its own homework is not a security system" — neither has an RPC for the other's job, and `Remediation.forbidden_paths` blocks a run from touching the controls that judge it.
- `books`, `canvas`, `remediation`, `security` all carry an explicit `option go_package` (managed mode does not reach them); `board` does not and relies on `buf.gen.yaml`'s `go_package_prefix` like most domains — a new hand-written proto must pick one of these two paths deliberately, not by accident.
- `board.proto`'s point is `AppFrame`: a frame can hold the running application at a commit, not a screenshot of one. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pin) so a renderer that understands none of it still draws the board correctly.
- `canvas.proto`'s point is staleness as a first-class signal: `Canvas.staleness` / `Source.changed` exist because "nobody can tell what is still true" is every wiki's actual failure, not that writing is hard. `BLOCK_KIND_DECISION` feeds `ListDecisions`, the cross-page decision ledger — a superseded decision names its replacement rather than disappearing.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE`; `DISPOSITION_AUTO_APPLY` requires a declared `Class` with `reversible`, `undo`, and never `lockout_risk`. `SubmitFinding` is idempotent on `(finding_id, control_version)` so an hourly evaluation doesn't open a second set of pull requests.
- `security.proto`'s `ControlState` has no state meaning "probably fine, unmeasured" — that's `NOT_YET`, and a stale check reports `UNKNOWN` rather than its last answer. Controls are the only facts; a `FrameworkClause` (e.g. SOC 2) is a view over them, never a second set of facts.
- Cross-package imports keep growing: `events.proto` now imports `board` and `canvas` for their realtime events (`CanvasBlockChanged`, `BoardPointer`, …), and `agentctl.proto` imports `board`, `books`, `canvas`. FILE-level breaking (`buf.yaml`) means a field removed from any of these fails the breaking check everywhere they're referenced.
- `agent.proto`'s `TreadSettings` grew the merge-on-green controls: `pull_requests` ("review" default | "merge_when_green") and `pr_reviewer_ids`, plus `read_neural_knowledge`. `agentctl.proto`'s `PolicySummary.tools_gate_destructive` is the fix for a real gap: the destructive_tool gate patterns existed in policy and were evaluated by the control plane, but were never sent into the sandbox, so "the gate the policy promised could not open and the command simply ran."
- `agentctl.proto`'s newest block (bottom of the file) is the `agent` schema boundary: `BindChannelRepo`, `SetChannelRepoAccess`, `SetChannelAgentSettings`, etc. exist because the messaging core was issuing INSERT/DELETE directly against a schema it only has SELECT on — "the fix is a call, not a wider grant," and there is deliberately no generic table+statement RPC.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `buf breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
