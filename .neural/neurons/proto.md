# Neurons · proto

refreshed 2026-10-14 · 65c4439b3e7d

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- `tank.board.v1` (Neuralboards): an infinite board whose `Frame` (`ObjectKind.OBJECT_KIND_FRAME`) can hold the **running application**, not a screenshot — `AppFrame.preview_url`/`status`/`drawn_from_sha`/`moved_on` track whether what's shown still matches what's deployed. `PutObjectsRequest.base_revs` + `BoardObject.rev` give per-object optimistic concurrency (two people moving different shapes never collide); `RequestChangeRequest` turns a click on a rendered `Element` (with its source file/line) into a prompt posted to the Tread's thread. `ExportBoardRequest`/`BoardEmbedRequest` cover file export and public embed links; `GenerateTestRequest` turns a clicked-through `FlowStep` sequence into a Playwright/Maestro spec.
- `tank.books.v1` (Neuralbooks): double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary, amounts always integer cents. `Invoice.share_url` is **write-only on read**: the token is stored as a hash, so `GetInvoiceRequest.rotate` is the only way to mint a new one once the original is lost — admin only, and the old link dies the instant the new one is issued. `Settings.stripe_secret_key` is the same write-only-hint pattern (`stripe_key_hint` is the last four chars). `ImportBankTransactionsRequest`/`MatchBankTransactionRequest` reconcile a bank CSV against invoices/expenses with a `suggested_*`/`explanation` pair so a match always says why. `ReadReceiptRequest` is a receipt image/PDF read by the model into vendor/category/amount/confidence.
- `tank.canvas.v1` (Neuralcanvas): pages that know what they were written from. `Canvas.sources` (`Source.changed`/`changed_note`) and `Canvas.staleness` are the same "the product moved, the page didn't" idea as `Board.staleness` — both 0 = current, 100 = nothing it rested on still holds. `UpdateBlockRequest.base_rev` gives per-block (not per-page) optimistic concurrency. `DecisionRecord` is a workspace-wide ledger view over `BLOCK_KIND_DECISION` blocks, with `supersedes_block_id`/`superseded_by_*` letting "what did we decide about X" be a query instead of a search. `AskRequest`/`AskResponse.semantic` tells a caller whether the Vault understood the question (`matched: "words"|"meaning"|"both"`) or only keyword-matched it.
- `tank.security.v1` (Neuralsecurity Phase 0 — read-only posture): one rule governs the whole file — **controls are the primitive, frameworks are views over them**; a `FrameworkClause` (e.g. SOC 2 "CC6.1") only ever maps onto an existing `Control`, never adds a new fact. `ControlState` has no state for "probably fine, unmeasured" — that's `NOT_YET`; a stale check (older than `Control.max_age_seconds`) always reports `UNKNOWN`, never its last answer, because a scanner's silent failure mode is a broken check that stays green. `CheckKind.CHECK_KIND_NONE` can never produce `MET`. `SecurityService` is deliberately read-only apart from `Evaluate` (re-runs checks only) — nothing in this file can write a fix; see `tank.remediation.v1` for the half that does.
- `tank.remediation.v1` is the other half, and the split is deliberate: the control registry (`tank.security.v1`, in the messaging core) decides what's wrong and cannot run anything; the remediation engine (agent control plane: GitHub App, sandboxes, gate engine, flight recorder) is the only thing that can write code and cannot alter a control. `Remediation.judge_principal`/`fix_principal` are checked to differ — "a system that can mark its own homework is not a security system." `Disposition.DISPOSITION_AUTO_APPLY` requires a declared `Class` with `reversible=true` + `undo` set, `lockout_risk=false`, and a `gate_kind`; everything else is `DISPOSITION_PROPOSE` (a PR a human merges) by default. `SubmitFinding` is idempotent on `(finding_id, control_version)` — an hourly re-evaluation doesn't open a second PR. A `Target` fans one finding out across every repo the pattern applies to ("fix the class, not the instance"); `Remediation.forbidden_paths` blocks a remediation run from touching the controls/probes/mappings that judged it.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `TreadSettings` (agent.proto) grew three fields this cycle: `pull_requests` (`"review"` default vs `"merge_when_green"` — TANK watches checks and merges without a person) + `pr_reviewer_ids`; and `read_neural_knowledge` (on by default). These are the settings the PolicySummary-level "can this run auto-merge / skip the knowledge layer" questions resolve to.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) is new and closes a real gap: `tools.gate.destructive_tool` had been in every workspace's policy with nothing in the wire format to carry it to the runner, so the gate never opened — "an absent control, not a weak one." Additive; an old runner reading it empty behaves exactly as before.
- `ControlService` grew six narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) because the messaging core was issuing raw INSERT/DELETE against the control plane's own `agent` schema — statements that can't succeed from an `api` pod (granted USAGE+SELECT only) and were only ever green in CI, where the test fixture self-grants DML. The fix is deliberately a narrow call per need, not a wider grant: "widening the grant would make the control-plane separation imaginary."
- `AdminService.EndMemberSessions` (admin.proto) signs a member out without removing them — ends sessions only, never API/bot tokens (a bot token isn't the lost device); `sessions_ended` in the response so "it worked" and "there were none" (the common case) read differently.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` (most new domains, incl. board/canvas, set it explicitly anyway — books/remediation/security do too), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
