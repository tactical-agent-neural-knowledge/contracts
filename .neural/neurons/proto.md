# Neurons · proto
refreshed 2026-10-14 · 65c4439b3e7d

- 27 files, one proto package per domain at `proto/tank/<domain>/v1/*.proto`; `buf.yaml` lints `STANDARD` minus `PACKAGE_VERSION_SUFFIX`, so the package is `tank.<domain>.v1` with no extra suffix on the name itself.
- `tank.agentctl.v1` (`agentctl.proto`, 1045 lines, the biggest file) is the runner↔control-plane contract: the in-sandbox agent runner talks only to `RunnerService` here, never to the messaging core directly, authenticated by a per-run `RUN_TOKEN`. Its RPCs are the full surface of every `mcp__tank__*` tool (PostToThread, PostPlan, BoardResearch, BooksSummary/CreateInvoice/RecordExpense/RecordPayment, ReadBoard/DrawOnBoard/ArrangeBoard, OpenPullRequest, RequestCiWatch, GetCiFailure, RecordDecision/Remember, etc).
- `agentctl.proto`'s `PolicySummary` (line 52) is the subset of `policy.v1` the runner enforces locally — `mode` is `propose_only | can_merge`; `tools_gate_destructive` (field 9) was added 2026-10-07 and the comment is explicit that before it existed the control plane evaluated destructive-tool deny patterns but never told the sandbox, so the gate it promised silently never opened.
- `tank.agent.v1.TreadSettings` (`agent/v1/agent.proto:260`) is the per-Tread switchboard an admin edits: `concurrent_runs` (1..5), `auto_accept_plans`, `max_run_usd`/`daily_usd` (0 = inherit workspace default), `pull_requests` (`"review"` default vs `"merge_when_green"`), `pr_reviewer_ids`, `read_neural_knowledge`. Set via `agent.v1.SetTreadSettings` or mirrored through `agentctl.v1.SetChannelAgentSettings`; surfaced to a run as `PolicySummary.mode`.
- `tank.admin.v1` (449 lines) gained `EndMemberSessions` (admin.proto:429) alongside `DeactivateMember`/`RemoveMember` — it revokes sessions without changing membership state, so don't conflate "end sessions" with "deactivate."
- `tank.security.v1` and `tank.remediation.v1` are a judge/fix split, not one service: `security.proto` is the half that evaluates `Control`s against a `Posture` and reports `FrameworkCoverage`/`ClauseCoverage`; `remediation.proto` is the half that takes a `Finding`, classifies it (`Class`), and tracks a `Remediation` to `SubmitFinding`/`CancelRemediation` — a security finding without a matching remediation flow is an incomplete feature, not a smaller one.
- `tank.board.v1` (549 lines) is Neuralboards: shapes via `PutObjects`, diagram derivation via `DeriveDiagram` (`ReportBoardSource`/`ListBoardSources` feed it), reusable layout via `SaveBoardTemplate`, and three distinct output shapes from `ExportBoard` — raster, slice (`ListBoardSlices`), and embed link (`BoardEmbed`) — these are not variants of one RPC.
- `tank.books.v1`, `tank.canvas.v1`, `tank.board.v1` are all imported into `agentctl.proto` because the runner's MCP tool surface (books_*, canvas, board tools) is typed directly against the product domain protos, not against a separate runner-only shadow schema — changing one of those three breaks the corresponding `mcp__tank__*` tool shape too.
- `tank.events.v1` is the bus envelope (not a service): one `EventEnvelope` wrapping a oneof of payloads like `MemberRoleChanged`, `MemberDeactivated`, `WorkspaceSettingsUpdated`, `AuditLogged`, `ExportReady` — adding a new async side effect anywhere else in the schema usually means adding a payload here too.
- `tank.realtime.v1` is the gateway WebSocket framing (`ClientFrame`/`ServerFrame` with `Resume` cursors), distinct from `tank.events.v1`'s bus envelope — realtime is the transport, events is the content that flows over both realtime and the bus.
- Breaking-change safety is enforced at `FILE` granularity (`buf.yaml`): `buf breaking --against '.git#branch=main'` (CI only runs it on PRs, via `make breaking` locally) catches a wire break at the source, which is the thing that makes shipping this as a polyrepo (not a monorepo) safe for web/mobile/agent-runner.
