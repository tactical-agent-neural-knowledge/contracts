# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New this refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- 9 files now carry an explicit `option go_package` rather than relying on managed mode: billing, **books**, **canvas**, catalog, monitor, platform, **remediation**, **security**, topo (the three bolded are new this refresh, alongside books/canvas which also added one). A hand-written prefix must match managed mode's `github.com/.../contracts/gen/go/tank/<domain>/v1;<domain>v1` exactly.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board where a `Frame` (`ObjectKind.OBJECT_KIND_FRAME`) can hold the running application via `AppFrame`, not a picture of one. `PutObjectsRequest.base_revs` does optimistic concurrency per-object (one shape moved ≠ a conflict); a mismatch comes back in `PutObjectsResponse.conflicts`, nothing is silently overwritten.
- `board.proto`'s `RequestChangeRequest` is the product's hinge: a click inside a running `AppFrame` carries an `Element.source` (`"src/features/shell/Logo.tsx:8:5"`, stamped by the preview build) and an `ask`, and the response is a thread in the board's own Tread where the agent posts its plan.
- `board.proto` never has TANK read a customer's database or repo directly: `ReportBoardSource`/`ReportPreview` are the workspace's own CI telling TANK what it already knows (schema, infra files, build URL), the same shape for both, deliberately — see the comment at `ReportBoardSourceRequest`. `Derivation`/`AppFrame.drawn_from_sha` let a board tell when the thing it was drawn from has moved on (`moved_on`/`moved_note`).
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary, amounts always integer cents. `Settings.stripe_secret_key` is write-only (set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — never round-trips the real key.
- `Invoice.share_url` (page a customer opens with no account) and `Invoice.pay_url` (Stripe, minted on send once the workspace has `payments_ready`) are distinct: a share link can exist without payments being configured.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite what they were written from (`Source`, `Canvas.sources`) and go stale when those move — "the failure of every wiki is... nobody can tell what is still true" (file header). `BlockKind.BLOCK_KIND_DECISION` and `BLOCK_KIND_LIVE` are the two kinds that aren't plain text: a decision and a figure read live when the page is read.
- `proto/tank/remediation/v1/remediation.proto` is the deliberate seam between the control registry (messaging core, judges) and the remediation engine (agent control plane, fixes) — "a system that can mark its own homework is not a security system." `Disposition.DISPOSITION_AUTO_APPLY` is narrow by design: only a declared, reversible `Class` with its own reverse is eligible, never anything that can lock an operator out.
- `proto/tank/security/v1/security.proto` is Neuralsecurity Phase 0: "controls are the primitive, frameworks are views over them" — one `Control` registry, a `FrameworkClause` only maps onto it, never adds a second set of facts. `ControlState.CONTROL_STATE_UNKNOWN` is mandatory for a stale check — it must not keep reporting its last answer.
- `proto/tank/agentctl/v1/agentctl.proto` grew the runner↔control-plane surface for every new product area from the agent's side: `BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`, `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` — each a thin, pre-authorized slice of the full service for an agent acting as the workspace.
- Trap fixed this refresh, read the comment at `PolicySummary.tools_gate_destructive` (agentctl.proto) in full: the destructive-tool deny list existed in policy and was evaluated by the control plane, but was never sent into the sandbox, so "the gate the policy promised could not open and the command simply ran" until 2026-10-07. A policy field with no matching runner field enforces nothing.
- `ControlService.RefreshNeuralKnowledge` / `StartRunRequest.mode = "neural"` / `skip_neural_knowledge` (on both `StartRunRequest` and `RunContext`) are the mechanism behind this very refresh process: one standing thread per repository, idempotent while a refresh is already running, and `skip_neural_knowledge` exists so the same task can be measured with and without the layer.
- `events.proto` and `realtime.proto` both grew matching pairs for the two new live surfaces: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`, mirrored by `Subscribe.canvas_ids`/`board_ids` and `ClientFrame.canvas_editing`/`board_pointer`. Pointer and editing-presence frames are explicitly never stored.
- Cross-package imports keep growing and still make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas`; `events` imports `board` and `canvas`. A field removed from any of those fails the breaking check anywhere it's referenced.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
