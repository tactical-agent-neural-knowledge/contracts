# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 27 domains now (was 22 at the last refresh): `board`, `books`, `canvas`, `remediation`, `security` are new. Each is still one package, always `proto/tank/<domain>/v1/<domain>.proto`, package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/security/v1/security.proto` and `proto/tank/remediation/v1/remediation.proto` are a deliberate split, not a layering accident: security owns the facts (`Control`, `ControlState` — MET/PARTLY/NOT_YET/N_A, never flattering: "a control nobody can evidence is NOT_YET even when everyone is fairly sure it holds"), remediation owns the fixing (`SubmitFinding` → a PR, propose-only by default). The registry cannot run anything and the engine cannot touch a control — "a system that can mark its own homework is not a security system" (remediation.proto header).
- `proto/tank/books/v1/books.proto`: amounts are integer cents, ids are Snowflake strings. `Invoice.share_url` is a write-once credential, not a readable field — `GetInvoiceRequest.rotate` mints a new link and kills the old one atomically ("a rotation that leaves both working is not a rotation"); there is no RPC to read back an existing share link.
- `proto/tank/board/v1/board.proto`: `AppFrame` is what makes this canvas different — a frame can hold the running application, not a picture of one. `drawn_from_sha` + `moved_on`/`moved_note` is how a board learns its own frame went stale against a later deploy. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pinning) so a renderer that doesn't understand it still draws the board correctly.
- `proto/tank/canvas/v1/canvas.proto`: the point is in the header — "what separates a canvas from a document is that it remembers what it was written from." Pages cite threads/decisions/repos and say so when those move; `WriteFromThread` and `Ask` are the two agent-facing entry points.
- `proto/tank/admin/v1/admin.proto`: `EndMemberSessions` (added this refresh) signs a member out without touching their membership or their bot/API tokens — distinct from `RemoveMember`, which only ends sessions as a side effect of taking the last membership. `EndMemberSessionsResponse.sessions_ended` exists so "it worked" and "there were none" (the common case) read differently.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, comments disagree: `Channel.last_seq` still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` documents why that's wrong (thread replies and deletes also consume a `channel_seq`). Use `unread_count`; it's `optional` so a client can tell "server said zero" from "older server said nothing."
- `optional` means deliberate presence throughout, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), empty-vs-unconfigured in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes its meaning.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only — never the messaging core. Schema `agent` belongs to the control plane (USAGE+SELECT grant to the app role); six RPCs added this refresh (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) exist because the messaging core was issuing writes the real grant can't do and CI's fixture masked it by granting itself DML. `StartRunRequest.mode = "neural"` skips planning and works in `repo` whatever the Tread is bound to.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`. `AuditLogged` is internal — the gateway never fans it to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default. `Event.cursor` is the JetStream sequence a client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview`, plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not an RPC.
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that only reference it.
- Adding a domain needs a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (managed mode supplies `go_package`, lint's `PACKAGE_VERSION_SUFFIX` exemption already covers it) — but remember `gen/ts/src/index.ts` is hand-written and will not pick it up; 13 of 27 domains are already missing from it.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
