# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five domains landed this cycle: `board`, `books`, `canvas`, `remediation`, `security` (up from 22 at the last refresh). Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A board is similarly wire-neutral: `tank.board.v1` never says Neuralboards, `tank.books.v1` never says Neuralbooks — the product names live only in comments and in the clients.
- `proto/tank/agentctl/v1/agentctl.proto` grew a whole tool surface this cycle: `BooksSummary/BooksCreateInvoice/BooksRecordExpense/BooksRecordPayment/BooksReport`, `WriteUpThread/ReadCanvas/AskCanvas`, and `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` on `AgentctlService` — these are the exact calls an in-sandbox agent's Neuralbooks/Neuralcanvas/Neuralboards tools make; there is no separate "tool protocol", it is this RPC set.
- `PolicySummary.tools_gate_destructive = 9` (agentctl.proto) closed a real gap: the field was absent until 2026-10-07, so a workspace's `tools.gate.destructive_tool` patterns were evaluated by the control plane but never told to the sandboxed runner — "a deny list the runner cannot see denies nothing" (the proto's own comment). Any new policy field meant to constrain the runner must round-trip through `PolicySummary`/`RunContext`, not just exist in the policy document.
- `StartRunRequest.mode` (agentctl.proto) is `""` for an ordinary run or `"neural"` for a Neural Knowledge refresh, which skips the planning phase and works in `repo` regardless of what the Tread is bound to — this is the mode every refresh of this repository's own layer runs under.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Collision handling repeats across the new domains as one pattern, not three: `board.proto` `PutObjectsRequest.base_revs` (per-object), `canvas.proto` `UpdateBlockRequest.base_rev` (per-block) and `UpdateCanvasRequest.base_version` (per-page) all refuse-and-return-theirs on a stale write rather than overwriting; `BoardObject.rev` / `Block.rev` are the counters a client must echo back.
- `proto/tank/books/v1/books.proto` keeps money as integer cents and never stores a readable secret: `Settings.stripe_secret_key` is write-only (read back only as `stripe_key_hint`'s last four chars), and `Invoice.share_url`/`GetInvoiceRequest.rotate` work the same way — the token is stored hashed, exists once, and a lost link is recovered only by admin-only rotation that kills the old one.
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are deliberately split across two services with no RPC that lets one do the other's job: the security registry (judge) states `Control`/`Finding`, and the remediation engine (fixer) only ever proposes a pull request (`DISPOSITION_PROPOSE`) unless a fix class is explicitly declared `AUTO_APPLY` with a mandatory `test_requirement`, `reversible`/`undo`, and never when `lockout_risk` is true.
- `proto/tank/board/v1/board.proto`'s `AppFrame`/`Derivation` are the same idea twice: a frame can hold the *running app* at a commit (`drawn_from_sha`, `moved_on`) or a *diagram derived* from a reported schema/repo (`ReportBoardSource` → `DeriveDiagram`), and both are re-derivable because the source records what it was drawn from rather than TANK polling anybody's infrastructure.
- Real-time fan-out for the two new editors is in `events.proto`/`realtime.proto`: persisted `CanvasBlockChanged`/`BoardObjectsChanged` carry the single block/objects that changed (not the whole page/board), while `CanvasEditing`/`BoardPointer` are ephemeral presence (typing-indicator subjects, rate-limited, never stored) — `BoardPointer.kind` distinguishes a person's cursor from the agent's.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, plus the new `.canvas.{canvas}` and `.board.{board}`. `AuditLogged` is internal — the gateway never fans it out to clients.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, and `agentctl`/`events` now import `tank.board.v1`, `tank.books.v1` and `tank.canvas.v1`. A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — it is now missing 13 of 27 domains, not 8.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
