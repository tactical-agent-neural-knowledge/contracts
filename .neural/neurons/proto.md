# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five joined this refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel."
- `proto/tank/security/v1/security.proto` (Neuralsecurity Phase 0): "Controls are the primitive; frameworks are views over them" — one set of facts (`Control`, each with an owner/check/evidence query), a framework like SOC 2 is a `FrameworkClause` mapping onto controls, never a second set of facts. `ControlStatus` has four honest states plus two the machinery forces: a check that has not run recently reports `UNKNOWN`, never its last answer — "the silent failure mode of every security scanner is a broken check that stays green."
- `proto/tank/remediation/v1/remediation.proto` is the seam between the half that judges and the half that fixes, and the seam is deliberate: the control registry (messaging core) submits a `Finding` and can run nothing; the remediation engine (agent control plane) holds the GitHub App and sandboxes and cannot form an opinion on whether a finding is real. Four rules: propose-only by default (`AUTO_APPLY` classes are short, declared, readable); a fix ships with the regression test it is checked against; a finding fans out to every repo the check applies to, recorded; every remediation names the run that drove it.
- `proto/tank/board/v1/board.proto` (Neuralboards): `AppFrame` can hold the running application itself, not a screenshot — `drawn_from_sha` plus a 0-100 staleness score is how a board learns the product moved past what it shows. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, layout, pin) so a renderer that doesn't understand a record still draws geometry and colour correctly.
- `proto/tank/canvas/v1/canvas.proto` (Neuralcanvas): a page cites the threads/decisions/repos it was written from and carries the same 0-100 staleness score + `moved_reason` as board — "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true." Editing is per-block with `base_rev` optimistic concurrency, so two people writing different paragraphs both succeed; a collision returns `theirs` rather than overwriting it.
- `proto/tank/books/v1/books.proto`: double-entry bookkeeping, surfaced as customers/invoices/payments/expenses/cash summary, amounts always integer cents. `Invoice`'s share-link token is stored as a hash — `share_url` is only readable once, at creation or send, never again by anyone including TANK; rotating mints a new link and kills the old one in the same call (admin only).
- `proto/tank/admin/v1/admin.proto` gained `EndMemberSessions` this refresh (additive, `buf breaking` clean): ends every session a member holds and nothing else — not API/bot tokens — distinct from `RemoveMember`, which only ends sessions once removal takes the person's last membership.
- `proto/tank/agent/v1/agent.proto`'s `TreadSettings` gained `pull_requests` ("review" default, posts + mentions `pr_reviewer_ids`; "merge_when_green", TANK watches checks and merges) and `read_neural_knowledge`, plus `SetUpRepoPreviews`/`CreateTreadRepo`/`SetTreadDeployment` for premium-workspace hosting — TANK opens a pull request in a workspace's own repository, it never pushes to one directly.
- `proto/tank/agentctl/v1/agentctl.proto`'s `PolicySummary` gained `tools_gate_destructive` on 2026-10-07: before that field existed, the destructive_tool gate patterns lived in every workspace's policy and the control plane evaluated them, but nothing inside the sandbox was ever told — "a deny list the runner cannot see denies nothing." Any new policy field meant to constrain the runner must actually be wired into `PolicySummary`, or it constrains nothing.
- `agentctl.proto` is also where this run's own tool surface is specified: `BooksSummaryRequest`, `ReadBoardRequest`/`BoardShape`, `WriteUpThreadRequest`/`AskCanvasRequest` and friends are messages on this one file, added this refresh so the runner ↔ control-plane contract could carry boards/books/canvas. `StartRunRequest.mode = "neural"` (the mode this very refresh runs under) skips planning and works in whatever repo the Tread is bound to.
- `events.proto` and `realtime.proto` grew matching per-block/per-object live-collaboration frames for the two new editable surfaces: `CanvasBlockChanged`/`BoardObjectsChanged` carry just the changed piece (not the whole page/board), and `BoardPointer.kind` is `"user" | "agent"` so an agent's cursor draws as its own thing. Both files now import `tank/board/v1/board.proto` and `tank/canvas/v1/canvas.proto`, so FILE-level breaking on those two files now also gates `events.proto` and `realtime.proto`.
- `README.md`'s consumer table was not updated in this round of proto changes and lists only 12 of the 27 packages (board, books, canvas, remediation, security, admin are all absent from it) — do not treat it as an index of what exists, only `proto/` is.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
