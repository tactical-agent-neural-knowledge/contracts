# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage. Five domains are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board (`BoardObject`, `ObjectKind` rect/ellipse/sticky/connector/draw/frame). Its one distinctive idea is `AppFrame`: a frame can hold the *running application*, not a screenshot. `PutObjects` writes one object at a time (two people moving different shapes don't conflict); `RequestChange` asks for a change to something clicked inside a running frame via `Element`, which is why preview builds stamp elements with their source origin. `BoardService.ReportPreview`/`ReportBoardSource` let a workspace's own CI tell TANK where a build or a schema already lives — TANK deliberately never holds a database connection string or reaches into anyone's network (`board.proto:452-462`). `DeriveDiagram` draws an ERD/architecture diagram from a reported source and records a `Derivation` so a diagram can say when its source has `moved_on`.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary, integer cents throughout. `Invoice.share_url` (books.proto:86) is a one-time-mint credential — the token is stored as a hash server-side, an ordinary `GetInvoice` returns it empty, and `GetInvoiceRequest.rotate` (books.proto:152-164, added this refresh) mints a new link and kills the old one atomically. There is deliberately no way to read an old share link back, by design, even for TANK itself.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite what they were written from (`Source`), so a page can say when a cited thread/decision/repo has moved instead of quietly going stale. `Live` blocks are filled in server-side at read time (never stale about their own data). `UpdateBlockRequest` edits one block without touching the rest of the page — concurrent editors in different blocks both succeed. `Decision` blocks feed a workspace-wide ledger (`ListDecisionsRequest`) answerable by what/who/when/why/superseded-by.
- `proto/tank/security/v1/security.proto` is Neuralsecurity Phase 0: "controls are the primitive, frameworks are views over them" (security.proto:14-16) — one `Control` registry, a framework (SOC 2 today) is a `FrameworkClause` crosswalk onto existing controls, never a second set of facts. `ControlState` has no room to flatter: `NOT_YET` beats a guess, and `UNKNOWN` is mandatory once an evaluation goes stale (`max_age_seconds`) — a stale check must not keep reporting its last answer. `SecurityService` is read-only except `Evaluate`, which only re-runs checks; nothing here can mark its own homework.
- `proto/tank/remediation/v1/remediation.proto` is the seam between the control registry (judges) and the agent control plane (fixes) — deliberately two different programs. `SubmitFinding` is idempotent on `(finding_id, control_version)`. Default `Disposition` is `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with a mandatory `test_requirement`, `reversible` + `undo`, and is forbidden outright when `Class.lockout_risk` is true. `Remediation.forbidden_paths` blocks a run from touching the very controls/probes that judge it — separation of powers as a field, not a promise. There is no RPC here that lets the engine change a control, retire a probe, or mark a finding resolved; the registry polls `ListRemediations` instead.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract, now importing `board`, `books` and `canvas` directly: `RunnerService` grew wrapper RPCs (`BooksSummary`, `BooksCreateInvoice`, `BooksRecordExpense`, `BooksRecordPayment`, `BooksReport`, `WriteUpThread`, `ReadCanvas`, `AskCanvas`, `ListBoards`, `ReadBoard`, `DrawOnBoard`, `ArrangeBoard`) so an in-sandbox run can act on these three services with the same checks a person gets from the page. `RunPhase` drives the runner's permission mode, and `StartRunRequest.mode = "neural"` skips planning and works in `repo` whatever the Tread is bound to — this is literally the mode this refresh is running under.
- `PolicySummary.tools_gate_destructive` (agentctl.proto:61-67) is new and the comment names its own prior bug plainly: the field was absent until 2026-10-07, so `policy.v1`'s `destructive_tool` deny patterns existed in every workspace's policy and were evaluated by the control plane, but nothing inside a sandbox was ever told them — "a deny list the runner cannot see denies nothing." Any change to the destructive-tool gate must keep this field populated or the gate is decorative again.
- `agentctl.proto:935-954` ("the agent schema's own writes") documents a real production bug and its fix: the messaging core was issuing INSERT/DELETE directly against `agent.*` tables it only has `USAGE`+`SELECT` on — green only in CI, where the test fixture grants itself DML. The fix is a set of narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) on `ControlService`, not a wider grant — "there is no RPC that takes a table and a statement, and there will not be one." A hand-rolled write to the `agent` schema from outside agent-control is the bug this boundary exists to prevent.
- `proto/tank/agent/v1/agent.proto` added hosting/deployment and preview plumbing this refresh: `TreadDeployment` (agent.proto:322-331) is a Tread's app on TANK's own cluster (`<slug>.tank.chat`, `managed` vs. brought-your-own repo, `awake` sleep/wake); `CreateTreadRepo`/`SetTreadDeployment` are premium-only, admin-only. `SetUpRepoPreviews` opens a *pull request* (never a push) adding a CI workflow to repositories the workspace already connected, and returns a one-time `token` that is never readable again — losing it means `rotate_token`, the same credential-rotation shape as the books share link. `TreadSettings.pull_requests` ("review" vs `"merge_when_green"`) and `.read_neural_knowledge` are new per-Tread switches.
- `proto/tank/events/v1/events.proto` grew two live-collaboration families this refresh, mirroring the board/canvas pattern already used for messages: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`. Both pairs separate a durable "what changed" event from an ephemeral `typ.{ws}.<kind>.{id}` presence stream that is never stored — `BoardPointer.kind` ("user"|"agent") is what lets an agent's cursor render distinctly from a person's while both are live on the same board.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (719 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`; `admin` imports `tank.workspace.v1` and `tank.channel.v1`; `agentctl` now imports `board`, `books` and `canvas`; `events` now imports `board` and `canvas` too. A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml` (board, books, canvas, remediation and security all landed this way). Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
