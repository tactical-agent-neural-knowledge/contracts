# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now (was 22): board, books, canvas, remediation and security are new since the last refresh, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `remediation.proto` and `security.proto` are a deliberate split, not two halves of one feature: `security` (the control registry) decides what is true about the system and cannot run anything; `remediation` (the agent control plane) holds the GitHub App and sandboxes and is the only thing that can write code. "A system that can mark its own homework is not a security system" — a `Finding` crosses from security into remediation but nothing crosses back.
- `remediation.proto`'s four rules, stated in the file header: propose-only by default (`Disposition.AUTO_APPLY` needs a declared, reversible, narrow `Class`, never anything that can lock an operator out); every remediation carries its regression test as a requirement, not a suggestion; a finding fans out to every repo/workspace the same `Class` applies to, recorded per-target; everything is logged against the run that drove it.
- `security.proto`'s one rule: "Controls are the primitive; frameworks are views over them" — one set of `Control` facts, a `FrameworkClause` only maps onto them, SOC 2 today and seven more frameworks later never add a second set of facts. A control with `CheckKind.NONE` can only ever be `NOT_YET` or `UNKNOWN`, never `MET` — nothing is watching it. `Evidence.stale` (age over the control's max_age) always forces `ControlState.UNKNOWN`, never the last good answer — "a registry that flatters the system is worse than no registry".
- `board.proto`'s `Frame` (`AppFrame`) can hold the *running application*, not a picture of one — `preview_url`/`status` are server-filled once `BoardService.ReportPreview` (or a workspace's own CI via `ReportBoardSource`) tells TANK where a build landed. This is the one board feature that makes it more than FigJam/Lucidspark.
- `agent.proto`'s `SetUpRepoPreviews` is the other half of that: for a workspace's *own* repos, TANK opens a pull request adding the CI workflow (never pushes directly — "a workflow file in somebody else's repository is their decision") and returns a one-time-readable token; `rotate_token` is the only way back from losing it.
- `books.proto`: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary. Amounts are integer cents. `Settings.stripe_secret_key` is write-only — set it to store it, send empty to leave it, read back only `stripe_key_hint` (last 4 chars) — the same write-only-plus-hint pattern as nowhere else in this repo.
- `canvas.proto`'s whole premise is in its header comment: "what separates a canvas from a document is that it remembers what it was written from" — every `Canvas` carries `sources` (`Source.kind` = thread|decision|repo|canvas) and a `staleness` 0-100 score with a `staleness_note` sentence; `BLOCK_KIND_LIVE` blocks render a real figure read fresh each time, `BLOCK_KIND_DECISION` blocks are answerable (what/who/when/why/supersedes), not prose.
- `agentctl.proto` (1045 lines, the largest file) is the runner↔control-plane contract: `RunnerService` (per-run `RUN_TOKEN`) now carries tool RPCs for all five new domains — `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` — gated by `RunContext.product_run` the same way `commit_files`/`set_brand`/`set_landing`/`record_finding` were.
- `StartRunRequest.mode` (agentctl.proto:707): `""` for an ordinary run, `"neural"` for a Neural Knowledge refresh — skips the planning phase and works in `repo` regardless of what the Tread is bound to. `RunPhase` itself only enumerates PLANNING/IMPLEMENTING; "neural" lives in the string `mode` field, not in that enum.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9) has a comment dated 2026-10-07 calling out its own history: the destructive-tool deny patterns existed in every workspace's policy and were evaluated by the control plane, but were never sent into the sandbox before this field — "a deny list the runner cannot see denies nothing".
- `agent.proto`'s `TreadSettings.pull_requests` (`"review"` default vs `"merge_when_green"`) and `pr_reviewer_ids` are the setting for unattended merges; `read_neural_knowledge` (default on, server always sets it) and `StartRunRequest.skip_neural_knowledge` / `RunContext.skip_neural_knowledge` exist specifically to A/B a run with and without this very knowledge layer.
- Unread-count trap, unchanged: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong. Use `unread_count`.
- `optional` is still deliberate presence throughout, not nullability — dropping it to tidy a field silently changes meaning (`UpdateChannelRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`).
- Cross-package imports now also run through the new domains: `agentctl` imports `agent`, `blocks`, `board`, `books`, `canvas`; `events` imports `board` and `canvas` in addition to `admin`/`agent`/`blocks`/`channel`/`files`/`huddle`. `breaking.use: [FILE]` means a field removed from any imported file fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
