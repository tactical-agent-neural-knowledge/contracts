# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` — all absent from `README.md`'s table and from the `gen/ts/src/index.ts` barrel (see root.md). `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/remediation/v1/remediation.proto` is the seam between the control registry (messaging core, decides what's wrong) and the remediation engine (control plane, the only thing that can write code) — Neuralsecurity §2.3. No RPC here changes a control or marks a finding resolved; the engine refuses a remediation whose judge and fix principals are the same. `Disposition` defaults to propose-only (a PR a human merges); `AUTO_APPLY` is a declared, narrow `Class` with a reverse and a gate, and the lockout-risk flag forbids it outright.
- `proto/tank/security/v1/security.proto` (Neuralsecurity Phase 0): "Controls are the primitive, frameworks are views over them" — one set of facts (`Control`, each with owner/check/evidence query), a `FrameworkClause` maps SOC-2-etc onto them, never a second set of facts. `ControlState` is deliberately allowed to be bad: `NOT_YET` even when everyone's sure it holds without evidence, `UNKNOWN` when a check hasn't run recently rather than reporting its last answer.
- `proto/tank/board/v1/board.proto` (Neuralboards) is the largest new file (549 lines): an infinite board where `AppFrame` can hold the *running* application, not a picture of one. Also carries board templates (`SaveBoardTemplateRequest`), exports as raster/slice/embed (`ExportBoardResponse`), `RequestChangeRequest` (ask for a change to something inside a running frame), `DeriveDiagramRequest` (a diagram derived from real schema/infra, not drawn freehand), and `ReportBoardSourceRequest` (a workspace's own CI tells TANK where its build is).
- `proto/tank/canvas/v1/canvas.proto` (Neuralcanvas): what separates it from a wiki is `Source` / `Decision` — a page cites the threads, decisions and repos it was written from, and says so when those move instead of quietly going stale. `WriteFromThreadRequest` turns a thread into a page; `AskRequest`/`AskResponse` answers a question by citing which page answered it.
- `proto/tank/books/v1/books.proto` (Neuralbooks): double-entry underneath, integer cents, Snowflake-string ids. `Invoice.share_url` (books.proto:22) is a page a customer opens without an account; as of `a887d51` the underlying share token is stored as a *hash* so an ordinary read returns it empty — `GetInvoiceRequest.rotate` (books.proto:155) mints a new link and kills the old one atomically, because a rotation that leaves both working is not a rotation, and TANK doesn't email invoices yet so losing the link is otherwise unrecoverable.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `tank.agent.v1.TreadSettings` (agent.proto:260) is the one message every per-Tread agent policy flows through: `auto_accept_plans`, `max_run_usd`/`daily_usd` ceilings, `pull_requests` ("review" default vs "merge_when_green" — TANK watches checks and merges itself) with `pr_reviewer_ids`, and `read_neural_knowledge` (on by default, server always sets it).
- `proto/tank/agentctl/v1/agentctl.proto` is now 1045 lines, by far the biggest file, and is the runner ↔ control-plane contract plus (as of `a297744`) six `ControlService` RPCs the messaging core calls instead of writing schema `agent` directly: `BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`. The application DB role only has USAGE+SELECT on schema `agent`; these calls are the boundary on purpose and there is deliberately no generic "table + statement" RPC.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`/`SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest long-standing file (721 lines); `GetBootstrap` is its point — one call on app open, everything else lazy. `HomeLayout.setup_hidden` (workspace.proto:264) and `DescribeHomeLayoutRequest` (a natural-language ask like "agents first, hide people" → a layout to review, nothing saved) live here too.
- `proto/tank/admin/v1/admin.proto` grew `EndMemberSessions` (`e52a377`, additive): ends every session a member holds without touching their membership or any bot/API token, for "laptop went missing" as distinct from "person left". `EndMemberSessionsResponse.sessions_ended` is a count on purpose, so "it worked" and "there were none" (the common case) read differently.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `agentctl` imports `tank.agent.v1` (for `TreadSettings`). A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up (13 of 27 domains are missing from it right now).
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
