# Neurons · proto

refreshed 2026-10-07 · 77435ec229ee

- 25 domains now (board, books and canvas are new this refresh, up from 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." The new `board.proto` and `agentctl.proto` keep the same split: fields are `channel_id` throughout, comments say "Tread".
- `proto/tank/board/v1/board.proto` (new, 549 lines) is Neuralboards: an infinite board where `BoardObject.app` (`AppFrame`) can hold the *running application* instead of a picture of one — `preview_url`/`status`/`moved_on` are server-filled, and `drawn_from_sha` vs. the live commit is how a frame learns it has gone stale. `PutObjectsRequest.base_revs` + `BoardObject.rev` is optimistic concurrency per-object: a mismatch comes back in `conflicts`, nothing is silently overwritten.
- `board.proto`'s `Derivation`/`DeriveDiagramRequest` is the ERD/architecture-diagram mechanism: a workspace's own CI calls `ReportBoardSource` (schema or `infra/` files) because TANK deliberately never holds a database credential, then `DeriveDiagram` draws a `Board` from that report and stamps `drawn_from_sha` so the frame can say `moved_on` later.
- `agentctl.proto`'s `ListBoardsRequest`/`BoardListing`/`ReadBoardRequest` are distinct message types from `board.proto`'s same-named `ListBoardsRequest`/`BoardSummary`/`GetBoardRequest` — different packages (`tank.agentctl.v1` vs `tank.board.v1`) so it compiles, but matching names with different shapes (`BoardListing` has no `staleness`; `BoardSummary` does) is a trap when grepping across the two files.
- `proto/tank/books/v1/books.proto` (new, 333 lines) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses, amounts always integer cents. `Settings.stripe_secret_key` is write-only by convention (comment, not enforced by the type): set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars.
- `proto/tank/canvas/v1/canvas.proto` (new, 302 lines) is Neuralcanvas: pages built of typed `Block`s (`BLOCK_KIND_DECISION`, `BLOCK_KIND_LIVE`, `BLOCK_KIND_MESSAGE`...). `Live` blocks are "the real number, not a screenshot" — server-fills `value`/`detail`/`as_of` on every read, so a page can't go stale about its own data the way prose can.
- `agentctl.proto` is still the runner ↔ control-plane contract only (never the messaging core directly, `RUN_TOKEN` auth, Snowflake decimal-string ids), but this refresh roughly doubled it (+240 lines): `RunnerService` now carries board tools (`BoardResearch`, `CommitFiles`, `SetBrand`, `SetLanding`, `RecordFinding`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`), Neuralbooks tools (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`), Neuralcanvas tools (`WriteUpThread`/`ReadCanvas`/`AskCanvas`), GitHub tools (`OpenPullRequest`/`RequestCiWatch`/`GetCiFailure`), knowledge tools (`RecordDecision`/`Remember`), a full `SessionStorePut/List/ListSessions/ListSubkeys/Delete` surface mirroring the Claude Agent SDK SessionStore contract, and `PollInbox` (long-poll for steer/approval/answer/cancel).
- `ControlService` in `agentctl.proto` is the separate operator surface (service-token auth, not `RUN_TOKEN`) — `StartRunRequest.mode = "neural"` skips planning and works in `repo` regardless of the Tread's binding, used by `RefreshNeuralKnowledgeRequest` (this very refresh mechanism) which keeps one standing thread per repository and is idempotent while a refresh is already running.
- `RunContext.product_run` / `RunContext.skip_neural_knowledge` gate two things per run: whether board-only tools (`commit_files`, `set_brand`, `set_landing`, `record_finding`, `board_research`) are exposed at all, and whether this run reads/writes `.neural/` — the latter also used to run a measurement pair (same task, with and without the layer).
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto).
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists. This refresh only added `HomeLayout.setup_hidden` (the first-week setup cards).
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws` — and now also `evt.{ws}.canvas.{canvas}` (`CanvasBlockChanged`/`CanvasChanged`) and `evt.{ws}.board.{board}` (`BoardObjectsChanged`/`BoardChanged`), each applying just the changed block/objects rather than a whole-document reload. `CanvasEditing`/`BoardPointer` are the ephemeral (`typ.*`) presence-style events, never stored; `BoardPointer.kind` distinguishes "user" from "agent" so the agent's own cursor renders.
- `proto/tank/realtime/v1/realtime.proto` (gateway, binary protobuf by default, `?enc=json` for debugging) grew matching plumbing: `Subscribe`/`Unsubscribe` now take `canvas_ids`/`board_ids` alongside channels and threads — a client that never subscribes never gets another person's edit — and `ClientFrame`/`ServerFrame` gained `canvas_editing`/`board_pointer` oneof members mirroring the two new ephemeral event kinds.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- `proto/tank/topo/v1/topo.proto` separates derived marks (always `MARK_STATUS_OPEN`, never stored, no `created_by_user_id`) from stored ones with a real lifecycle; only stored marks ever produce a `TopoMarkUpdated` event. This refresh added `GetBriefingResponse.hours`/`.setup` (`BriefingHour`, `BriefingSetup`) — Home's day ring and first-week setup checklist are both server-computed, not client-assembled.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events` now imports `board` and `canvas` in addition to `admin`, `agent`, `blocks`, `channel`, `files`, `huddle`; `topo` and `search` import `message`; `admin` imports `workspace` and `channel`. A field removed from any imported file fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless you set one explicitly (board didn't; books and canvas did), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — board/books/canvas all still need adding there by hand.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
