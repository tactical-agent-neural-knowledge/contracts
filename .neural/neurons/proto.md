# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (up from 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Newest: `admin`, `board`, `books`, `canvas`, `remediation`, `security` have all grown or landed since the last refresh.
- `proto/tank/agentctl/v1/agentctl.proto` is no longer just the runner↔control-plane session contract — it has grown into the full tool surface a run can call: `RunnerService` now carries thread/board/books/canvas RPCs (`PostToThread`, `DrawOnBoard`, `ArrangeBoard`, `BooksCreateInvoice`, `ReadCanvas`, `AskCanvas`, `OpenPullRequest`, `RequestCiWatch`, session-store and inbox RPCs) and `ControlService` carries repo/deployment/policy admin (`CreateProductRepo`, `RegisterDeployment`, `SetUpPreviewWorkflow`, `BindChannelRepo`, `SetWorkspaceAgentPolicy`). It now imports `agent`, `blocks`, `board`, `books` and `canvas` — the widest cross-package surface in the repo, so a FILE-level breaking change to any of those five can fail agentctl's build too.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) carries the policy's destructive-tool gate patterns into the sandbox. Its own comment records the trap: the field was absent until 2026-10-07 and that absence was not a weak control but no control at all — the patterns existed in every workspace's policy and the control plane evaluated them, but nothing inside the sandbox could see them, so the gate the policy promised never opened and the command just ran.
- `StartRunRequest.mode` (agentctl.proto) is `""` for an ordinary run or `"neural"` for a Neural Knowledge refresh — `"neural"` skips planning and works in `repo` regardless of what the Tread is bound to. `RefreshNeuralKnowledgeRequest`/`Response` keeps one standing thread per repository for these refreshes and is idempotent while one is already running (`started = false` otherwise) — this is the exact RPC behind the "@tank neural <repo>" refresh this file itself was produced by.
- `tank.agent.v1.TreadSettings` (agent.proto:260) is the per-Tread switchboard: `auto_accept_plans` skips the plan gate, `pull_requests` is `"review"` (default, mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges itself). Mirrored into a run as `agentctl.PolicySummary.mode` = `propose_only` | `can_merge`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `proto/tank/security/v1/security.proto` models a compliance registry where **controls are the primitive, frameworks are views over them** (file header) — one set of facts (`Control`, keyed by a never-renumbered `id` and bumped `version`), with `FrameworkClause` rows mapping onto them, never a second set of facts. `ControlState` is deliberately allowed to be bad: `NOT_YET` even when everyone is fairly sure a control holds, `UNKNOWN` (not the last known answer) once a check is stale past `max_age_seconds`. `SecurityService` is read-only apart from `Evaluate`, which only re-runs checks — nothing can mark its own homework.
- `proto/tank/remediation/v1/remediation.proto` is the seam between "the half that judges and the half that fixes": the security registry (messaging core) submits a `Finding` via `SubmitFinding`, and only the remediation engine (agent control plane) can act on it. `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` is restricted to a short, declared `Class` list that must state `reversible`, `undo`, and never `lockout_risk`. `SubmitFinding` is idempotent on `(finding_id, control_version)`. Neither service can do the other's job: the registry has no RPC to act, the engine has no RPC to change a control.
- `proto/tank/board/v1/board.proto` (549 lines, no cross-package imports) is Neuralboards: `AppFrame` holds the *running application* at a commit (not a screenshot) and tracks `drawn_from_sha`/`moved_on` so a board can tell it has gone stale (`ListBoardSources`/`ReportBoardSource` feed that). Also carries board templates (`SaveBoardTemplate`), export as raster/slice/embed (`ExportBoard`, `BoardEmbed`, `ListBoardSlices`), generating a test from a recorded click-through (`GenerateTest`/`FlowStep`), and deriving a diagram from what is actually true of the system (`DeriveDiagram`/`Derivation`, fed by `SchemaTable`/`InfraFile`).
- `proto/tank/books/v1/books.proto`: `GetInvoiceRequest.rotate` (admin only) mints a new share link and kills the old one atomically — the share token is stored as a hash, so an ordinary read never returns `share_url`; this is the only way to recover a lost link, by design (comment at the field).
- `proto/tank/admin/v1/admin.proto`: `EndMemberSessionsRequest`/`Response` ends every session a member holds without touching their membership or their bot/API tokens — added so "a laptop goes missing" no longer requires removing and re-adding the person just to sign them out everywhere.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`/`SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` imports `agent`, `blocks`, `board`, `books`, `canvas`; `topo` and `search` import `message`; `admin` imports `workspace` and `channel`. A field removed from any of those fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
