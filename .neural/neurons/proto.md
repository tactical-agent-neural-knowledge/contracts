# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now (22 at the last refresh), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New since 2026-10-03: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same pattern elsewhere: Neuralboards = `board`, Neuralbooks = `books`, Neuralcanvas = `canvas`.
- `proto/tank/board/v1/board.proto` (Neuralboards): an infinite board where a `Frame` can hold the *running application* (`AppFrame`), not a picture of one — that's the one thing that distinguishes it from any other canvas tool. `BoardService` also covers templates, raster/slice/embed export, a saved-journey-as-test (`GenerateTest`), and `ReportBoardSource`/`DeriveDiagram` for turning a workspace's own schema/infra files into a board.
- `proto/tank/books/v1/books.proto` (Neuralbooks): double-entry bookkeeping surfaced as customers, invoices, payments, expenses and a cash summary. Amounts are **integer cents** in the workspace's currency, never floats. Bank import (`ImportBankTransactionsRequest`) and `MatchBankTransactionRequest` tie a statement line to an invoice or expense by hand.
- `proto/tank/canvas/v1/canvas.proto` (Neuralcanvas): a page that "remembers what it was written from" — `Source` cites the threads, decisions and repositories a page was built from, and the file's own header names the failure mode it exists to avoid: "nobody can tell what is still true." `WriteFromThreadRequest` turns a thread into a page; `AskRequest`/`Answer` is semantic search that returns a passage, not just a link.
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberate split, explained in remediation.proto's header: the security **registry** (what's true, what's wrong — lives in the messaging core, `security.proto`) and the **remediation engine** (what can run code — lives in the agent control plane, `remediation.proto`) must not be the same program, "a system that can mark its own homework is not a security system." `security.proto`'s rule: "Controls are the primitive; frameworks are views over them" — one `Control` per fact, a `FrameworkClause` (e.g. SOC 2) maps onto controls, never a second set of facts.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` is narrow, declared per `Class`, reversible, and can never lock an operator out; `REFUSED` is a first-class outcome with a reason, not silence. Every `Finding` fans out to every repository/workspace a `Class` applies to, and that fan-out is recorded — "we fixed it" means a per-target list, not a single ticket closed.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), empty-vs-unconfigured in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. `HomeLayout.setup_hidden` (new) is the person dismissing the first-week setup cards that `topo.proto`'s `BriefingSetup` now describes (`goal_set`, `github_connected`, `agent_summoned`, `someone_invited`, `avatar_set`, `done`).
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, grew by ~370 since last refresh) is the runner ↔ control-plane contract: the in-sandbox runner talks only to agent-control, authenticated by the per-run `RUN_TOKEN`. It picked up thin pass-through RPCs so a run can act as the workspace's own agent — `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` — all on `RunnerService`, all wrapping the `board`/`books`/`canvas` packages it now imports.
- `PolicySummary.tools_gate_destructive` (agentctl.proto, new) is the fix for a control that looked real but wasn't: the destructive-tool deny patterns lived in every workspace's policy and were evaluated by the control plane, but were never told to the sandbox, so "the gate the policy promised could not open and the command simply ran." Comment on the field spells this out — read it before assuming any `PolicySummary` field is merely advisory.
- `ControlService` grew `RefreshNeuralKnowledge` and `OpenThread` (agentctl.proto): the control plane keeps one standing thread per repository for refreshes and starts a neural run there, idempotent while one is already active — this is the mechanism that produced this very file.
- A whole new block in `agentctl.proto` (search "the agent schema's own writes") replaces direct SQL the messaging core used to issue against the control plane's own `agent` schema — it had only ever been green in CI, where the test fixture over-grants DML; in production the app role has USAGE+SELECT only. `BindChannelRepo`, `SetChannelRepoAccess`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy` etc. replace those statements one call at a time, deliberately with **no** generic table+statement RPC.
- `agent.proto`'s `TreadSettings` gained `pull_requests` ("review" default vs. "merge_when_green" — TANK watches checks and merges without a person) and `pr_reviewer_ids`, plus `read_neural_knowledge` (on by default, server always sets it). `RepoConnection`/`TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` are TANK-hosted repos+deployment for premium workspaces (`agenture-<slug>`, `<slug>.tank.chat`); `SetUpRepoPreviews` is the separate self-hosted-repo case — TANK opens a PR adding a reporting workflow to a repo the workspace already owns, never a push to a default branch.
- `admin.proto` gained `EndMemberSessions`: ends every session a member holds without touching their membership or any bot/API token — previously the only way to force sign-out was remove-then-re-add.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope (`Envelope.id` = `Nats-Msg-Id` idempotency key, payload a `google.protobuf.Any`, subjects `evt.{ws}.ch.{channel}` / `.thread.{root}` / `.user.{uid}` / `.ws`). New subjects follow the same shape: `evt.{ws}.canvas.{canvas}` (`CanvasBlockChanged`, `CanvasChanged`) and `evt.{ws}.board.{board}` (`BoardObjectsChanged`, `BoardChanged`), plus ephemeral `typ.{ws}.canvas.{canvas}` / `typ.{ws}.board.{board}` presence (`CanvasEditing`, `BoardPointer` — never stored, and `BoardPointer.kind` is "user" | "agent" so the agent's own cursor renders distinctly).
- `proto/tank/realtime/v1/realtime.proto` mirrors every new event pair into `Subscribe`/`Unsubscribe` (`canvas_ids`, `board_ids`) and `ClientFrame`/`ServerFrame` oneofs (`CanvasEditingFrame`, `BoardPointerFrame`) — a client that never subscribes to a canvas/board id sees none of its live traffic.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary (`PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview`) plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE) — unchanged this cycle, now also imported by `agentctl.proto`'s board/books/canvas RPCs for status/diff cards.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent` and `blocks`; `events` imports `board` and `canvas`; `topo` and `search` still import `message`; `admin` still imports `workspace` and `channel`. A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (or `npx --yes @bufbuild/buf generate` — see `root.md` on why `make` itself doesn't run here): managed mode supplies `go_package` unless you set one explicitly (board/books/canvas/remediation/security all set theirs by hand), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain automatically.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
