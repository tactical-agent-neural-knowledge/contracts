# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Five new domains since the last refresh: `board` (Neuralboards, the infinite canvas with a frame that can hold the running app), `books` (Neuralbooks, double-entry bookkeeping: customers/invoices/payments/expenses/bank feed/reports), `canvas` (Neuralcanvas, pages that cite the threads/decisions/repos they were written from and go stale when those move), `remediation` (the agent control plane's fix-it engine, called by a `security` finding), and `security` (the Neuralsecurity control registry: one set of facts about TANK, frameworks are views over it).
- Nine proto files carry an explicit `option go_package` rather than relying on managed mode: billing, books, canvas, catalog, monitor, platform, remediation, security, topo. `board` does not — it is managed-mode default like most of the repo. A hand-written `go_package` must still match the managed prefix (`.../contracts/gen/go/tank/<domain>/v1;<domain>v1`) or `gen/go` lands in the wrong directory.
- `security.proto` and `remediation.proto` are a deliberate separation of powers: the control registry (messaging core) judges and submits a `Finding` via `RemediationService.SubmitFinding`; the remediation engine (agent control plane) can only act on what it's handed and has no RPC to change a control, retire a probe or mark a finding resolved. `Remediation.judge_principal` and `fix_principal` must differ — "a system that can mark its own homework is not a security system" (remediation.proto:19).
- `security.proto`'s `ControlState` has no state meaning "probably fine": unmeasured is `NOT_YET`, and a check that hasn't run recently reports `UNKNOWN` rather than repeating its last answer — a stale check is modelled as not knowing, not as still passing.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a `Class` with `reversible=true`, a stated `undo`, and `lockout_risk=false` — a class that could lock an operator out can never be auto-applied, whatever else it declares.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `TreadSettings` (agent.proto:260) is the per-Tread agent switchboard: `auto_accept_plans` skips the plan gate, `pull_requests` is `"review"` (default, posts + mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges), `read_neural_knowledge` is on by default and server-set.
- `realtime.proto` and `events.proto` grew matching pairs for the two new live-editing surfaces: `Subscribe`/`Unsubscribe` now carry `canvas_ids`/`board_ids`, and `ClientFrame`/`ServerFrame` carry `CanvasEditingFrame`/`BoardPointerFrame` (ephemeral, rate-limited like typing, never stored) alongside the stored `CanvasBlockChanged`/`BoardObjectsChanged` events.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto). Dropping `optional` to tidy a field silently changes meaning.
- `board.proto`'s `BoardObject.meta` (field 18) is one opaque string for editor-only relationships (component instance, named style, layout, pin, hidden) rather than a field per idea, because geometry and colour stay in real fields so a renderer that knows nothing about `meta` still draws the board correctly.
- `canvas.proto`'s `Block` and `board.proto`'s `BoardObject`/`Board` both use optimistic concurrency per-unit (`rev`/`base_rev` per block or object, `version`/`base_version` for the whole page/board) so two people editing different parts never collide — only the same block or object twice is reported as a conflict.
- Cross-package imports make FILE-level breaking bite across domains: `topo`/`search` import `tank.message.v1`; `admin` imports `tank.workspace.v1`/`tank.channel.v1`; `events` now also imports `tank.board.v1`/`tank.canvas.v1`. A field removed from an imported file fails the breaking check in every file that references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
