# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (was 22): `board`, `books`, `canvas`, `remediation` and `security` are new since the last refresh. Same convention throughout: `proto/tank/<domain>/v1/<domain>.proto`, package `tank.<domain>.v1`, Connect client in `gen/go/tank/<domain>/v1/<domain>v1connect/`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `agentctl.proto` is the busiest file in the repo (1045 lines) because it is where every other domain gets a runner-facing door: `Books*`, `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` are all thin RPCs on `RunnerService` that wrap `books.v1`, `canvas.v1` and `board.v1` types for the in-sandbox agent. It is the runner ↔ control-plane contract only — the runner never talks to the messaging core directly, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings.
- `agentctl.proto`'s `agent schema` boundary (bottom of the file) is the load-bearing trap: schema `agent` belongs to the control plane, the messaging core (api) has USAGE + SELECT only, and the fix for api code that was issuing INSERT/DELETE against `agent.repo_bindings` etc. (only ever green because the CI test fixture grants itself DML) was **new narrow RPCs** (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`), not a wider grant. There is deliberately no RPC that takes a table and a statement, and there will not be one — do not add a generic write escape hatch here.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) is the other security fix in this window: the field was absent until 2026-10-07, meaning the control plane evaluated a destructive-tool deny list that the sandbox was never told about, so the gate it implied could never actually open. A deny list the runner cannot see denies nothing — if adding a new gate kind, check it is actually threaded into `PolicySummary`, not just evaluated server-side.
- `remediation.proto` and `security.proto` are the two halves of Neuralsecurity and must stay separate programs by design: `security.v1` (messaging core, read-only registry of `Control`s with `ControlState` MET/PARTLY/NOT_YET/NOT_APPLICABLE/UNKNOWN) judges; `remediation.v1` (agent control plane) fixes by opening pull requests. `remediation.proto`'s header states the rule plainly: "the engine cannot change a control, a probe or a framework mapping... a system that can mark its own homework is not a security system." `Remediation.forbidden_paths` enforces this in data, not just in the comment.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (pull request, human merges); `AUTO_APPLY` requires a declared `Class` with `reversible = true`, a stated `undo`, and `lockout_risk = false` — a class that can lock an operator out can never be AUTO_APPLY regardless of anything else it declares.
- `security.proto`'s `ControlState.UNKNOWN` is deliberately distinct from a stale MET: "a check that has not run recently reports UNKNOWN rather than its last answer... a registry that flatters the system is worse than no registry." Evidence carries its own `stale` bool keyed off `Control.max_age_seconds`.
- `books.proto`: `Invoice.share_url` and `Settings.stripe_secret_key` are both write-once-read-never-back credentials, same pattern as `channel`'s read-state trap from before — `GetInvoiceRequest.rotate` mints a new share link and kills the old one in the same call, because the share token is stored as a hash and an ordinary read always returns it empty. `stripe_secret_key` is "write-only: set it to store it, send it empty to leave it alone, and read it back as the last four characters in `stripe_key_hint`" — never put the real key in a response message.
- `canvas.proto` and `board.proto` share one vocabulary across two surfaces (pages vs. an infinite board): both have per-object/per-block `rev`/version fields for optimistic concurrency (`UpdateBlockRequest.base_rev`, `PutObjectsRequest.base_revs`), both have a 0–100 `staleness` + `staleness_note` on the parent object ("0 is current; 100 is nothing it was drawn from is still as it was"), and both get realtime fan-out through new `events.proto` messages (`CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing`, `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`) and matching `realtime.proto` `ClientFrame`/`ServerFrame` oneof cases (`canvas_editing`, `board_pointer`) plus `Subscribe`/`Unsubscribe.canvas_ids`/`board_ids`.
- `board.proto`'s `AppFrame` is the product point of the whole domain: a frame can hold the *running application* at a commit, not a screenshot — `drawn_from_sha` + `moved_on` is how the board knows it has gone stale relative to what's deployed. `BoardObject.meta` is one deliberately opaque string for editor-only relationships (component instance, named style, auto-layout, pinning) so a renderer that understands nothing about them still draws the board correctly — don't split it into typed fields without re-reading why.
- `agent.proto`'s new `TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` (hosting TANK generates) and `SetUpRepoPreviews`/`ListRepoPreviewSetups` (previews for a repo the workspace already owns) are two different flows for the same board feature (`AppFrame`/`ReportPreview` in `board.proto`) — one TANK hosts, one the workspace's own CI reports into. Don't conflate `RepoConnection.premium`/`hosting_available` (TANK-hosted) with `ReportPreviewRequest` (self-hosted, `board.proto`).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline holds for the new domains: Neuralboards is `board.v1`, Neuralbooks is `books.v1`, Neuralcanvas is `canvas.v1`, Neuralsecurity is split `security.v1`/`remediation.v1` — product names in comments only.
- `optional` is still used throughout as deliberate presence, not nullability (unchanged-field semantics, "this replaces nothing", empty-vs-unconfigured). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent`/`blocks`; `events` imports `board` and `canvas` on top of its existing set. A field removed from any of those fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
