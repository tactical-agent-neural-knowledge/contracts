# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board, shared by people and the agent. `BoardObject.app` (`AppFrame`) is the point — a frame can hold the *running application* at a commit, not a screenshot of one; `AppFrame.moved_on`/`moved_note` flag when the deployed app has drifted past what was drawn. `PutObjectsRequest.base_revs` makes editing per-object: two people moving different shapes never collide, only the same object twice is reported as a conflict.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses. All money is integer cents (`int64 ..._cents`); `Settings.stripe_secret_key` is write-only (set it, send empty to leave it, read back only `stripe_key_hint`'s last four chars) — never assume a full key round-trips.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite their own sources (threads, decisions, repos) and say so when those move — "the failure of every wiki ... nobody can tell what is still true." `BlockKind.LIVE` blocks are filled server-side on read, never stored stale.
- `proto/tank/remediation/v1/remediation.proto` is the judge/fixer seam from Neuralsecurity §2.3, deliberately split: the control registry (messaging core) decides what's wrong and submits a `Finding`; the remediation engine (agent control plane) is the only thing that can write code. Four fixed rules in the file header: propose-only by default (PRs, not auto-merges), every fix ships its regression test as a requirement not a suggestion, fixes target the class not the instance (fan-out to every affected repo/workspace), everything is logged via the run it drove.
- `proto/tank/security/v1/security.proto` is Neuralsecurity Phase 0: "Controls are the primitive; frameworks are views over them" — SOC 2 etc. map onto `Control`s, never a second set of facts. `ControlState` has no comfortable default: `NOT_YET` is honest ("probably true but we cannot evidence it"), `UNKNOWN` is forced onto any check that hasn't run recently rather than showing its last answer, and `PARTLY`/`NOT_APPLICABLE` both require a mandatory `reason`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong. Use `unread_count`.
- `optional` is deliberate presence, not nullability: `UpdateChannelRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`. Dropping it to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` grew RPCs for the thread-driven agent to act as the workspace's own user against Neuralbooks, Neuralcanvas and Neuralboards (`BooksSummary`/`BooksCreateInvoice`/..., `WriteUpThread`/`ReadCanvas`/`AskCanvas`, `ListBoards`/`ReadBoard`/`DrawOnBoard`) — same checks a human gets from the page. `PolicySummary.tools_gate_destructive` (field 9) closed a real hole: before 2026-10-07 the destructive-tool deny patterns lived in policy and were evaluated control-plane side but never told to the sandbox, so "the gate the policy promised could not open and the command simply ran."
- `RunContext.task_class` ("single_area" | "multi_area") and `skip_neural_knowledge` are new on the runner contract; both are empty/false on older runs, not a hard requirement to check.
- `proto/tank/events/v1/events.proto` gained `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`, mirrored in `realtime.proto`'s `ClientFrame`/`ServerFrame` oneofs (fields 9-10 client, 10-11 server) and `Subscribe`/`Unsubscribe` (fields 3-4) — a client must subscribe to a canvas/board id before another editor's writes arrive over the socket.
- Cross-package imports make FILE-level breaking bite across domains: `events.proto` now also imports `board` and `canvas`; `agentctl.proto` imports `board`, `books`, `canvas`. A field removed from any of those fails the breaking check wherever it's referenced.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`. The five new domains all set `option go_package` explicitly (books, canvas, remediation, security join billing/catalog/monitor/platform/topo — 9 of 27 files now opt out of the managed-mode prefix). `gen/ts/src/index.ts`'s hand-written barrel still won't pick up a new domain automatically: 13 of 27 packages are absent from it now (the 8 from the last refresh plus board, books, canvas, remediation, security).
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
