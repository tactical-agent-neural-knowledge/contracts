# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now (five added this round: `board`, `books`, `canvas`, `remediation`, `security`), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." The same split holds in the new files: Neuralboards is `tank.board.v1`, Neuralbooks is `tank.books.v1`, Neuralcanvas is `tank.canvas.v1` — none of those product names appear in a field or message name.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only, and it alone is allowed to import across every product domain (`agent`, `blocks`, `board`, `books`, `canvas`) because it is the single surface the sandboxed runner talks to; a product domain never imports another product domain directly. `PolicySummary.tools_gate_destructive` (added 2026-10-07) is the policy fix worth knowing: the field was absent before, so the control plane evaluated `tools.gate.destructive_tool` but the runner was never told the patterns, and "a deny list the runner cannot see denies nothing" (agentctl.proto:66-68) — the gate silently did not fire.
- `proto/tank/remediation/v1/remediation.proto` is a hard separation-of-powers boundary: the messaging core's control registry "judges" (owns `security.v1` Controls/Findings) and the agent control plane's remediation engine "fixes" (owns sandboxes, the GitHub App, the gate engine) — neither service has an RPC to do the other's job. `Remediation.judge_principal` and `fix_principal` must differ; the engine refuses a `SubmitFindingRequest` where they're the same. `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` is only legal for a declared, reversible `Class` with no `lockout_risk`.
- `proto/tank/security/v1/security.proto` models honesty, not status: `ControlState.UNKNOWN` is mandatory once evidence goes stale past `max_age_seconds` — a control must never keep reporting its last good answer. `CheckKind.NONE` controls can never be `MET`. `FrameworkClause` (e.g. SOC 2 `CC6.1`) is a view that maps onto existing `Control`s; a framework requirement with no backing `Control` is a modeling bug, not a thing to special-case.
- `proto/tank/board/v1/board.proto` and `proto/tank/canvas/v1/canvas.proto` share one editing model: both use per-object/per-block `rev`/`base_rev` optimistic concurrency (`PutObjectsRequest.base_revs`, `UpdateBlockRequest.base_rev`) so two people editing different shapes/blocks never collide — only the same object/block twice is reported as a conflict, nothing is silently overwritten.
- `board.proto`'s `AppFrame` is the product's point: a frame can hold the *running application* at a commit, not a screenshot. `AppFrame.drawn_from_sha` / `moved_on` / `moved_note` is how a board learns it has gone stale relative to what's actually deployed — same `staleness`/`staleness_note` idea as `Canvas`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), empty-vs-unconfigured in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists. `HomeLayout.setup_hidden` (new) and `topo.proto`'s `GetBriefingResponse.hours`/`setup` feed the same Home surface: a day ring of message/run volume plus first-week setup cards that a person can dismiss.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, and now also `.canvas.{canvas}` / `.board.{board}` for `CanvasBlockChanged`/`CanvasChanged`/`BoardObjectsChanged`/`BoardChanged`. The matching ephemeral (never-stored) presence events — `CanvasEditing`, `BoardPointer` — ride `typ.{ws}.canvas.{canvas}` / `typ.{ws}.board.{board}`, mirrored in `realtime.proto`'s `ClientFrame`/`ServerFrame` oneofs as `canvas_editing`/`board_pointer`. `AuditLogged` is still internal-only — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it. `Subscribe`/`Unsubscribe` now also carry `canvas_ids`/`board_ids` — a client that never subscribes to a page or board simply never receives its live-edit events.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1`/`tank.channel.v1`, `events` now also imports `board`/`canvas`. A field removed from an imported file fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless you add one explicitly (nine files now do — `billing`, `books`, `canvas`, `catalog`, `monitor`, `platform`, `remediation`, `security`, `topo`), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain automatically.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
