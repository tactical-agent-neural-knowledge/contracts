# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now (board, books, canvas, remediation, security added since the last refresh), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new files: `board.proto` is "Neuralboards", `books.proto` "Neuralbooks", `canvas.proto` "Neuralcanvas" in comments only — the wire types are `Board`, `Invoice`, `Canvas`.
- `security.proto` + `remediation.proto` are a deliberate seam, not two views of one thing: the registry (security, in the messaging core) judges and cannot run anything; the engine (remediation, in agent-control) fixes and "cannot change a control, a probe or a framework mapping." `remediation.proto:9-19` states this as the reason a security system cannot mark its own homework — do not merge these packages or add a write path across the boundary.
- `security.proto`'s own rule: "Controls are the primitive; frameworks are views over them" — a `FrameworkClause` maps onto existing `Control`s and must never introduce a new fact. `ClauseCoverage` state is derived (worst of its controls), never stored, so a crosswalk can't read greener than the facts under it. A control with no evidence is `NOT_YET` even if everyone assumes it holds; a stale check reports `UNKNOWN`, never its last answer.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (pull request, human merges); `AUTO_APPLY` is only valid for a declared, readable `Class` with a written reverse. `SubmitFindingRequest` is idempotent on `(finding_id, control_version)` so an hourly evaluation re-submitting the same finding returns the remediation already in flight instead of opening a second pull request. `ListRemediationsResponse` is a poll, not a push: the engine never writes back to the registry.
- `board.proto`'s point is `AppFrame`: a frame can hold the *running application* at a commit, not a screenshot. `BoardSource`/`ReportPreview` deliberately mirror each other ("the same shape... and for the same reason"): TANK never holds a workspace's DB credentials or CI pipeline, the workspace's own CI tells TANK what it already knows, scoped to a `board:preview` token.
- `board.proto`'s `PutObjectsRequest` is one-object-at-a-time: "two people moving different shapes are not in conflict, and the only real collision is the same shape twice" — same per-object conflict model reused in `agentctl.proto`'s `DrawOnBoardRequest`/`ArrangeBoardRequest` via `base_revs` (a revision map keyed by object id), so a shape moved by a person since the agent last read is reported in `conflict_ids`/`conflict_note` rather than overwritten.
- `books.proto`: amounts are integer cents, ids are Snowflake strings like everywhere else. `GetInvoiceRequest.rotate` (added 2026-10-08) mints a new share link and kills the old one atomically — the share token is stored as a hash, so an ordinary read always returns an empty `share_url`; losing the link has no recovery except rotation. Admin only.
- `canvas.proto`'s differentiator from a wiki: a page's `Source` cites what it was written from (threads, decisions, repos) and says when that has moved. `Live` blocks hold the real number, filled in by the server at read time, "so a canvas is never stale about its own data." `UpdateBlockRequest` edits one block without touching the rest of the page — concurrent editors in different blocks both succeed.
- `canvas.proto`'s `DecisionRecord`/`ListDecisionsRequest` is the decision ledger across every page in the workspace: "What did we decide about X" is a query, not a search; a superseded decision names its replacement.
- `agentctl.proto` is now 1045 lines (was ~700) and the runner/control-plane boundary has grown three new surfaces the runner can call on the thread's behalf, mirroring the product services: Neuralbooks (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`), Neuralcanvas (`WriteUpThread`/`ReadCanvas`/`AskCanvas`), Neuralboards (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`) — all under `RunnerService`, all against the same checks a human calling the underlying service would hit.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9, added 2026-10-07) closes a real gap called out in its own comment: the destructive-tool patterns existed in every workspace's policy and were evaluated by the control plane, but were never told to the sandbox, so "the gate the policy promised could not open and the command simply ran." A deny list the runner cannot see denies nothing — any new gated-pattern policy field must flow into this message or it is decorative.
- `agentctl.proto`'s biggest single addition is "the agent schema's own writes" (bottom of file): `BindChannelRepo`/`UnbindChannelRepo`/`SetChannelRepoAccess`/`CreateGitHubConnectState`/`SetChannelAgentSettings`/`SetWorkspaceAgentPolicy`. These exist because the messaging core was issuing raw INSERT/DELETE against schema `agent` (owned by the control plane, which only grants it USAGE+SELECT) — "only ever green in CI, where the test fixture grants itself DML." Each RPC is deliberately narrow; there is no generic table+statement RPC and the comment says there will not be one. Widening the grant instead of adding RPCs would make the control-plane separation imaginary.
- `agentctl.proto`'s `RefreshNeuralKnowledge`/`OpenThread` on `ControlService` are how this very refresh gets triggered: the control plane keeps one standing thread per repository, idempotent while a refresh is already active for that repo.
- `agent.proto`'s `TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` is TANK-hosted deploys for premium workspaces: `managed` distinguishes a TANK-generated repo (`agenture-<slug>`) from a workspace's own; `awake` means 1 replica, "builds never wake it" — waking is a deliberate decision (preview, sale), recorded in GitOps. `SetUpRepoPreviews`/`ListRepoPreviewSetups` is the parallel path for a workspace's *own* repos: TANK opens a pull request adding the reporting workflow, never pushes directly, and `rotate_token` shows a secret exactly once (same one-shot-credential pattern as the books share link and board embed link).
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`/`SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent`/`blocks`; `topo` and `search` import `message`; `admin` imports `workspace` and `channel`. A field removed from any imported file fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
