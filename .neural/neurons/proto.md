# Neurons · proto

refreshed 2026-10-08 · e52a377a71d9

- 27 domains now (was 22 at the last refresh), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New since 2026-10-03: `board`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberate two-program split: security.proto's `SecurityService` (messaging core) judges — it owns `Control`/`Posture`/`FrameworkClause` and is read-only except `Evaluate`, which only re-runs checks — and remediation.proto's `RemediationService` (agent control plane) fixes by opening pull requests via `SubmitFinding`. Neither has an RPC for the other's job; a `Remediation.judge_principal` equal to its `fix_principal` is refused. Read both files' header comments before touching either.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with `reversible=true`, a stated `undo`, and `lockout_risk=false` — a class that could lock an operator out can never be AUTO_APPLY regardless of what else it declares.
- `SubmitFindingRequest` is idempotent on `(finding_id, control_version)`: resubmitting without `resubmit=true` returns the remediation already in flight rather than opening a second PR, which is what an hourly evaluation loop needs.
- `proto/tank/agentctl/v1/agentctl.proto`'s `ControlService` gained six narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`, agentctl.proto:853-858) so the messaging core writes schema `agent` — which it is granted only USAGE+SELECT on — through the control plane instead of issuing DML it cannot execute outside CI's permissive test fixture. There is deliberately no generic "table + statement" RPC and there will not be one (agentctl.proto:935-956).
- `PolicySummary.tools_gate_destructive` (agentctl.proto:69) is the patterns that must open a `GATE_KIND_DESTRUCTIVE_TOOL` gate instead of running; it was added 2026-10-07 because the field was absent and a deny list the sandboxed runner cannot see denies nothing, even though the control plane evaluated it.
- `proto/tank/board/v1/board.proto`: `AppFrame` can hold the running application itself, not a screenshot — `drawn_from_sha`/`moved_on`/`moved_note` are how a board learns it has gone stale against the app, the same staleness idea `Board.staleness` carries at the board level. `PutObjectsRequest.base_revs` + `BoardObject.rev` is optimistic concurrency: a mismatch is reported in `PutObjectsResponse.conflicts`, never silently overwritten.
- `board.proto`'s `BoardObject.meta` (field 18) is one opaque string for editor-only relationships (component instance, named style, layout, pinning) rather than a field per idea, so a renderer that does not understand the editor's vocabulary still draws geometry and colour correctly and simply leaves `meta` alone.
- `proto/tank/canvas/v1/canvas.proto` (added with `events.proto`'s `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing`) is Neuralcanvas: pages that cite what they were written from, edited one block at a time so concurrent edits in different paragraphs merge instead of colliding.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `proto/tank/books/v1/books.proto`'s `GetInvoiceRequest.rotate` (books.proto:164) rotates an invoice's `share_url` token: the token is stored only as a hash and cannot be read back once issued, so rotation is the only recovery when a business loses the link — admin-only, and the old link dies the instant the new one is issued.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, plus new `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}`. `AuditLogged` is internal — the gateway never fans it out to clients.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events.proto` now imports `board`, `canvas`, `admin`, `huddle`, `monitor`, `topo` on top of the originals. A field removed from any of those fails the breaking check in `events.proto` even though it never touches the wire there.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
