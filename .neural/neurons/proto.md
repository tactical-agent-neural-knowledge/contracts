# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five domains are new this refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire, including in the new domains: `board.proto` is Neuralboards, `canvas.proto` is Neuralcanvas, `books.proto` is Neuralbooks — the proto comments use the product names freely, but `channel.proto:7` still states the rule ("a Channel is presented as a 'Tread'… the wire name stays Channel") and the new files follow it (`AppFrame`, `Block`, `Invoice`, never "Tread"/"Vault" as a type name).
- `proto/tank/remediation/v1/remediation.proto` and `proto/tank/security/v1/security.proto` are a deliberate separation of powers: `security.v1.Control`/`Finding` is the registry's read-only posture (messaging core), `remediation.v1.Finding`/`Remediation` is the fix side (agent control plane), and neither service has an RPC to do the other's job — `RemediationService` has no method that marks a finding resolved or edits a control, by design (`remediation.proto:285-298`). `SubmitFinding` is idempotent on `(finding_id, control_version)`; `Disposition` defaults to `PROPOSE` and `DISPOSITION_AUTO_APPLY` is refused whenever `Class.lockout_risk` is true, whatever else the class declares.
- `security.v1.ControlState` is deliberately allowed to look bad: `NOT_YET` is the honest home of "probably true but unevidenced", and `UNKNOWN` is forced whenever a check's evidence is stale (`Evidence.stale`) — a stale check must never report its last answer. `CHECK_KIND_NONE` controls can never be `MET`.
- `proto/tank/books/v1/books.proto`: amounts are integer cents, ids are Snowflake strings. `Invoice.share_url`/`GetInvoiceRequest.rotate` follow the same "token stored as a hash, readable only once" pattern that `board.v1.BoardEmbedRequest` reuses for board embeds — admin-only rotation, old link dies the instant the new one is issued, and there is deliberately no way to read a share link back.
- `proto/tank/board/v1/board.proto`'s point is `AppFrame` (board.proto:52): a frame can hold the running application itself, not a picture of one. `AppFrame.drawn_from_sha`/`moved_on` and `Board.staleness` are the same "has the product moved past this" idea `canvas.v1.Canvas.staleness`/`Source.changed` already uses — don't model one without checking the other stayed consistent.
- `proto/tank/canvas/v1/canvas.proto` states its own thesis in the file comment: "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true" — hence `Source` (what a page was written from, and whether it changed) and `Decision.needs_revisiting`. `Block.rev` / `UpdateBlockRequest.base_rev` is per-block optimistic concurrency, the same shape as `board.v1.BoardObject.rev` / `PutObjectsRequest.base_revs` — editing one block/object never collides with edits to a different one.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, the largest hot file) grew a whole new surface this refresh: `PolicySummary.tools_gate_destructive` (agentctl.proto:61-67) finally tells the sandboxed runner which tool patterns must open a `destructive_tool` gate — before 2026-10-07 the control plane evaluated this policy but never told the runner, so "the gate the policy promised could not open and the command simply ran." Also new: `RunContext.skip_neural_knowledge`/`task_class`, the `BooksSummary`/`BooksCreateInvoice`/... RPCs and `WriteUpThread`/`ReadCanvas`/`AskCanvas` and `ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard` RPCs (the agent acting as the workspace's own user of Neuralbooks/Neuralcanvas/Neuralboards from inside a run), and `RefreshNeuralKnowledge`/`OpenThread` on `ControlService` (this refresh job's own entry point).
- `agentctl.proto`'s `BindChannelRepo`/`UnbindChannelRepo`/`SetChannelRepoAccess`/`SetWorkspaceAgentPolicy`/`SetChannelAgentSettings`/`CreateGitHubConnectState` RPCs exist because schema `agent` belongs to the control plane and the messaging core's app role has `USAGE`+`SELECT` only — the messaging core had been issuing INSERT/DELETE against `agent.repo_bindings` etc. directly, which "cannot succeed from an api pod and were only ever green in CI, where the test fixture grants itself DML." The fix is these narrow RPCs, not a wider grant — there is deliberately no RPC that takes a table and a statement.
- `proto/tank/agent/v1/agent.proto` grew `TreadDeployment`/`CreateTreadRepo`/`SetTreadDeployment` (TANK-hosted repos for premium Treads) and `SetUpRepoPreviews`/`ListRepoPreviewSetups` (TANK opens a PR adding a preview-reporting workflow to a workspace's *own* repo — a pull request, never a push, because a workflow file in someone else's repo is their decision). `TreadSettings.pull_requests` ("review" vs "merge_when_green") and `read_neural_knowledge` are new per-Tread knobs the server always sets.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, and now also `.canvas.{canvas}` / `.board.{board}` for the new `CanvasBlockChanged`/`CanvasChanged`/`BoardObjectsChanged`/`BoardChanged` events, plus ephemeral (never-stored) `CanvasEditing`/`BoardPointer` on `typ.{ws}...`. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto`'s `Subscribe`/`Unsubscribe` grew `canvas_ids`/`board_ids`: a client that never subscribes to a page or board never receives another editor's changes for it. `ClientFrame`/`ServerFrame` got matching `canvas_editing`/`board_pointer` oneof branches, rate-limited like `TypingFrame`.
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, and now `agentctl` imports `tank.board.v1`/`tank.books.v1`/`tank.canvas.v1`, and `events` imports `tank.board.v1`/`tank.canvas.v1`. A field removed from `message.proto` (or now `board.proto`/`canvas.proto`) fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless the file sets its own, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — none of the five domains added this refresh are in it yet.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
