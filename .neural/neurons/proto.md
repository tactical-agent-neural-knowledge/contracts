# Neurons · proto

refreshed 2026-10-14 · 3b1cc8caafe7

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Five domains are new since the last refresh: `board` (Neuralboards, an infinite shared board), `books` (Neuralbooks, invoicing/expenses/bank reconciliation), `canvas` (Neuralcanvas, pages that cite the threads/decisions/repos they were written from and report staleness), `remediation` (security findings → pull requests) and `security` (the control-registry posture API). All five follow the same shape as the rest: a `List*`/`Get*` pair, server-filled fields marked as such in comments, and Snowflake-decimal ids as strings.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `board.proto` and `canvas.proto` share one convention worth knowing once: both `Board`/`Canvas` carry a `staleness` int (0 current, 100 "nothing it rests on still holds") plus a `staleness_note` sentence, and both use per-object/per-block `rev`/`base_rev`(s) for last-write-wins-with-conflict-reporting rather than locking — `PutObjectsRequest.base_revs` / `UpdateBlockRequest.base_rev` / `DrawOnBoardRequest.base_revs` are all "the rev I last read"; a mismatch comes back as a `conflicts`/`theirs` field, never a silent overwrite.
- `board.proto`'s `AppFrame` is the product's actual point: a frame can hold the *running application* at a commit, not a screenshot — `preview_url`/`status`/`drawn_from_sha`/`moved_on` are all server-filled and compare what's drawn against what's deployed now. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pin, hidden) deliberately *not* broken into fields, so a renderer that understands none of it still draws the board correctly.
- `books.proto`'s `Invoice.share_url`/`pay_url` and the `rotate` flag on `GetInvoiceRequest` follow the same share-link pattern as a board embed link (see below): the token is stored as a hash, a plain read never returns it, and `rotate` is the only recovery path for a lost link — admin only, and the old link dies the instant the new one is issued.
- `remediation.proto` is the enforced half of Neuralsecurity: the registry (messaging core) submits a `Finding` via `SubmitFinding`, and the engine (agent control plane) is the only thing that can act on it. The file states four hard rules in its header comment: propose-only by default (`Disposition.PROPOSE`; `AUTO_APPLY` is a short declared list only), every fix carries a mandatory regression-test requirement, a finding fans out to every repository the same `Class` applies to (not just the one it was reported against), and every remediation names the run that drove it. `Class.lockout_risk = true` forbids `AUTO_APPLY` outright, whatever else the class declares.
- `security.proto`'s one rule, from its own header: "Controls are the primitive; frameworks are views over them" — a `FrameworkClause` (e.g. SOC 2 CC6.1) only ever maps onto an existing `Control`, never introduces a new fact. `ControlState.UNKNOWN` is forced whenever a check is stale (`Evidence.stale` / past `max_age_seconds`): the registry reports UNKNOWN rather than repeating its last answer, which is the opposite of how most "green dashboard" scanners behave.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. It now also carries the runner-side RPCs for Neuralbooks/Neuralcanvas/Neuralboards (`BooksSummary`, `WriteUpThread`, `DrawOnBoard`, etc. on `RunnerService`) — these mirror the public `*Service`s in `books.proto`/`canvas.proto`/`board.proto` but scoped to "the run acting as the workspace's agent in this thread".
- `PolicySummary.tools_gate_destructive` (agentctl.proto) is a trap worth knowing: the field was *absent* until 2026-10-07, and its absence was not a weak control, it was no control at all — the control plane evaluated `tools.gate.destructive_tool` patterns, but nothing inside the sandbox could see them, so the gate the policy promised never actually opened. A deny list the runner cannot see denies nothing; check this field exists before assuming a destructive-tool gate is wired end to end.
- `RunContext.skip_neural_knowledge` / `StartRunRequest.skip_neural_knowledge` (agentctl.proto) exist for measurement: the same task run with and without the Neural Knowledge layer. `RunContext.task_class` ("single_area" | "multi_area" | "") drives whether a run skips the planning stage on a cheaper model.
- `tank.agent.v1.TreadSettings` (agent.proto) gained `pull_requests` ("review" default, posts + mentions `pr_reviewer_ids`; or "merge_when_green", TANK watches checks and merges) and `read_neural_knowledge`. This is the setting behind "can an agent merge its own PR" — it is a Tread switchboard setting (`SetTreadSettings` / `SetChannelAgentSettings`), not a TANK GitHub App permission; the app grants reach, the Tread decides what happens with it.
- `tank.agent.v1.TreadSecurity` / `ListTreadSecurity` (agent.proto) is the Home-screen read of the newest finished Neuralsecurity scan per Tread with a bound repo — states are `clean | findings | scanning | failed | unscanned`, one row per bound Tread.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest file and `GetBootstrap` is still its point: one call on app open, everything else lazy. Members cap at 200, which is the entire reason `ListMembersRequest.query` exists.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, and now `agentctl` imports `board`/`books`/`canvas`, and `events`/`realtime` import `board`/`canvas` for the live-collaboration event types (`BoardObjectsChanged`, `CanvasBlockChanged`, `BoardPointer`/`CanvasEditing` presence frames). A field removed from any of these fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
