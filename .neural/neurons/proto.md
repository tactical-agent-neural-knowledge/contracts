# Neurons · proto

refreshed 2026-10-06 · fb6e2ffe6678

- 25 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` (now 381 lines, the biggest contract after workspace) is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings. It now also carries the Neuralboards surface (`ListBoards`/`ReadBoard`/`PutObjects`-style `BoardShape` draw calls) and the Neuralbooks pass-through (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`) so an agent acts as the workspace's own user, not a separate principal.
- `tank.board.v1` (new) is the infinite-board domain: `BoardObject.kind` covers frame/rect/ellipse/line/arrow/text/sticky/image/connector/draw, and `AppFrame` is the one field that matters — a frame can hold the *running application* at a commit (`drawn_from_sha`), not a screenshot. `BoardObject.meta` is deliberately one opaque string for editor-only relationships (component instance, named style, layout, pin) so a renderer that doesn't understand it still draws correctly; geometry and colour stay in real fields.
- `tank.board.v1.ReportPreview`/`ListPreviews`/`ForgetPreview` exist so a workspace running its own CI can tell TANK where a build landed instead of TANK building it; `SetUpRepoPreviews` (in `tank.agent.v1`, agentctl mirrors it) is the other direction — TANK opens a pull request adding the reporting workflow to a repo the workspace already connected, never a push.
- `tank.books.v1` (new) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/CashSummary, amounts always integer cents. `Settings.stripe_secret_key` is write-only by convention (send to set, empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — there is no `ClearStripeKey`, so the field's comment is the only enforcement of that contract.
- `tank.canvas.v1` (new, not in `hot:` but same wave as board/books) backs Neuralcanvas pages; `tank.events.v1` gained `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` in the same commits that added the two domains — adding a realtime-backed domain means touching `events.proto` and `realtime.proto` (`ClientFrame`/`ServerFrame` oneofs) together, not just the domain's own file.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` for debugging). `Subscribe`/`Unsubscribe` now carry `canvas_ids` and `board_ids` alongside `channel_ids`/`thread_root_id`s — a client that never subscribes never receives another editor's board/canvas writes. `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding.
- `proto/tank/topo/v1/topo.proto`'s `GetBriefingResponse` grew `hours` (a `BriefingHour` ring for Home's day view) and `setup` (`BriefingSetup`, the first-week checklist: goal set, GitHub connected, agent summoned, someone invited, avatar set). Derived marks (`MARK_STATUS_OPEN`, never stored) stay separate from stored ones with a real lifecycle; only stored marks emit `TopoMarkUpdated`.
- `proto/tank/workspace/v1/workspace.proto` (719+ lines, still the biggest file) added `HomeLayout.setup_hidden` next to its existing `GetBootstrap` one-call-on-open design; it caps members at 200, the entire reason `ListMembersRequest.query` exists.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events.proto` now imports `tank.board.v1` and `tank.canvas.v1` on top of `admin`/`agent`/`blocks`/`channel`/`files`/`huddle`; `agentctl.proto` imports `agent`, `blocks`, `board`, `books`, `canvas`. A field removed from any of those fails the breaking check in every importer.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and does **not** pick up a new domain automatically — it currently covers only 14 of 25 packages (missing: admin, billing, board, books, canvas, catalog, command, huddle, monitor, platform, topo), so board/books/canvas consumers must use the deep import path the barrel's own comment calls primary.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
