# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 files, one package per domain, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five new domains since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new files: Neuralboards/Neuralbooks/Neuralcanvas/Neuralsecurity are product names in comments only — the wire packages are `board`, `books`, `canvas`, `security`.
- `remediation.proto`'s header is the load-bearing design doc for the security side: the control registry (messaging core, judges) and the remediation engine (agent control plane, the only thing that writes code) are deliberately two programs — "A system that can mark its own homework is not a security system." `Finding` crosses that boundary one way only; the engine cannot edit a control or a framework mapping.
- `remediation.proto`'s `Disposition` defaults to `PROPOSE` (a PR a human merges); `DISPOSITION_AUTO_APPLY` requires a declared `Class` with `reversible=true` and an `undo`, and is unconditionally forbidden when `Class.lockout_risk=true`, "whatever else it declares." A `Class` without `gate_kind` can never be AUTO_APPLY either (mandatory for that disposition, empty for PROPOSE).
- `security.proto`'s rule: "Controls are the primitive; frameworks are views over them" — a `FrameworkClause` (e.g. SOC 2) maps onto `Control`s, never adds a second set of facts. `ControlState.UNKNOWN` is mandatory for a check that "has not run recently," not its last answer — a stale check must not report green by default.
- `board.proto`'s `AppFrame` is the differentiator from every other whiteboard: a frame can hold the running application at a commit (`drawn_from_sha`), not a screenshot of one. `moved_on`/`moved_note` are server-filled when the deployed app has advanced past what the frame shows — that's what `agentctl.ListBoardSources`/`ReportBoardSource` (agent side) keeps in sync.
- `books.proto`: amounts are integer cents everywhere, ids are Snowflake-string like the rest of the schema. `Settings.stripe_secret_key` is write-only by convention (comment, not enforced by the type system) — set to store, send empty to leave alone, read back only as `stripe_key_hint`'s last four chars.
- `canvas.proto`'s point, stated in its header: "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true." `Decision.needs_revisiting`/`revisit_note` and `Live` blocks (server-filled at read time, never stale about their own data) are how that's kept honest; `BLOCK_KIND_LIVE`'s `Live.kind` is a free-string lookup key (`"books.cash"`, `"radar.widget"`, …) with no compile-time link to the domain it reads.
- `agentctl.proto` (1045 lines, the largest file) is the runner ↔ control-plane contract only — never messaging core directly — authenticated by the per-run `RUN_TOKEN`. This refresh added `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, and `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` to `RunnerService` — agent access to Neuralbooks/Neuralcanvas/Neuralboards all goes through this one file, mirroring the dedicated service protos rather than importing their RPCs directly.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) was added because the destructive-tool deny list existed in every workspace's policy and was evaluated by the control plane, but the sandbox was never told the patterns — "A deny list the runner cannot see denies nothing." Added 2026-10-07; a runner build from before that date silently ran commands a policy meant to gate.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `realtime.proto` and `events.proto` grew matching pairs for the two new live surfaces: `Subscribe/Unsubscribe.canvas_ids`/`board_ids`, ephemeral `CanvasEditingFrame`/`BoardPointerFrame` client frames, and server-side `CanvasBlockChanged`/`CanvasChanged`/`BoardObjectsChanged`/`BoardChanged`/`BoardPointer` events — pointer and editing-presence frames are explicitly "never stored," unlike the block/object-change events.
- Cross-package imports are real and make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent`/`blocks`; `events` imports `board` and `canvas`; `topo` and `search` import `message`; `admin` imports `workspace` and `channel`. A field removed from any of these fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless the file sets its own `option go_package` (all five new domains do). Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain automatically.
