- 29 proto files across 29 domains (up from 22 at the last refresh): board, books, canvas, crew, remediation, security, and social are among the additions since 2026-10-03. Each domain follows `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel is presented as a "Tread" in the product; the wire name stays Channel. `CLAUDE.md`: "Wire names stay neutral (`Channel`, not `Tread`); product vocabulary lives in the clients."
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract: `RunnerService` is the only network surface the sandbox may reach besides the LLM gateway. Every call carries `Authorization: Bearer <RUN_TOKEN>`. All ids are Snowflake decimal strings. `RunContext.workbench_board_id` (field 30) is the thread's Workbench board — the live board the agent draws its steps on while people watch. Empty for neural/recon/remediation runs.
- `RunContext.task_class` (field 27) lets the control plane class the ask as `single_area` (cheaper model, no plan stage) or `multi_area`. `RunContext.channel_purpose` and `channel_goal` (fields 24–25) carry the Tread's own goal so an agent working the code knows what the Tread is for. `RunContext.agent_title` and `agent_skill` (fields 28–29) carry a Crew member's identity.
- `PolicySummary.tools_gate_destructive` (field 9) was absent until 2026-10-07: without it, destructive-tool gate patterns were never sent to the sandbox, so the gate the policy promised could not open and commands simply ran. A deny list the runner cannot see denies nothing.
- The Workbench RPCs in `RunnerService`: `WorkbenchSteps` sets the process row (the whole row in order; a step left out is removed). `WorkbenchShow` puts content in the stage area below it. Both return a `board_id`. The control plane handles layout — the model never computes coordinates for Workbench objects.
- `proto/tank/agent/v1/agent.proto` carries `TreadSettings`: `pull_requests` = "review" (default, mentions pr_reviewer_ids) | "merge_when_green" (TANK watches checks and merges). `auto_accept_plans` skips the plan gate. `strongest_model` starts the run on Opus from turn one (costs 2.5× on every token; off = start on Sonnet, escalate only after two CI failures). `merge_allowed` gates whether TANK may approve and merge at all.
- `TreadMetrics.neural_saved_usd` / `neural_saved_month_usd` (HourBucket field 4, TreadMetrics fields 11–12) estimates what Neural Knowledge saved against a baseline of comparable runs in the prior thirty days. `neural_measured` = false means "still measuring", not zero saved.
- `proto/tank/crew/v1/crew.proto`: Crew is a workspace's swarm of agents, each with a role, title, handle, and skill (a prompt). `Member.activity` controls how often it speaks up unprompted: `MENTIONED_ONLY` | `LOW` (daily) | `NORMAL` (every few hours) | `HIGH` (every half hour). `crew.proto` carries an explicit `option go_package` unlike most domains.
- `proto/tank/social/v1/social.proto`: Flare is the workspace's voice on X and Instagram. `Settings.review_required = true` means every agent-authored post waits for a human go before publishing. `social.proto` also carries an explicit `option go_package`. `SocialService.DeletePost` is drafts only.
- `proto/tank/board/v1/board.proto`: Neuralboards. A `Frame` can hold the running application (`AppFrame`), not just a picture of it — that is the product's point. `Board.staleness` (0 = current, 100 = nothing it was drawn from is still as it was). `Board.thread_root_id` marks the board as a thread's Workbench. `PutObjectsRequest.base_revs` prevents silent overwrites when two people edit different objects.
- `proto/tank/workspace/v1/workspace.proto` (719 lines) is the biggest file. `GetBootstrap` is its point: one call on app open, everything else lazy. Members cap at 200, which is the entire reason `ListMembersRequest.query` exists.
- `optional` is used throughout as deliberate presence for unchanged-field semantics — dropping it to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (managed mode supplies `go_package`). The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up automatically.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches numbering violations; only discipline catches premature removal.
