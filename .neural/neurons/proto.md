# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- `board` (Neuralboards), `books` (Neuralbooks) and `canvas` (Neuralcanvas) are the three tools the agent uses *alongside* people in the workspace, not just on their behalf — `board.proto`/`books.proto`/`canvas.proto` are the product surfaces (CRUD, reports, templates); `agentctl.proto`'s `RunnerService` carries the agent-shaped subset (`DrawOnBoard`, `BooksCreateInvoice`, `WriteUpThread`, ...) that corresponds 1:1 to the tools documented in this run's own system prompt.
- `remediation.proto` and `security.proto` are Neuralsecurity's two halves and must stay separate programs by design (remediation.proto's header): `security.v1` (messaging core) is the control registry that judges — `Control`/`Posture`/`FrameworkClause`, read-only except `Evaluate`; `remediation.v1` (agent control plane) is the engine that fixes, called across that boundary via `SubmitFinding`. Neither has an RPC for the other's job: the engine cannot touch a control, and the registry cannot run anything. A finding is idempotent on `(finding_id, control_version)`.
- `remediation.v1.Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` is only for a `Class` that is declared, `reversible` with a stated `undo`, and not `lockout_risk` — enforced by convention in the message shapes, not by the proto compiler.
- `security.v1.ControlState` has no success-by-default: `CHECK_KIND_NONE` can only ever read `NOT_YET`/`UNKNOWN`, and a stale `Evidence` (past `max_age_seconds`) always reports `UNKNOWN` rather than its last real answer — "a registry that flatters the system is worse than no registry."
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (721 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunPhase` drives the runner's permission mode. `StartRunRequest.mode = "neural"` (agent.proto) is this very refresh mechanism: it skips planning and works in `repo` whatever the Tread is bound to, and `RefreshNeuralKnowledgeRequest` is idempotent while one run is already active for that repository.
- `RunContext.skip_neural_knowledge` / `TreadSettings.read_neural_knowledge` is a kill switch for measuring this layer itself: a run with it set must not read or write `.neural/`, so an A/B of "with vs without Neural Knowledge" is possible on the same codebase.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, and subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, plus new `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}` for per-block/per-object collab events. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it. `Subscribe`/`Unsubscribe` now also take `canvas_ids`/`board_ids` — a client must subscribe to a page or board to see another person's edits to it at all.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- `proto/tank/board/v1/board.proto`'s `AppFrame` is the product's point: a frame can hold the *running application* at a commit, not a screenshot of one. `BoardObject.meta` is one deliberately opaque string for editor-only relationships (component instance, named style, auto-layout, pinning) so a renderer that understands none of it still draws the board correctly from the typed geometry/colour fields alone.
- `proto/tank/canvas/v1/canvas.proto`'s whole premise is in its header comment: a page remembers what it was written from (`Source`), and `staleness`/`staleness_note` say when that's gone stale instead of quietly lying. `Block.rev` / `Canvas.version` give per-block optimistic concurrency distinct from whole-page concurrency — editing one block never collides with editing another.
- `proto/tank/books/v1/books.proto`'s `Invoice.share_url`/`GetInvoiceRequest.rotate`: the share token is stored only as a hash, so an ordinary read always returns an empty `share_url` — it is readable back exactly once (on create/send) and `rotate` (admin-only) is the *only* recovery if a business loses the link, killing the old link the instant the new one is issued.
- `proto/tank/topo/v1/topo.proto` separates derived marks (always `MARK_STATUS_OPEN`, never stored, no `created_by_user_id`) from stored ones with a real lifecycle; only stored marks ever produce a `TopoMarkUpdated` event. `RecordEvent` is for first-party observers only and carries a `dedupe_key` because webhooks get redelivered. `GetBriefingResponse.hours`/`.setup` (new) back Home's day ring and first-week setup checklist.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `events` now imports `tank.board.v1` and `tank.canvas.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` (unless the file sets its own `option go_package`, as 9 files now do), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — it still only covers 14 of 27 packages.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
