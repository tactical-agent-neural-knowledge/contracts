# Neurons · proto

- 29 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." `CLAUDE.md`: "Wire names stay neutral (`Channel`, not `Tread`); product vocabulary lives in the clients."
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract: the in-sandbox runner talks to agent-control only, authenticated by the per-run `RUN_TOKEN`. `RunContext` (field 83) carries everything the runner needs: repo, branch, policy, thread excerpt, attachments, Workbench board id (`workbench_board_id` field 30), crew title and skill (`agent_title` field 28, `agent_skill` field 29), and channel purpose/goal for neural threads.
- `PolicySummary.tools_gate_destructive` (field 9 of `PolicySummary`, agentctl.proto) was absent until 2026-10-07 — its comment explains: patterns in every workspace policy that the runner must see to open the destructive-tool gate. A deny list the runner cannot see denies nothing.
- `proto/tank/agent/v1/agent.proto` holds `RunState`, `Run`, `TreadSettings`, `TreadMetrics`, and `HourBucket`. `TreadSettings.pull_requests` (field 5) takes "review" (default, mentions `pr_reviewer_ids`) or "merge_when_green" (TANK watches checks and merges). `TreadSettings.merge_allowed` (field 8) governs whether TANK may merge at all. `TreadSettings.strongest_model` (field 10) starts a run on Opus rather than the auto-escalation path. `HourBucket.neural_saved_usd` (field 4) and `TreadMetrics.neural_saved_month_usd` (field 11) / `neural_measured` (field 12) surface Neural Knowledge savings estimates.
- `proto/tank/crew/v1/crew.proto`: the Crew domain — a workspace's swarm of named agent members (`Member`), each with a role, handle, skill prompt, activity level, and spend caps. `CrewService` has ListCrew, AddMember, UpdateMember, RemoveMember. `Agent.title` and `Agent.skill` (agent.proto fields 6-7) are set from the Crew member for a crew run and empty for the workspace agent.
- `proto/tank/social/v1/social.proto`: the Flare domain — workspace voice on X and Instagram. `SocialService` covers ListAccounts, StartConnect, Disconnect, GetSettings, UpdateSettings, ListPosts, CreatePost, PublishPost, DeletePost. `Settings.review_required` gates every agent post as a draft until a person gives a go. The agentctl tools (`SocialAccountsRequest`, `SocialCreatePostRequest`, `SocialPublishPostRequest`) mirror this from the thread.
- `proto/tank/board/v1/board.proto`: Neuralboards. A `Frame` can hold the running application (`AppFrame`), not just a screenshot. `Board.thread_root_id` (field 14) marks the board as a thread's Workbench — at most one per thread. `CreateBoardRequest.thread_root_id` (field 7) sets it; `ListBoardsRequest.thread_root_id` (field 5) filters to it. `PutObjectsRequest.base_revs` (field 5) checks optimistic concurrency: a mismatch is reported as a conflict, never silently overwritten.
- `proto/tank/files/v1/files.proto`: `GetDownloadUrlRequest.inline` (field 2) asks for a browser-renderable URL; the server grants it only for safe MIME types (PDF, images, audio, video, plain text, office documents) and keeps everything else as a download regardless.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200; `ListMembersRequest.query` exists for that reason.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`. `AuditLogged` is internal — the gateway never fans it out.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default. `Event.cursor` is the JetStream sequence clients persist and replay with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set.
- `proto/tank/richtext/v1/richtext.proto` states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE).
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`; `admin` imports `tank.workspace.v1` and `tank.channel.v1`; `agentctl` imports `agent`, `blocks`, `board`, `books`, `canvas`, and `social`. Removing a field from any of those ripples to every importer's breaking check.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (or `npx --yes @bufbuild/buf generate`). Managed mode supplies `go_package`. Remember `gen/ts/src/index.ts` is hand-written and will not pick up the new domain automatically.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
