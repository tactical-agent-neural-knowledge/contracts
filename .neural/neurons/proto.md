# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 26 domains now (was 22): `board`, `books`, `canvas`, `remediation`, `security` are new. Same rule as before — one package per domain, `proto/tank/<domain>/v1/<domain>.proto`, package `tank.<domain>.v1`. All five changes landed purely additive: `git diff` against the last refresh shows 0 deletions across every proto file.
- `remediation.proto` and `security.proto` are the two halves of Neuralsecurity and must stay split: the registry (`security.proto`, judges, read-only apart from `Evaluate`) and the engine (`remediation.proto`, fixes, the only thing with write access) are deliberately different services so "a system that can mark its own homework" stays impossible. `RemediationService` has no RPC that changes a control, and `SecurityService` has no RPC that submits a finding — if a future change adds either, that is the boundary breaking, not a convenience.
- `remediation.proto:22-38` — four rules gate every remediation: propose-only by default (`Disposition.PROPOSE` is the zero-value's neighbour; `AUTO_APPLY` needs a declared, reversible `Class` with no `lockout_risk`), every fix carries its `test_requirement`, a finding fans out to every `Target` the pattern applies to, and every remediation names the `run_id` that drove it.
- `security.proto` posture model: `ControlState` has no "probably fine" — unmeasured is `NOT_YET`, a check that hasn't run recently is `UNKNOWN` (never its last answer), and `NOT_APPLICABLE`/`PARTLY` both require `reason`. A `FrameworkClause` maps onto a `Control` and is never a second set of facts; `ClauseCoverage.state` is derived (worst of its controls), never stored.
- `books.proto` keeps money as `int64` cents everywhere, never a float. `Settings.stripe_secret_key` is write-only (set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — the same shape as `Invoice.share_url`/`GetInvoiceRequest.rotate` on a get, which also never reads back the live link, only mints a new one.
- `canvas.proto` and `board.proto` share one pattern end to end: a `staleness`/`staleness_note` pair on the parent (`Canvas`, `Board`), a `Source`/`Derivation` message recording what it was drawn from and whether that `changed`/`moved_on`, and per-child revision numbers (`Block.rev`, `BoardObject.rev`) so two editors colliding on the same block/object is reported in the response rather than silently overwritten — editing different blocks/objects is never a conflict.
- `board.proto`'s one real distinguishing idea is `AppFrame` (board.proto:52): a frame can hold the *running application* at a commit, not a picture of one. `BoardObject.meta` (field 18, not adjacent to 17 — note the gap) is one opaque string for editor-only relationships (component instance, layout, pin) precisely so a renderer that doesn't understand it still draws the board correctly from the typed fields alone.
- Six domains now set `option go_package` explicitly instead of relying on managed mode's prefix (was five): `billing`, `catalog`, `monitor`, `platform`, `topo`, plus new arrivals `books`, `canvas`, `remediation`, `security` — that's actually nine now. Check `buf.gen.yaml`'s `go_package_prefix` before assuming a new domain needs this option; most don't.
- `gen/ts/src/index.ts` is still hand-written and still does not cover every domain — `board`, `books`, `canvas`, `remediation`, `security` joined `admin`, `billing`, `catalog`, `command`, `huddle`, `monitor`, `platform`, `topo` as absent. Adding a domain's proto does not add it to the barrel; a TS consumer needs the deep import.
- `agentctl.proto` grew three new RPC groups on `RunnerService`/`ControlService` this round: Neuralbooks-from-the-run (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`), Neuralcanvas-from-the-run (`WriteUpThread`/`ReadCanvas`/`AskCanvas`), and Neuralboards-from-the-run (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`). These are the runner's own request/response shapes (`BoardShape`, not `board.v1.BoardObject`) — the control plane translates, the runner never touches the domain types directly for writes.
- `agentctl.proto:328-399` (the "agent schema's own writes" block) is a deliberate anti-pattern fix: the messaging core was issuing INSERT/DELETE against `agent.*` tables it only has SELECT on, green only because CI's fixture over-grants. The fix is five narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`) — there is explicitly no generic "table + statement" RPC and the comment says there will not be one.
- `PolicySummary.tools_gate_destructive` (agentctl.proto) closes a real gap dated in the comment: before 2026-10-07 the destructive-tool gate patterns lived in policy and were evaluated by the control plane but never told to the sandbox, so the gate could never open and the command just ran. A deny list the runner cannot see denies nothing — worth remembering before trusting any gate field that isn't also plumbed into `PolicySummary`.
- Cross-package imports keep growing with the new domains: `events.proto` now imports `board.v1` and `canvas.v1` for `BoardObjectsChanged`/`CanvasBlockChanged` etc., and `agentctl.proto` imports `board.v1`, `books.v1`, `canvas.v1`. `buf.yaml`'s `breaking.use: [FILE]` means a field removed from any of these fails the breaking check in every file that merely imports it — the import list is the blast radius.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second. Note `BoardObject` already has a numbering gap at field 18 (`meta`) sitting before 16/17 in source order — fields are not declared in numeric order in this file, don't assume they are when scanning for a free number.
