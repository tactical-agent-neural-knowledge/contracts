# Neurons · proto

refreshed 2026-10-08 · b57522e4f7aa

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/agentctl/v1/agentctl.proto` is now the biggest file (1045 lines, was ~600) because every new product surface — Neuralboards, Neuralbooks, Neuralcanvas, remediation findings, decisions, session store, CI watch/failure, pull requests — got RPCs added to `RunService` rather than a new runner-facing service. It is still runner ↔ control-plane only, authenticated by the per-run `RUN_TOKEN`.
- `StartRunRequest.mode = "neural"` (agentctl.proto:118) is what this very refresh runs under: it skips planning and works in `repo` (field 8, required for that mode) regardless of what the Tread is bound to. `skip_neural_knowledge` (field 9/26) exists on both `StartRunRequest` and `RunContext` to run a task with the layer on or off for comparison.
- Trap: `RecordFinding` on `RunService` (agentctl.proto:307, used by `record_neuron`) is unrelated to `Finding` in `remediation.proto` — same English word, two different schemas (tool-research fact vs. security-control violation). Don't conflate them when grepping.
- `agentctl: the messaging core asks the control plane to write its schema` (commit a297744): `tank_app`'s DB role only has USAGE+SELECT on schema `agent`, so api cannot INSERT/DELETE into `agent.repo_bindings` etc. directly — those statements only ever passed in CI, where the test fixture grants itself DML. Six `ControlService` RPCs exist solely so api can ask agent-control to make specific, narrow writes instead: `BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`.
- `proto/tank/security/v1/security.proto` models one rule: controls are the primitive, frameworks (SOC 2 today) are views over them via `FrameworkClause` — never a second set of facts. `ControlState.NOT_APPLICABLE` and `.PARTLY` both require a `reason`, and a stale check reports `UNKNOWN` rather than replaying its last answer.
- `proto/tank/remediation/v1/remediation.proto` is the seam the registry (messaging core) and the fixer (agent control plane) talk across: nothing here lets the engine change a control or mark a finding resolved, and the engine is documented to refuse a remediation whose judge and fix principals are the same. Default disposition is propose-only (a PR a human merges); `AUTO_APPLY` is a declared, narrow `Class` list.
- `proto/tank/board/v1/board.proto` (549 lines) is the only new-domain file with no `option go_package` — it relies entirely on managed mode (`buf.gen.yaml`'s `go_package_prefix`), unlike `books`, `canvas`, `remediation`, `security`, which all set it explicitly like the five pre-existing holdouts (billing, catalog, monitor, platform, topo). Inconsistent but currently harmless since the path already matches the managed prefix.
- `Frame.app` in `board.proto` is the product idea of the domain: a frame can hold the *running application*, not a screenshot of one.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel."
- `optional` is used throughout as deliberate presence, not nullability (`ChannelReadState.unread_count`, `UpdateChannelRequest`, `TopoPreferences.configured`). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains (`buf.yaml`: `breaking.use: [FILE]`): `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
