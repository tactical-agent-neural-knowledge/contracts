# Neurons · proto

refreshed 2026-10-10 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1` (`CLAUDE.md`: "One proto package per domain, version suffix `v1`"). Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel."
- `remediation.proto` and `security.proto` share one design rule, stated in both files: nothing can mark its own homework. The control registry (judges, `security.proto`) and the remediation engine (fixes, `remediation.proto`) are deliberately two different programs; the engine never writes back to the registry, there is no RPC to resolve a finding or edit a control, and `Remediation.forbidden_paths` stops a run from touching the controls/probes/mappings that judge it.
- `agentctl.proto` is the cross-domain hub: it imports `agent`, `blocks`, `board`, `books`, `canvas` (not `remediation`/`security`). The Board/Books/Canvas RPCs it exposes (`ListBoards`, `BooksSummary`, `ReadCanvas`, …) only fire when `RunContext.product_run = true` — they are TANK's own product tools, never exposed to a customer run.
- `StartRunRequest.mode = "neural"` (agentctl.proto) is a Neural Knowledge refresh: it skips planning and works in `repo` regardless of what the Tread is bound to; `RefreshNeuralKnowledge` is idempotent — it reuses one standing thread per repo and reports `started=false` if a refresh is already running there.
- Documented trap in `agentctl.proto`: `PolicySummary.tools_gate_destructive` was absent until 2026-10-07, and its absence silently meant zero enforcement even though the control plane evaluated the pattern — "a deny list the runner cannot see denies nothing." `PolicySummary` is a mirror, not authoritative; the control plane stays the source of truth.
- `board.proto`'s `AppFrame` holds the *running application*, not a screenshot — the domain's whole differentiator. `BoardObject.rev` + `PutObjectsRequest.base_revs` give per-object optimistic concurrency; conflicts are reported back, never silently overwritten.
- `books.proto`: `Settings.stripe_secret_key` is write-only, read back only as a last-4 `stripe_key_hint`. An invoice's share token is stored as a hash — `share_url` reads back empty, and `rotate` (admin-only) is the only recovery path; the old link dies the instant a new one is issued.
- `canvas.proto`: `UpdateBlockRequest.base_rev` gives per-*block* (not per-page) optimistic concurrency, so two people editing different blocks never collide. `DecisionRecord` entries chain via `superseded_by_*` rather than ever being deleted.
- `optional` is used throughout as deliberate presence, not nullability: `ChannelReadState.unread_count` (use this, not the misleading `last_seq` arithmetic at channel.proto:44), `DecideBenchmarkRequest.supersedes_id` ("this replaces nothing"), `ListMembersRequest.deactivated` in admin.proto (unset = no filter). Dropping `optional` to tidy a field silently changes its meaning.
- `agent.proto`'s `TreadSettings`: `pull_requests` is `"review"` (default, posts + mentions `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges itself); `read_neural_knowledge` defaults on and the server always sets it explicitly, never leaves it unset.
- `admin.proto`'s new `EndMemberSessions` ends every session for a member without touching membership or bot/API tokens — previously the only way to force a signout was remove-then-re-add; `sessions_ended` lets a caller distinguish "worked" from "there were none."
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `agentctl` imports `agent`/`blocks`/`board`/`books`/`canvas`. The five newest domains (board, books, canvas, remediation, security) import only `google/protobuf/timestamp.proto` — no cross-domain coupling yet.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain on its own.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
