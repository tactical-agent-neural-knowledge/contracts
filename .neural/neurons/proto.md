# Neurons · proto

refreshed 2026-10-06 · 1d64b4097636

- 25 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. New since the last refresh: `board`, `books`, `canvas`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `option go_package` is now hand-set in 7 files, not 5: `billing`, `catalog`, `monitor`, `platform`, `topo`, plus the two newest, `books` and `canvas`. Everything else relies on `buf.gen.yaml`'s managed `go_package_prefix`; a hand-set path must still match that prefix exactly.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board whose point is `AppFrame` — a frame can hold the *running* application, not a screenshot. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pin, hidden) on purpose, so a renderer that doesn't understand a record still draws geometry and colour correctly and leaves it alone. `PutObjectsRequest.base_revs` + `BoardObject.rev` give last-write-wins per object with reported (not silent) conflicts.
- Board staleness is tracked two ways: `Board.staleness`/`staleness_note` (board vs. the product it documents) and `AppFrame.moved_on`/`drawn_from_sha` (one frame vs. what's deployed now) — don't confuse the two when reading either.
- `ReportPreviewRequest` (board.proto) is the escape hatch for a workspace that runs its own CI: it reports repo/ref/sha/url/retain_days itself rather than TANK building the preview, so a frame can point at a build TANK never touched.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry money kept by the agent, integer cents, `option go_package` already set (new domain, no `tank.<domain>.v1` managed surprises to debug). `Settings.stripe_secret_key` is write-only by convention (comment only, not enforced by proto): set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars — never round-trips the real key.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that cite what they were written from (threads, decisions, repos) and go stale when those move, same staleness idea as boards. `BlockKind` includes `LIVE` (a real figure, current when read) and `DECISION` (kept as structure, not prose) — a page author should prefer those over a text block when the content is actually one of them.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only, now 882 lines and the largest file by RPC count: 38 `RunnerService` methods plus `ControlService`. All ids stay Snowflake decimal strings. `StartRunRequest.mode = "neural"` skips planning and works in `repo` regardless of the Tread's binding — used for `RefreshNeuralKnowledgeRequest`, which keeps one standing thread per repository and is idempotent while a refresh is already running there.
- `RunContext.skip_neural_knowledge` and `StartRunRequest.skip_neural_knowledge` exist purely to measure the layer: run the same task with and without Neural Knowledge and compare. Don't read it as a user-facing toggle; `TreadSettings.read_neural_knowledge` (agent.proto) is the actual per-Tread setting, on by default, server-set.
- `TreadDeployment` (agent.proto) and `agentctl`'s `RegisterDeploymentRequest`/`GetDeploymentRequest` describe the same hosting state from two sides: `managed=true` means TANK generated the repo (`agenture-<slug>`) via `CreateTreadRepo`/`CreateProductRepo`; `managed=false` means the workspace brought its own repo and registered it with `RegisterDeployment`, carrying `.github/workflows/tank.yml` itself (`workflow_present`).
- `proto/tank/events/v1/events.proto` is still the NATS JetStream envelope (`Envelope.id` = `Nats-Msg-Id`, payload `google.protobuf.Any`), now importing `board` and `canvas` for `BoardObjectsChanged`/`BoardChanged`/`BoardPointer` and `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing`. Pointer/editing events are ephemeral (`typ.{ws}.board.{board}` / `typ.{ws}.canvas.{canvas}`) and never stored; the `*Changed` ones are the persisted, subscribable kind.
- `realtime.proto`'s `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids`: a client that never subscribes to a page or board never receives its live edits, same opt-in model as `channel_ids`/`thread_root_ids`.
- Cross-package imports still make FILE-level breaking bite across domains, and now reach further: `events` imports `board` and `canvas` on top of the existing `admin`→`workspace`/`channel` and `topo`/`search`→`message` edges. A field removed from `board.proto` or `canvas.proto` now fails the breaking check in `events.proto` too.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
