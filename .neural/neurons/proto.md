# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now, up from 22: `board`, `books`, `canvas`, `remediation` and `security` were added since the last refresh. Each is still one package, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `tank.books.v1` (Neuralbooks): double-entry bookkeeping surfaced as customers/invoices/payments/expenses/a cash summary, integer cents throughout. `Invoice.share_url` is a credential, not a readable field: `GetInvoiceRequest.rotate` (books.proto:155) mints a fresh link and kills the old one atomically — the token is stored as a hash, so an ordinary `GetInvoice` always returns an empty `share_url`, and a business that loses the link has no way to read it back, only to rotate it. `Settings.stripe_secret_key` follows the same write-only pattern (set it, send empty to leave it, read back only `stripe_key_hint`'s last four chars).
- `tank.board.v1` (Neuralboards): an infinite board where `Frame.app` (`AppFrame`) can hold the *running application*, not a picture of one — the product's whole differentiator. `BoardObject.rev` is bumped per write so concurrent edits are reported as `PutObjectsResponse.conflicts`, never silently overwritten. `BoardEmbedRequest.rotate`/`revoke` reuse the exact same share-link-is-a-credential pattern as `books.Invoice.share_url`. `Board.staleness`/`staleness_note` mirror `AppFrame.moved_on`/`moved_note` and `tank.canvas.v1.Canvas`'s own staleness field: three independent places in this schema model "this artifact says what was true once, and may no longer be."
- `tank.canvas.v1` (Neuralcanvas): pages that cite what they were written from — threads, decisions, repos — and say so when those move, rather than silently going stale. `BLOCK_KIND_DECISION` and `BLOCK_KIND_LIVE` are the two kinds that aren't static prose: a `Decision` is answerable (what/who/when/why/supersedes) and a `Live` block is filled in by the server at read time, so a canvas page is never stale about its own numbers even if it is stale about everything else.
- `tank.security.v1` (Neuralsecurity, read-only posture API): one rule decides the whole file — "controls are the primitive, frameworks are views over them." There is exactly one `Control` registry (owner, `CheckKind`, evidence, `ControlState`); a `FrameworkClause` (e.g. SOC 2 "CC6.1") only ever maps onto existing controls and never introduces a second set of facts. `ControlState.UNKNOWN` is forced whenever a check is stale or has never run — the registry reports "we don't know," never a flattering stale answer, because "every later phase reads from it." `SecurityService` is deliberately read-only apart from `Evaluate`, which only re-runs checks; nothing in it can mark its own homework.
- `tank.remediation.v1` is the seam between security's judge half and the fix half, and the seam is the point: the control registry (messaging core) decides what's wrong and calls `RemediationService.SubmitFinding`; the remediation engine (agent control plane, which owns the GitHub App/sandboxes/gate engine/flight recorder) is the only thing that can write code, and has no RPC to change a control, retire a probe or mark a finding resolved — "a system that can mark its own homework is not a security system." `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with a mandatory `test_requirement`, `reversible`+`undo`, and is categorically forbidden when `Class.lockout_risk` is true. `SubmitFinding` is idempotent on `(finding_id, control_version)` so a repeated hourly evaluation reopens nothing.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, the biggest file by far) is the runner ↔ control-plane contract, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings. It grew two new families of RPC this cycle: (1) `AgentCoreService` now also proxies every MCP tool used in this very workflow — `BooksSummary/CreateInvoice/RecordExpense/RecordPayment/Report`, `WriteUpThread/ReadCanvas/AskCanvas`, `ListBoards/ReadBoard/DrawOnBoard/ArrangeBoard` — so an agent run reaches books/canvas/board through agentctl rather than those services directly; (2) `ControlService` gained six narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) added specifically because the messaging core's Postgres role for schema `agent` is USAGE+SELECT only — it had been issuing raw INSERT/DELETE against `agent.repo_bindings` etc. that only ever passed in CI, where the test fixture over-grants itself DML. There is deliberately no generic "table + statement" RPC and there will not be one.
- `PolicySummary.tools_gate_destructive` (agentctl.proto, field 9, additive) carries `tools.gate.destructive_tool` patterns down to the runner. Before this field existed the policy had the rule and the control plane evaluated it, but nothing inside a sandbox could ever see it, so the gate could never open and the command just ran — "an absent control, not a weak one."
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`, subjects `evt.{ws}.ch.{channel}` / `.thread.{root}` / `.user.{uid}` / `.ws`, plus now `evt.{ws}.canvas.{canvas}` and `evt.{ws}.board.{board}` for `CanvasBlockChanged`/`CanvasChanged` and `BoardObjectsChanged`/`BoardChanged` — each a one-block or one-object delta so two people editing different parts of the same page/board see each other rather than fighting over a whole document. `AuditLogged` is internal — the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Subscribe`/`Unsubscribe` now carry `canvas_ids`/`board_ids` alongside channels and threads — a client only receives canvas/board deltas for pages it has explicitly opened. Cursor/pointer presence for both (`CanvasEditingFrame`, `BoardPointerFrame` client→server; `CanvasEditing`, `BoardPointer` server→client) is ephemeral, rate-limited like typing, and never stored; `BoardPointer.kind` is `"user" | "agent"` so an agent's own cursor renders distinctly while it draws alongside people.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- `proto/tank/topo/v1/topo.proto` separates derived marks (always `MARK_STATUS_OPEN`, never stored, no `created_by_user_id`) from stored ones with a real lifecycle; only stored marks ever produce a `TopoMarkUpdated` event. `GetBriefingResponse` grew `hours` (24 hourly message/run counts, for Home's day ring) and `setup` (`BriefingSetup`: goal_set/github_connected/agent_summoned/someone_invited/avatar_set/done — the first-week checklist Home shows until every flag is true).
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, `events` now also imports `tank.board.v1` and `tank.canvas.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` for most domains (the newest five set it explicitly instead, same as billing/catalog/monitor/platform/topo before them), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and does not pick up new domains automatically — none of board/books/canvas/remediation/security are in it yet.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
