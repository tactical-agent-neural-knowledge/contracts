# Neurons · proto

refreshed 2026-10-14 · 65c4439b3e7d

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `option go_package` is now explicit in 9 files, not 5: billing, books, canvas, catalog, monitor, platform, remediation, security, topo. Everything else relies on `buf.gen.yaml`'s managed `go_package_prefix`; a new domain only needs the explicit option if it must land somewhere the managed prefix wouldn't put it.
- `proto/tank/security/v1/security.proto` and `proto/tank/remediation/v1/remediation.proto` are a deliberately split pair: security.proto is the control registry (judges — `Control`, `ControlState`, `Evidence`, `Attestation`, read-only `SecurityService` except `Evaluate`) and remediation.proto is the fix engine (acts — `Remediation`, `Disposition`, `Class`). `remediation.proto:9`: "those two halves must not be the same program… A system that can mark its own homework is not a security system." `Remediation.judge_principal`/`fix_principal` must differ; `forbidden_paths` blocks a fix run from touching the controls that judged it.
- `remediation.proto` `Class.max_disposition` gates `DISPOSITION_AUTO_APPLY`: a class needs `reversible = true` and a stated `undo`, and `lockout_risk = true` forces `PROPOSE` regardless of what else the class declares. `SubmitFinding` is idempotent on `(finding_id, control_version)` so an hourly evaluation doesn't open a second pull request for the same finding.
- `proto/tank/agentctl/v1/agentctl.proto` is now the biggest file (1045 lines) because it re-exports slices of `board`, `books` and `canvas` as runner-facing RPCs (`BooksSummary`, `BooksCreateInvoice`, `DrawOnBoard`, `ArrangeBoard`, `ReadCanvas`, `AskCanvas`, …) — it imports all three and is the one file that pulls the new domains into the runner's vocabulary. `PolicySummary.tools_gate_destructive` (added 2026-10-07) is the first time the destructive-tool gate patterns are actually sent to the sandbox; before this field existed the control plane evaluated the gate but the runner was never told, so "the gate ran and the command still ran" was not a bug in enforcement, it was a missing field.
- `proto/tank/agentctl/v1/agentctl.proto`'s `RefreshNeuralKnowledgeRequest`/`RunContext.skip_neural_knowledge` are this very refresh mechanism as a contract: the control plane keeps one standing thread per repository for refreshes and the request is idempotent while one is active. `agent.v1.TreadSettings.read_neural_knowledge` is the per-Tread on/off switch, server-set, defaulting on.
- `proto/tank/agent/v1/agent.proto`'s `TreadSettings.pull_requests` ("review" | "merge_when_green") plus `pr_reviewer_ids` is the auto-merge setting: "review" posts the PR and mentions the reviewers, "merge_when_green" has TANK watch checks and merge. This is a Tread switchboard setting, not a TANK GitHub App setting.
- `proto/tank/board/v1/board.proto`'s point is `AppFrame`: a frame can hold the running application itself (not a screenshot) via `repo`/`ref`/`path`, and `drawn_from_sha` + server-filled `moved_on`/`moved_note` is how a board learns the product has moved past what it shows — the same staleness idea `Canvas.staleness` uses. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, auto-layout, pin) precisely so a renderer that doesn't understand it still draws the board correctly.
- `board.proto` and `canvas.proto` both use per-object optimistic concurrency the same way: a `rev`/`base_rev` (board: `PutObjectsRequest.base_revs` map; canvas: `UpdateBlockRequest.base_rev`) means a collision is reported with the other person's version (`conflicts`/`theirs`) rather than silently overwritten — never "last write wins" on these two domains.
- `proto/tank/canvas/v1/canvas.proto`'s `Decision` blocks feed `ListDecisions`/`DecisionRecord`: "what did we decide about X" is a stored query over every decision block in the workspace, not a text search, and a superseded decision carries forward who replaced it and when.
- `proto/tank/books/v1/books.proto`: `Invoice.share_url` is mint-once — the token is stored as a hash and cannot be read back, so `GetInvoiceRequest.rotate` (admin only) is the only recovery path for a lost link, and issuing a new one kills the old one immediately. `Settings.stripe_secret_key` is the same write-only pattern (set it, send empty to leave alone, read back only as `stripe_key_hint`'s last four chars).
- Cross-package imports keep growing and still make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas` on top of `agent`/`blocks`; `events` imports `board` and `canvas` on top of its existing list. A field removed from any of these fails the breaking check in every file that merely references it.
- `optional` is still deliberate-presence, not nullability, throughout: unchanged-field semantics in update requests, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`. Dropping it to tidy a field silently changes meaning.
- Never renumber or reuse a field number, never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
