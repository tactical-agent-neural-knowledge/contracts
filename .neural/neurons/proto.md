# Neurons · proto

refreshed 2026-10-14 · 3b1cc8caafe7

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five are new since the last refresh (2026-10-03): `board`, `books`, `canvas`, `remediation`, `security` — none of them are in `gen/ts/src/index.ts`'s hand-written barrel or README's package table yet (see `.neural/neurons/root.md`).
- `proto/tank/security/v1/security.proto` is Neuralsecurity's own schema, and its rule is stated at the top of the file: "**Controls are the primitive; frameworks are views over them.**" One `Control` per fact about the running system, with an owner, a `CheckKind` and an `Evidence` query; a `FrameworkClause` (SOC 2 today) maps onto controls and is never a second set of facts. `ControlState` is deliberately pessimistic — `NOT_YET` covers "probably true but we cannot evidence it", and a stale check reports `UNKNOWN` rather than repeating its last answer.
- `proto/tank/remediation/v1/remediation.proto` is the seam between the half that judges and the half that fixes, on purpose split across two systems: the control registry (messaging core) decides what's wrong and cannot run anything; the remediation engine (agent control plane) holds the sandboxes and gate engine and cannot change a control. `Remediation.judge_principal` / `fix_principal` must differ — "a system that can mark its own homework is not a security system" (`remediation.proto:19`).
- `remediation.proto`'s `Class.max_disposition` caps what a finding class may ever become; `AUTO_APPLY` additionally requires `reversible`, a non-empty `undo`, and `lockout_risk = false` — "the one failure mode a security fix must not have is becoming the outage" (`remediation.proto:150`). Every class also needs a `test_requirement`: no class registers without one.
- `remediation.proto`'s `SubmitFinding` is idempotent on `(finding_id, control_version)`: resubmitting returns the remediation already in flight instead of opening a second round of pull requests, which is what an hourly re-evaluation needs. `Remediation.forbidden_paths` blocks a fix run from touching the controls/probes/framework files that judge it.
- `proto/tank/board/v1/board.proto` (549 lines, the largest of the new domains) is Neuralboards: `AppFrame` holds a running application's repo/ref/route inside a board frame; `ExportBoard` can return a raster, a `BoardSlice`, or an embed link; `GenerateTest` turns a `FlowStep` journey through a running frame into a test; `DeriveDiagram` builds a `Board` from a `BoardSource` (schema tables, infra files) rather than a blank canvas.
- `proto/tank/books/v1/books.proto` is Neuralbooks: `Invoice`/`Payment`/`Expense`/`CashSummary` plus bank import (`ImportBankTransactionsRequest` → `MatchBankTransactionRequest` against an invoice or expense) and `ReadReceipt` (receipts read by the model). `GetInvoiceResponse`'s share link rotates via `rotate` on the update path (`books.proto:164`) — a workspace can invalidate a leaked link without voiding the invoice.
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages (`Canvas`) built from `Block`s (`BlockKind`: text, table, image, decision, live, …), each block independently revisable (`UpdateBlockRequest`). `WriteFromThread` turns a thread into a page; `Ask` answers a question by citing the pages it drew from (`Answer`/`Source`); `ListDecisions` is a standing ledger separate from ordinary blocks.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids Snowflake decimal strings. It now imports `board`, `books`, and `canvas` directly (`agentctl.proto:9-11`) — those three domains are reachable from inside a run. `RefreshNeuralKnowledge` keeps one standing thread per repository for refresh runs and is idempotent while one is active (`agentctl.proto:794`); this very refresh is that call.
- `StartRunRequest` carries `skip_neural_knowledge` (field 26) and `task_class` (field 27); `RunContext` repeats `skip_neural_knowledge` (field 9) — a run can opt out of reading/recording the repo's neural layer, and `task_class` lets the control plane route or budget by kind of work.
- `proto/tank/agent/v1/agent.proto`'s `TreadSettings` is the per-Tread switchboard: `pull_requests` is `"review"` (default: post the PR, mention `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges) — the setting a workspace admin wants for "don't make me merge manually" is already on the wire (`agent.proto:264-268`), not a TANK GitHub App setting. `read_neural_knowledge` defaults on and the server always sets it explicitly.
- `agent.proto`'s `TreadSecurity` (new, backs `ListTreadSecurity`) is what Neuralsecurity last found per connected Tread: `state` is one of `clean | findings | scanning | failed | unscanned`, plus `secrets`, `vulns_critical`, `vulns_high`, and the `sha` the counts are about. `CreateTreadRepo` / `SetTreadDeployment` manage a `TreadDeployment` — TANK generating and waking/sleeping a Tread's own app on TANK's cluster.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), empty-vs-unconfigured in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `topo`/`search` import `tank.message.v1`, `admin` imports `tank.workspace.v1`/`tank.channel.v1`, and now `agentctl` imports `agent`, `blocks`, `board`, `books`, `canvas`. A field removed from any of those fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen` (or `npx --yes @bufbuild/buf generate` — no `make` in this sandbox): managed mode supplies `go_package`, lint's `PACKAGE_VERSION_SUFFIX` exemption already applies. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — five domains are already missing from it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `buf breaking` catches the first; nothing but discipline catches the second.
