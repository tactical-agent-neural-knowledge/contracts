# Neurons · proto

refreshed 2026-10-11 · e52a377a71d9

- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same discipline in the new domains: `board.proto`'s `Board.channel_id` and `canvas.proto`'s `Canvas.channel_id` both mean "the Tread it belongs to", never named Tread on the wire.
- `proto/tank/board/v1/board.proto` is Neuralboards: an infinite board whose `Frame` (`AppFrame`) can hold the *running application* at a commit (`drawn_from_sha`/`moved_on`), not a screenshot. Every write is per-object (`PutObjectsRequest.base_revs` keyed by object id) so two people moving different shapes never collide — the only real collision is the same object twice, reported back in `conflicts`, never silently overwritten.
- `proto/tank/books/v1/books.proto` is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/a cash summary, amounts always integer cents. `Settings.stripe_secret_key` is write-only (set to store, empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — the same write-only-credential pattern as `Invoice`'s share-link rotation (`GetInvoiceRequest.rotate`, admin only, old link dies the instant the new one is issued).
- `proto/tank/canvas/v1/canvas.proto` is Neuralcanvas: pages that remember what they were written from (`Canvas.sources`, each with `changed`/`changed_note`) instead of quietly going stale. Writes are per-block (`UpdateBlockRequest.base_rev`), same collision-reporting shape as board's `PutObjects`. `BlockKind.BLOCK_KIND_LIVE` is a value the *server* fills at read time, never stored stale.
- `proto/tank/remediation/v1/remediation.proto` is the one boundary a finding crosses: the messaging core's control registry judges (never fixes), the agent control plane's remediation engine fixes (never judges a control). `RemediationService` deliberately has no RPC to change a control, retire a probe, or mark a finding resolved — read the file header before adding one. `Disposition` defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with `reversible=true`, an `undo`, and `lockout_risk=false`.
- `proto/tank/security/v1/security.proto` is Neuralsecurity's posture registry: `Control` is the one primitive, `FrameworkClause` (e.g. SOC 2) is a view over controls, never a second set of facts. `ControlState.UNKNOWN` is forced whenever a check is stale or has never run — a registry is never allowed to report its last answer past `max_age_seconds`, and a `ClauseCoverage.state` is always derived (worst of its controls), never stored.
- `proto/tank/agentctl/v1/agentctl.proto` gained a schema-boundary block (`BindChannelRepo`, `SetChannelRepoAccess`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`, …): the messaging core was issuing INSERT/DELETE directly against the control plane's `agent` schema (green only in CI, where the test fixture self-grants DML) — the fix is narrow RPCs, not a wider grant, and there will deliberately never be an RPC taking a table + a statement.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (field 9) is new and closes a real gap: the destructive-tool gate patterns existed in every workspace's policy and were evaluated control-plane side, but were never told to the sandboxed runner, so the gate could never open and the command just ran.
- `agentctl.proto StartRunRequest.skip_neural_knowledge` / `RunContext.skip_neural_knowledge` lets a run skip this repo's own Neural Knowledge read/write (for A/B measuring the layer); `agent.proto TreadSettings.read_neural_knowledge` is the Tread-level on/off the server always sets explicitly. `ControlService.RefreshNeuralKnowledge` is what fires on every default-branch push — it is idempotent while a refresh is already running for the repo.
- `agent.proto TreadSettings.pull_requests` is `"review"` (default: post + mention `pr_reviewer_ids`) or `"merge_when_green"` (TANK watches checks and merges) — this is the Tread-level auto-merge switch, read it before assuming one needs inventing.
- `realtime.proto`/`events.proto` extended the same WebSocket gateway for canvas and board: `Subscribe.canvas_ids`/`board_ids`, ephemeral `CanvasEditingFrame`/`BoardPointerFrame` (ClientFrame) mirrored by `CanvasEditing`/`BoardPointer` (ServerFrame) — never stored, rate-limited like typing. `BoardPointer.kind` is `"user" | "agent"` so the agent's own cursor renders distinctly while it works a board alongside people.
- Cross-package imports are real and make FILE-level breaking bite across domains: `agentctl` now imports `board`, `books` and `canvas`; `events` imports `board` and `canvas`; `topo`/`search` import `tank.message.v1`; `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from any imported file fails the breaking check in every file that merely references it.
- `optional` is used throughout as deliberate presence, not nullability (unchanged-field semantics, "this replaces nothing", empty-vs-unconfigured). Dropping it to tidy a field silently changes meaning — unchanged this refresh, still worth re-checking before touching an `optional` field.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
