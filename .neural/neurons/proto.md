# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains now (22 at the last refresh), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New this round: `board`, `books`, `canvas`, `remediation`, `security`. Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `proto/tank/agentctl/v1/agentctl.proto` (now 1045 lines) is the runner ↔ control-plane contract only; it has grown to carry three more surfaces the runner can call as the workspace's own agent: Neuralbooks (`BooksSummary`/`BooksCreateInvoice`/…), Neuralcanvas (`WriteUpThread`/`ReadCanvas`/`AskCanvas`) and Neuralboards (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`) — all on `RunnerService`, imported from `tank.books.v1`/`tank.canvas.v1`/`tank.board.v1`.
- Trap fixed this round, worth remembering the shape of: `PolicySummary.tools_gate_destructive` (field 9) was absent until 2026-10-07 — the destructive-tool deny patterns existed in every workspace's policy and the control plane evaluated them, but nothing inside the sandbox was ever told, so the gate the policy promised could not open and the command just ran. A policy field with no runner-visible counterpart is not enforced; check both sides when adding a gate.
- `ControlService` gained five narrow RPCs (`BindChannelRepo`, `UnbindChannelRepo`, `SetChannelRepoAccess`, `CreateGitHubConnectState`, `SetChannelAgentSettings`, `SetWorkspaceAgentPolicy`) solely because the messaging core has SELECT-only grants on schema `agent` but was issuing INSERT/DELETE against it directly — green only in CI, where the test fixture self-grants DML. The fix is deliberately a call per need, not a wider grant or a generic "run this statement" RPC; `SetWorkspaceAgentPolicy` only narrows a policy document, never widens it.
- `RunContext.skip_neural_knowledge` / `StartRunRequest.skip_neural_knowledge` / `RunContext.task_class` ("single_area" | "multi_area") are new and together let the control plane A/B a run with and without the Neural Knowledge layer, and route a one-file ask to a cheaper model without a plan stage. `agentctl.proto`'s `RefreshNeuralKnowledge` RPC is what drives the refresh you are reading right now: one standing thread per repository, idempotent while a refresh is already active.
- `events.proto` is the NATS JetStream envelope (`Envelope.id` is the `Nats-Msg-Id` idempotency key, payload is `google.protobuf.Any`). It now also carries Neuralcanvas/Neuralboards traffic: `evt.{ws}.canvas.{canvas}` / `evt.{ws}.board.{board}` for persisted changes (`CanvasBlockChanged`, `BoardObjectsChanged`, one object/block at a time so concurrent edits to different shapes don't collide), and ephemeral, never-stored `typ.{ws}.canvas.{canvas}` / `typ.{ws}.board.{board}` for `CanvasEditing` and `BoardPointer` (the agent's own cursor is `BoardPointer.kind = "agent"`).
- `realtime.proto`'s `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids` — a client must ask before another person's edit to a page or board arrives at all. `ClientFrame`/`ServerFrame` gained `CanvasEditingFrame`/`BoardPointerFrame`, rate-limited the same way `TypingFrame` already was.
- `optional` is used throughout as deliberate presence, not nullability: `Channel.last_seq`/`ChannelReadState.unread_count` disagree on paper (use `unread_count`; thread replies and deletes also consume a `channel_seq`), and the same pattern now appears in `remediation.proto`'s `Finding.control_state` (re-read, not trusted, before acting) and `security.proto`'s staleness fields (`Evidence.stale`, `Control.stale` — a check that hasn't run recently reports `UNKNOWN`, never its last answer).
- Neuralboards (`board.proto`) and Neuralcanvas (`canvas.proto`) share one concurrency pattern: write one shape/block at a time (`PutObjectsRequest`/`UpdateBlockRequest`) keyed by a per-object `rev`/`base_rev`, so two people editing different parts never collide and a real collision comes back as the other person's version rather than an overwrite. `BoardObject.meta` is deliberately one opaque string (not typed fields) for editor-only relationships — component instance, named style, layout, pin, visibility — so a renderer that only understands geometry and `Style` still draws the board correctly.
- Neuralbooks (`books.proto`): amounts are always integer cents; `Invoice.share_url` is mint-once — the token is stored as a hash and cannot be read back by anyone including TANK, so `GetInvoiceRequest.rotate` (admin only) is the only recovery when a business loses its link, and the old link dies the instant the new one is issued. `Settings.stripe_secret_key` is write-only the same way: send it to store it, read back only `stripe_key_hint` (last 4 chars).
- Neuralsecurity's two new files enforce a judge/fix separation at the schema level, not just by convention: `security.proto`'s `SecurityService` (registry of `Control`s, one set of facts; frameworks like SOC 2 are `FrameworkClause` views over them) is read-only except `Evaluate`, which only re-runs checks. `remediation.proto`'s `RemediationService` (agent control plane) can act on a `Finding` the registry submits but has no RPC to edit a control, retire a probe or mark a finding resolved — "a system that can mark its own homework is not a security system" (remediation.proto:19). `Class.lockout_risk` forces `DISPOSITION_PROPOSE` regardless of what else a fix class declares; `DISPOSITION_AUTO_APPLY` requires `reversible` + `undo` on the class.
- `proto/tank/topo/v1/topo.proto`'s `GetBriefingResponse` gained `BriefingHour` (Home's 24h day ring: messages + agent runs per hour) and `BriefingSetup` (the first-week checklist: goal set, GitHub connected, agent summoned, someone invited, avatar set); `workspace.proto`'s `HomeLayout.setup_hidden` is the person dismissing that checklist.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`, and now `events.proto` imports `tank.board.v1` + `tank.canvas.v1` while `agentctl.proto` imports `tank.board.v1` + `tank.books.v1` + `tank.canvas.v1`. A field removed from any of those fails the breaking check in every file that merely references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
