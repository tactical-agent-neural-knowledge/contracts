# Neurons · proto

refreshed 2026-10-07 · 77435ec229ee

- 25 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1` (`board`, `books`, `canvas` are new since the last refresh, alongside the original 22). `CLAUDE.md`: "One proto package per domain, version suffix `v1`."
- `proto/tank/agentctl/v1/agentctl.proto` (913 lines, the largest file) now imports `agent`, `blocks`, `board`, `books` and `canvas` — it is the cross-domain hub, so a FILE-level breaking change in any of those five also fails `make breaking` here even when agentctl's own wire is untouched.
- agentctl holds two services with different auth, not one: `RunnerService` (in-sandbox runner, per-run `RUN_TOKEN`) and `ControlService` (operator/product surface — run panel, slash commands, GitOps deploys — service token, never `RUN_TOKEN`). The top-of-file comment only describes the former.
- `RunnerService`'s board/books/canvas RPCs (`DrawOnBoard`, `BooksCreateInvoice`, `WriteUpThread`, …) are the agent's narrow MCP-shaped surface — purpose-built request/response messages, not the full `BoardService`/`BooksService`/`CanvasService` RPCs reused. Widening what the runner can do means adding a message here, not exposing more of the owning domain's service.
- `proto/tank/board/v1/board.proto` (549 lines): a `Board` is `BoardObject`s with revision numbers (`rev`) for per-object optimistic concurrency, `AppFrame` can hold a *running* application (not a screenshot) and tracks `drawn_from_sha`/`moved_on` staleness, and `Derivation` carries the same staleness idea for diagrams drawn from a reported ERD/architecture source. `BoardObject.meta` is one opaque string for editor-only relationships (component instance, named style, layout, pin) deliberately, so a renderer that ignores it still draws correctly.
- `tank.board.v1.ReportPreviewRequest` / `ReportBoardSourceRequest` exist so a workspace's own CI tells TANK where a build or schema already is — board.proto says plainly why: TANK holding a database credential or reaching into a customer's VPC is a liability. Never add a field that would make TANK poll a workspace's infrastructure directly.
- `proto/tank/books/v1/books.proto`: `Settings.stripe_secret_key` is write-only by convention — set it to store it, send empty to leave it alone, read it back only as `stripe_key_hint` (last four chars). Never add a getter that returns the raw key.
- `proto/tank/books/v1/books.proto` amounts are integer cents in the workspace's currency throughout (`Invoice`, `Payment`, `Expense`, `Report`); there is no float money field anywhere in the package — add new amount fields as `int64 ..._cents`.
- `proto/tank/canvas/v1/canvas.proto`: pages are per-block revisioned (`Block.rev`, checked via `UpdateBlockRequest.base_rev`) the same way boards are per-object revisioned — the two domains share the optimistic-concurrency shape but not a message. `Block.live` (kind `books.cash`, `radar.widget`, etc.) is filled in by the server at read time so a page is never stale about its own numbers; `Block.decision` carries `needs_revisiting` for when something it rested on has changed.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest domain file (721 lines) and `GetBootstrap` is still its point: one call on app open, everything else lazy.
- `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel" (`CLAUDE.md`'s neutral-wire-names rule, verbatim in the proto). `Channel.last_seq`'s comment claims `unread = last_seq - last_read_seq`; `ChannelReadState.unread_count` (optional, so "server said zero" is distinguishable from an old server saying nothing) is the one to trust — thread replies and deletes also consume a `channel_seq`.
- `option go_package` is now hand-set in 7 files, not 5: `billing`, `books`, `canvas`, `catalog`, `monitor`, `platform`, `topo`. Every other domain relies on `buf.gen.yaml`'s managed `go_package_prefix`; a hand-written option must match that prefix exactly or `gen/go` lands in the wrong directory.
- `gen/ts/src/index.ts` is a hand-maintained barrel and still only covers 14 of the now-25 packages — `board`, `books` and `canvas` are absent from it along with the original 8 gaps (`admin`, `billing`, `catalog`, `command`, `huddle`, `monitor`, `platform`, `topo`). Adding a proto domain never adds it to the barrel automatically.
- Cross-package imports make FILE-level breaking bite across domains beyond agentctl too: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from an imported file fails the breaking check in every file that references it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
