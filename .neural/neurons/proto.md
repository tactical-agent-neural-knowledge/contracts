# Neurons · proto

refreshed 2026-10-14 · 3b1cc8caafe7

- 27 domains now (five added since the last refresh: board, books, canvas, remediation, security), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." `Treads` elsewhere (`TreadSecurity`, `TreadDeployment`, `RunContext.channel_id`) are a comment-level name for the same wire type, not a second message.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract and the aggregator for every in-run tool surface: it imports `agent`, `blocks`, `board`, `books` and `canvas` and `RunnerService` exposes board (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`), books (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`) and canvas (`ReadCanvas`/`AskCanvas`/`WriteUpThread`) as runner RPCs distinct from each domain's own service. `security` and `remediation` are **not** imported here — the runner cannot call either; they are control-plane/console-only surfaces so far.
- `RunContext.task_class` (agentctl.proto:124, added this cycle) is how the control plane cheapens a run before it starts: `"single_area"` skips the plan stage and uses the cheaper model, `"multi_area"` does not; empty on older runs and special modes. `RunContext.skip_neural_knowledge` (same message) is true when a Tread turned Neural Knowledge off or the run is a measurement control — this refresh's own run has it false by definition.
- `ControlService.RefreshNeuralKnowledge` (agentctl.proto) is what triggers a run like this one: idempotent per repository (`started=false` if one is already active), and it keeps one standing thread per repository rather than opening a new one each push.
- `proto/tank/board/v1/board.proto` (new, 549 lines): Neuralboards, an infinite board whose `Frame` (`OBJECT_KIND_FRAME`) can hold the *running application*, not a picture of one — that's its entire reason to exist next to Neuralcanvas. `BoardService` covers boards, templates, export (raster/slice/embed), previews of a connected app, and `DeriveDiagram`.
- `proto/tank/books/v1/books.proto` (new, 343 lines): Neuralbooks, double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary, amounts always integer cents. `Settings.stripe_secret_key` is write-only by convention — set it to store, send empty to leave alone, read back only `stripe_key_hint` (last four chars); the field itself is never round-tripped.
- `proto/tank/canvas/v1/canvas.proto` (new, 302 lines): Neuralcanvas pages cite what they were written from (threads, decisions, repos) and go stale when the source moves — `BLOCK_KIND_LIVE` and `BLOCK_KIND_DECISION` are the structural blocks that make that possible, not just a paragraph saying so.
- `proto/tank/remediation/v1/remediation.proto` (new, 298 lines) and `proto/tank/security/v1/security.proto` (new, 262 lines) are a deliberately split pair: security's registry judges ("Controls are the primitive; frameworks are views over them" — a framework like SOC 2 is a `FrameworkClause` mapping onto Controls, never a second set of facts), remediation's engine is the only thing that writes code and runs via `SubmitFindingRequest` across that boundary. Four hard rules in the remediation header: propose-only by default (AUTO_APPLY is a short, declared exception list), every fix carries its own required regression test, a finding fixes the class not the instance (fans out to every repo/workspace the check applies to), and every remediation names the run that drove it.
- `security.proto`'s `ControlState` has two "we don't know" states on purpose: `NOT_YET` ("probably true but we cannot evidence it") vs `UNKNOWN` (the check itself is stale or never ran) — a stale check must report `UNKNOWN`, never repeat its last answer, because "a registry that flatters the system is worse than no registry."
- `agent.proto`'s `TreadSecurity` / `ListTreadSecurityRequest` (new this cycle) is the read-model Home uses: one row per Tread with a bound repo, state ∈ `clean|findings|scanning|failed|unscanned`, keyed to the scanned commit's `sha`. A Tread with no repo bound is simply absent from the list, not present with a zero state.
- `realtime.proto` grew live-presence frames to match: `CanvasEditingFrame` ("I am in this page, in this block") and `BoardPointerFrame` (cursor + selection) are rate-limited like `TypingFrame` and never stored; `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids` so a client only gets another person's edit on a page or board it has actually opened.
- Cross-package imports still make FILE-level breaking bite across domains, and the graph is wider now: `events.proto` alone imports nine other domains (admin, agent, blocks, board, canvas, channel, files, huddle, message, monitor, presence, topo, workspace) to build its fan-out envelope — board and canvas events exist on the wire, books/remediation/security do not yet. A field removed from any imported file fails the breaking check everywhere it's referenced.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
