# Neurons · proto

refreshed 2026-10-08 · a887d51f4d82

- 27 domains now (was 22), one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." New since the last refresh: `board`, `books`, `canvas`, `remediation`, `security`.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." Same pattern elsewhere: `tank.board.v1` is Neuralboards, `tank.books.v1` is Neuralbooks, `tank.canvas.v1` is Neuralcanvas — the file header names the product, the package name never does.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not as nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/agentctl/v1/agentctl.proto` is the biggest file (1045 lines, the single largest addition this refresh at +372 lines) and the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, all ids are Snowflake decimal strings. It holds two services: `RunnerService` (everything a sandboxed run calls — PostToThread, PostPlan, AskForApproval, the Books/Board/Canvas RPCs, StreamEvents) and `ControlService` (operator surface: StartRun, DecideGate, repo binding, product-repo provisioning — authenticated with a service token, never a RUN_TOKEN).
- `PolicySummary.tools_gate_destructive` (agentctl.proto:69) is a comment worth reading before touching policy fields: it was absent until 2026-10-07 and its absence "was not a weak control but no control at all" — a deny list the runner cannot see denies nothing. Any new policy/gate field needs the same round-trip into the runner, not just evaluation in the control plane.
- `RunContext.skip_neural_knowledge` / `StartRunRequest.skip_neural_knowledge` (agentctl.proto) exist so a run can be done *without* reading or writing this very layer — "for measuring the layer: the same task with and without it." If you're ever debugging why a run didn't touch `.neural/`, check this flag before the refresh pipeline.
- `proto/tank/board/v1/board.proto` (new, 549 lines) is Neuralboards: an infinite board where a `Frame` can hold the *running application*, not a picture of one (`AppFrame`), which is what separates it from every other canvas/whiteboard. `BoardService` also covers templates, exports (raster/slice/embed), preview workflows and diagram derivation from a live app.
- `proto/tank/books/v1/books.proto` (new, 343 lines) is Neuralbooks: double-entry bookkeeping surfaced as customers/invoices/payments/expenses/cash-summary, amounts always integer cents in the workspace's currency. It is the one new-domain file that still writes an explicit `option go_package` despite managed mode already supplying one.
- `proto/tank/canvas/v1/canvas.proto` (new, 302 lines) is Neuralcanvas: pages that cite the threads/decisions/repos they were written from and say so when those move — "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true" (canvas.proto:9-13).
- `proto/tank/remediation/v1/remediation.proto` (new, 298 lines) and `proto/tank/security/v1/security.proto` (new, 262 lines) are a deliberately split pair: security.proto's Control/FrameworkClause registry ("controls are the primitive; frameworks are views over them") lives in the messaging core and decides what's true; remediation.proto's engine lives in the agent control plane and holds the GitHub App, sandboxes and gates. The file header calls this split "the seam between the half that judges and the half that fixes" and says the two halves "must not be the same program" — don't merge them for convenience.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is a `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`. It now imports `board`, `canvas` and the rest of the new domains too — `AuditLogged` is internal and the gateway never fans it out to clients.
- `proto/tank/realtime/v1/realtime.proto` is the WebSocket gateway, binary protobuf by default (`?enc=json` only for debugging). `Event.cursor` is the JetStream stream sequence the client persists and replays with `Resume`; `PresenceSubscribe` caps at 500 ids and *replaces* the set rather than adding to it.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `events` now imports nine other packages (admin, agent, blocks, board, canvas, channel, files, huddle, message, monitor, presence, topo, workspace), `agentctl` imports agent/blocks/board/books/canvas. A field removed from any of those fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package`, and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up — none of `board`, `books`, `canvas`, `remediation`, `security` are in it yet.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
