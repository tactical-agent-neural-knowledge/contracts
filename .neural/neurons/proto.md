- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` — all already carry an explicit `option go_package` (as do the older `billing`, `catalog`, `monitor`, `platform`, `topo`), so 9 of 27 opt out of managed mode's prefix.
- `gen/ts/src/index.ts` is hand-written and still only covers 14 of 27 packages; none of the 5 new domains were added to it. Adding a domain's barrel export is a manual step `make gen` will never do for you — check this file whenever a TS consumer complains an import is missing.
- `proto/tank/remediation/v1/remediation.proto:9` and `proto/tank/security/v1/security.proto:9` are a deliberate split, Neuralsecurity's judge/fixer seam: `security` (the control registry) states what is wrong, `remediation` (the agent control plane) is the only thing that writes code, and neither service has an RPC for the other's job — `RemediationService` has no method to change a control, and `SecurityService` is read-only apart from `Evaluate` (re-running checks, never grading itself).
- `remediation.proto` disposition defaults to `PROPOSE` (a PR a human merges); `AUTO_APPLY` requires a declared `Class` with `reversible=true`, an `undo`, and `lockout_risk=false` — a class that could lock an operator out can never be auto-applied regardless of what else it declares.
- `security.proto`'s `ControlState` has no state meaning "probably fine": unmeasured is `NOT_YET`, and a check that hasn't run recently (past `max_age_seconds`) reports `UNKNOWN` rather than its last answer — a stale check is never silently green.
- `board.proto`'s whole point is `AppFrame` (board.proto:52): a frame can hold the *running* application, not a screenshot — `drawn_from_sha` plus server-filled `moved_on`/`moved_note` is how a board learns the product has moved past it, same `staleness`/`staleness_note` idea as `Canvas`.
- `canvas.proto`'s `Live` block (canvas.proto:59) is filled in by the server on every read, never stored — the value in a `BLOCK_KIND_LIVE` block is always current, unlike `BLOCK_KIND_MESSAGE`'s quoted snapshot.
- Collaborative edits on both `board` and `canvas` are optimistic-concurrency, object/block-level, not whole-document: `PutObjectsRequest.base_revs` / `UpdateBlockRequest.base_rev` report a conflict with the other person's version rather than overwriting or locking.
- `events.proto` and `realtime.proto` grew matching pairs for both new surfaces: `CanvasBlockChanged`/`CanvasChanged`/`CanvasEditing` and `BoardObjectsChanged`/`BoardChanged`/`BoardPointer`, mirrored into `realtime.proto`'s `Subscribe`/`ClientFrame`/`ServerFrame` as `canvas_ids`/`board_ids` and `CanvasEditingFrame`/`BoardPointerFrame`. The `*Editing`/`*Pointer` messages are ephemeral (presence-like, on `typ.*` subjects) and never stored.
- `agentctl.proto`'s `PolicySummary.tools_gate_destructive` (added this refresh) is noted in its own comment as closing a real gap: the control plane evaluated `tools.gate.destructive_tool` patterns but never told the sandboxed runner about them, so the gate the policy promised silently never opened. Don't add a policy field here without checking the runner actually reads it.
- `agentctl.proto`'s `RunnerService` now proxies Neuralbooks (`BooksSummary`/`BooksCreateInvoice`/`BooksRecordExpense`/`BooksRecordPayment`/`BooksReport`), Neuralcanvas (`WriteUpThread`/`ReadCanvas`/`AskCanvas`) and Neuralboards (`ListBoards`/`ReadBoard`/`DrawOnBoard`/`ArrangeBoard`) — the in-sandbox runner never calls `books`/`canvas`/`board` services directly, only through this control-plane seam, same as everything else in `agentctl`.
- `ControlService.RefreshNeuralKnowledge` is idempotent per repository ("started: false when a refresh was already running") and keeps one standing thread per repo — it is what fires this very refresh.
- Product vocabulary never reaches the wire: `channel.proto:7`, a Channel "is presented as a 'Tread'"; the same discipline extends to the new domains — `tank.board.v1`/`tank.canvas.v1` name nothing after the product. `optional` is still used for deliberate presence, not nullability (`UpdateChannelRequest`, `DecideBenchmarkRequest.supersedes_id`, `TopoPreferences.configured`); dropping it to tidy a field silently changes meaning.
- Cross-package imports still make FILE-level breaking bite across domains, and now include the newcomers: `events` imports `board` and `canvas`; `agentctl` imports `board`, `books`, `canvas`; `topo`/`search`/`admin` import as before. A field removed from an imported file fails breaking checks in every file that merely references it.
- Never renumber or reuse a field number, never remove one before every client has shipped without it (`CLAUDE.md`). `make breaking` catches the first; nothing but discipline catches the second.
