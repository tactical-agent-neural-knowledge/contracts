- 27 domains now, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. Five are new since the last refresh: `board`, `books`, `canvas`, `remediation`, `security` — all added in the last week of commits.
- `gen/ts/src/index.ts` is a hand-written barrel and still only covers 14 of the 27 packages; none of the five new domains were added to it. Deep imports (`./tank/board/v1/board_pb.js`) are the only way to reach them from TS today.
- `proto/tank/security/v1/security.proto` and `proto/tank/remediation/v1/remediation.proto` are a deliberate split, not a naming accident: the registry (security.proto, in the messaging core) decides what is wrong, the engine (remediation.proto, in the agent control plane) is the only thing that can write code. `remediation.proto:17-19`: "The registry submits a finding across this boundary; it cannot run anything, and the engine cannot change a control... A system that can mark its own homework is not a security system."
- `security.proto`'s one rule: "Controls are the primitive; frameworks are views over them" (line 11) — one set of facts (`Control`), frameworks (`FrameworkClause`) map onto them, never a second set of facts. A control with no evidence reports `NOT_YET` even when everyone is sure it holds, and `ClauseCoverage` state is always derived (worst of its controls), never stored.
- `remediation.proto` defaults to propose-only: `Remediation.severity` defaults to `PROPOSE`, and `AUTO_APPLY` is restricted to a short declared `Class` list with each fix's reverse written down (`ListClassesRequest` exists so a buyer's security team can see exactly those four things). `SubmitFinding` is idempotent on `(finding_id, control_version)` because an hourly evaluation must not open duplicate PRs.
- `proto/tank/board/v1/board.proto:50-52`: `AppFrame` holds the running application itself, not a screenshot — the thing a board can hold that every other canvas tool can't. `BoardSource`/`ReportPreview` are deliberately the same request shape: a workspace's own CI reports what it knows (preview URL, schema, infra files) rather than TANK holding a credential and reaching into their network.
- `proto/tank/books/v1/books.proto:11-12`: double-entry bookkeeping underneath, integer cents in the workspace's currency, Snowflake string ids throughout. `Invoice.share_url` is a rotatable credential — readable by anyone who has it, exactly like a board embed link — not a signed-once value.
- `proto/tank/canvas/v1/canvas.proto:11-14`: a page cites what it was written from (threads, decisions, repos) and says so when that source has moved — "the failure of every wiki is not that writing is hard, it is that nobody can tell what is still true." `Live` values (canvas.proto:57-59) are filled in by the server on read, so a canvas block is never stale about its own data; `UpdateBlockRequest` edits one block so two people writing different parts of a page never conflict.
- `proto/tank/agentctl/v1/agentctl.proto` grew by 372 lines this cycle: `RefreshNeuralKnowledge` (line 794/819 — this very refresh's RPC), `skip_neural_knowledge` on `StartRun`/`RunContext`/`OpenThread`, and `task_class` on `RunContext`. `TreadSettings.mode` (agentctl.proto:53) is `"propose_only" | "can_merge"` — the PR review-vs-merge switch mirrored on the Tread side as `TreadSettings.pull_requests`.
- Unread-count trap, still live: `Channel.last_seq` (channel.proto:44) says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that's wrong — thread replies and deletes also consume a `channel_seq`. Use `unread_count`.
- `optional` is deliberate presence, not nullability, throughout: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id`, empty-vs-unconfigured in `TopoPreferences.configured`. Dropping it to tidy a field silently changes meaning.
- Cross-package imports make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1` and `tank.channel.v1`. A field removed from `message.proto` fails the breaking check in files that merely reference it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
