# Neurons · proto

refreshed 2026-10-06 · fb6e2ffe6678

- 25 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- Three domains are new since the last refresh: `board` (Neuralboards, an infinite canvas with a frame that can hold the running app), `books` (Neuralbooks, double-entry bookkeeping: customers, invoices, payments, expenses, cash/report summaries), `canvas` (Neuralcanvas, pages that cite the threads/decisions/repos they were written from and flag when those move).
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- Unread-count trap, and the two comments disagree: `Channel.last_seq` (channel.proto:44) still says "unread = last_seq - last_read_seq", while `ChannelReadState.unread_count` (channel.proto:77-85) documents why that arithmetic is wrong — thread replies and deleted messages also consume a `channel_seq`. Use `unread_count`; it is `optional` so a client can tell "server said zero" from an older server saying nothing.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest` / `SetChannelPreferenceRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), and the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is the biggest file (723 lines) and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists. `HomeLayout.setup_hidden` (new) is the one bit of state behind Home's first-week setup cards.
- `board.proto` and `canvas.proto` share one shape of collaborative write: whole-object (`BoardObject`/`Block`) writes carry a per-object `rev`, and a write includes the `rev` the editor started from (`base_revs` / `base_rev`); a mismatch comes back as a `conflicts`/`conflict` field with the other side's version rather than silently overwriting it. Both also share `staleness` (0..100) + `staleness_note` for "the thing this was built from has moved on."
- `board.proto`'s `AppFrame` is the actual product surface: a frame can show the running app at a commit (`drawn_from_sha`), not a picture of one; `ReportPreviewRequest`/`ListPreviews`/`ForgetPreview` let a workspace's *own* CI tell TANK where a build lives instead of TANK needing to own the pipeline. `BoardObject.meta` is deliberately one opaque string (component instance, style, layout, pin, visibility) rather than a field each, so a renderer that doesn't understand the editor's vocabulary still draws geometry correctly.
- `books.proto`: `Settings.stripe_secret_key` is write-only by convention (set to store, send empty to leave alone, read back only as `stripe_key_hint`'s last four chars) — there is no `GetSecret`-shaped RPC, and a client expecting to echo the key back will get nothing. All money is integer cents (`*_cents` fields); `InvoiceLine.total_cents` is server-computed, never trust a client-sent value for it.
- `agentctl.proto` now imports `board`, `books` and `canvas` to give the in-sandbox runner thin pass-through RPCs on `RunnerService` (`BooksSummary`, `BooksCreateInvoice`, `WriteUpThread`, `DrawOnBoard`, …) scoped to the current run's workspace/thread — the runner never calls `BoardService`/`BooksService`/`CanvasService` directly, only `agentctl`'s wrappers of them.
- `proto/tank/agentctl/v1/agentctl.proto` is the runner ↔ control-plane contract only: the in-sandbox runner talks to agent-control and never to the messaging core, authenticated by the per-run `RUN_TOKEN`, and all ids are Snowflake decimal strings. `RunContext.task_class` (new) is `"single_area"` vs `"multi_area"` and is empty on older runs; `RunContext.skip_neural_knowledge` / `StartRunRequest.skip_neural_knowledge` (new) exist purely to measure this very Neural Knowledge layer's effect, A/B on the same task.
- `ControlService.RefreshNeuralKnowledge` (new) is what reruns this refresh: it finds a Tread with access to the repo, keeps one standing thread per repository, and is idempotent while a refresh is already active — a second trigger while one is running is a no-op, not a second run.
- `agent.proto`'s `SetUpRepoPreviews` / `CreateTreadRepo` / `SetTreadDeployment` (new) are the hosting surface: TANK can generate a repo (`CreateTreadRepo`, premium + admin only) or wire previews into a repo the workspace already owns via a pull request it opens itself — "never a push: a workflow file in somebody else's repository is their decision." `TreadDeployment.managed` tells the two cases apart.
- `proto/tank/events/v1/events.proto` is the NATS JetStream envelope: `Envelope.id` is the `Nats-Msg-Id` idempotency key, the payload is `google.protobuf.Any`, subjects are `evt.{ws}.ch.{channel}`, `.thread.{root}`, `.user.{uid}`, `.ws`, and now also `evt.{ws}.board.{board}` / `evt.{ws}.canvas.{canvas}` plus ephemeral `typ.{ws}.board.{board}` / `typ.{ws}.canvas.{canvas}` for cursors and editing presence (`BoardPointer`, `CanvasEditing` — never stored). `AuditLogged` is internal — the gateway never fans it out to clients.
- `realtime.proto`'s `Subscribe`/`Unsubscribe` gained `canvas_ids`/`board_ids` (new): a client must opt a page or board in before it receives that object's live edits — opening one without subscribing means edits never arrive.
- `proto/tank/richtext/v1/richtext.proto` holds the `RichText` AST and states the rule plainly: "Markdown is never the storage format." Anything accepting user-authored text should take `RichText`, not a string.
- `proto/tank/blocks/v1/blocks.proto` is the agent UI vocabulary — `PlanCard`, `DiffPreview`, `CiStatus`, `ApprovalPrompt`, `ToolLog`, `StatusCard`, `FilePreview` — plus `GateKind` (PLAN, SCOPE_CHANGE, MERGE, DEPLOY, DESTRUCTIVE_TOOL, BUDGET_INCREASE). A `BlockAction` travels client → server → owning agent as an event, not as an RPC.
- Cross-package imports are real and make FILE-level breaking bite across domains: `topo` and `search` import `tank.message.v1`, `admin` imports `tank.workspace.v1`/`tank.channel.v1`, and now `agentctl`/`events` import `board`/`books`/`canvas`. A field removed from any of those fails the breaking check in every file that merely references it.
- Adding a domain needs only a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless you write one (see `books`/`canvas`), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. Remember the TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick it up.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
