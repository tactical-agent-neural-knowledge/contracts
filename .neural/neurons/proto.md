# Neurons · proto

refreshed 2026-10-09 · e52a377a71d9

- 27 domains, one package each, always `proto/tank/<domain>/v1/<domain>.proto` with package `tank.<domain>.v1`. `CLAUDE.md`: "One proto package per domain, version suffix `v1`." Generated Go lands at `gen/go/tank/<domain>/v1/` with the Connect client in a `<domain>v1connect/` subpackage.
- `proto/tank/agentctl/v1/agentctl.proto` (1045 lines, the biggest file) is two services: `RunnerService` is every tool a sandboxed agent run can call — `PostToThread`, `PostPlan`, `AskForApproval`, `BooksSummary`/`BooksCreateInvoice`/etc., `ReadBoard`/`DrawOnBoard`/`ArrangeBoard`, `ReadCanvas`/`AskCanvas`, `OpenPullRequest`, `Remember` — authenticated by the per-run `RUN_TOKEN`, never the messaging core directly. `ControlService` is the control plane's own surface (`StartRun`, gates, deployments, GitHub binding).
- `ControlService`'s GitHub/deployment/policy RPCs carry one rule in their shared comment (agentctl.proto:849): they write into schema `agent`, which belongs to the control plane, and "the messaging core may read that schema and may not write it, so each of these is a thing it needs done rather than a statement it issues."
- `PolicySummary.tools_gate_destructive` (agentctl.proto:69) is the destructive-tool deny-pattern list made visible to the runner. Added because the field was absent before 2026-10-07 and "a deny list the runner cannot see denies nothing" — the policy existed server-side but the sandbox was never told, so the gate it promised never opened.
- Product vocabulary never reaches the wire. `proto/tank/channel/v1/channel.proto:7`: a Channel "is presented as a 'Tread' in the product… The wire name stays Channel." A Radar is `CHANNEL_TYPE_MONITOR = 5`, implemented in `tank.monitor.v1`.
- `tank.books.v1.GetInvoiceRequest.rotate` (books.proto) mints a new share link and kills the old one atomically; the token itself is stored as a hash, so an ordinary read always returns an empty `share_url` — the link is readable only once, at creation or send. Model this pattern (write-once secret + explicit rotate) anywhere else a shareable credential shows up.
- `tank.security.v1` (new) has one rule stated in its header: "Controls are the primitive; frameworks are views over them" — one `Control` registry with an owner/check/evidence query each, and a framework (SOC 2 today) is a `FrameworkClause` mapping onto it, never a second set of facts. `ControlState` has no flattering default: `NOT_YET` for "probably true but unevidenced", `UNKNOWN` (not the last answer) for a check that hasn't run recently, and `NOT_APPLICABLE`/`PARTLY` both require a non-empty `reason`.
- `proto/tank/remediation/v1/remediation.proto` (new) is the seam between the control registry (messaging core — decides what's wrong) and the remediation engine (agent control plane — the only thing that can write code); the registry `SubmitFinding`s across the boundary and cannot run anything itself. Four stated rules: propose-only by default (`AUTO_APPLY` is a short, declared exception list), every fix carries a required regression test, a finding fans out to every repo/workspace the same check applies to, and every remediation names the run that drove it.
- `proto/tank/board/v1/board.proto` and `proto/tank/canvas/v1/canvas.proto` are both new whole domains (Neuralboards, Neuralcanvas) — not incremental additions, read them from scratch rather than diffing against anything. Board's `Frame` can hold a running app, not just a picture of one; Canvas's distinguishing feature is that pages cite the threads/decisions/repos they were written from and can go stale.
- Realtime and events grew in lockstep for both new domains: `realtime.proto`'s `ClientFrame`/`ServerFrame` oneofs gained `canvas_editing`/`board_pointer` (ephemeral, rate-limited like typing, never stored), and `events.proto` gained the stored/broadcast counterparts `CanvasBlockChanged`/`CanvasChanged`/`BoardObjectsChanged`/`BoardChanged` plus the same two ephemeral ones — a new realtime domain needs both files touched, not just one.
- Cross-package imports make FILE-level breaking bite across domains, and the import graph just widened: `events` now imports `board` and `canvas` on top of `admin`, `agent`, `blocks`, `channel`, `files`, `huddle`; `topo` and `search` import `message`; `admin` imports `workspace` and `channel`. A field removed from an imported file fails the breaking check in every file that references it, however unrelated the change looks.
- `optional` is used throughout as deliberate presence, not nullability: unchanged-field semantics in `UpdateChannelRequest`, "this replaces nothing" in `DecideBenchmarkRequest.supersedes_id` (topo.proto), the empty-vs-unconfigured distinction in `TopoPreferences.configured` (workspace.proto). Dropping `optional` to tidy a field silently changes meaning.
- `proto/tank/workspace/v1/workspace.proto` is still the biggest hand-grown domain file and `GetBootstrap` is its point: one call on app open, everything else lazy. It caps members at 200, which is the entire reason `ListMembersRequest.query` exists.
- Adding a domain needs a new `proto/tank/<domain>/v1/<domain>.proto` plus `make gen`: managed mode supplies `go_package` unless you write one explicitly (9 files do — billing, books, canvas, catalog, monitor, platform, remediation, security, topo), and lint's `PACKAGE_VERSION_SUFFIX` exemption is already in `buf.yaml`. The TS barrel at `gen/ts/src/index.ts` is hand-written and will not pick up a new domain automatically — 13 of 27 are currently missing from it.
- Never renumber or reuse a field number, and never remove a field before every client has shipped without it (`CLAUDE.md`). `make breaking` / the PR's breaking check catches the first; nothing but discipline catches the second.
